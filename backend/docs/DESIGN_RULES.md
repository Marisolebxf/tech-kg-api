### 文档角色边界

- `DESIGN_RULES.md` 是项目唯一视觉与交互规范来源。
- `PRODUCT.md` 只描述产品定位、用户和范围；PRD 只描述业务需求与验收目标；`README.md` 只描述项目运行与协作信息。
- 产品文档可以决定页面要有什么，但不能自行定义品牌色、组件尺寸、Shell、间距或状态样式。
- 临时截图说明、视觉 QA 报告和历史审计结论完成合并后应清理，不得作为并行规范长期保留。

发生冲突时按以下顺序处理：

1. 用户在当前任务中最后一次明确确认的要求。
2. 本文件中与目标目录匹配的作用域规则。
3. 本文件中的全局规则。
4. 当前实现，只用于核对落地状态，不能反向覆盖已确认规范。
5. Figma、历史截图和旧示例。

同一作用域不得并存两套尺寸、字段或交互规则。确认新规则后直接替换旧规则，不追加“普通规则 + 页面例外”。

## 产品语境

本规范服务于深圳国际科技信息中心 / 国科信体系的后台、数据平台和业务工作台。界面应稳定、清晰、可信，优先支持数据扫描、筛选、录入、判断和连续处理，不采用营销页式的大字、插画或装饰堆叠。

设计体系以 Arco Design 的组件语义为基础，并使用国科信品牌色、密度、图标和页面 Shell 进行视觉覆盖。Arco 提供行为与无障碍基础，不直接决定最终视觉。

## 内容来源合同

**来源管内容，规范管样式。** 高保真表示视觉精度更高，不表示可以重组字段、补流程或扩写业务内容。

内容优先级：

1. 用户明确给出的原型、截图、Figma 节点或 PRD。
2. 用户在当前任务补充并确认的字段与文案。
3. 当前路由、数据结构和实现，仅用于补充已经可验证的事实。
4. 本规范只提供视觉、布局、组件和交互规则，不提供业务内容。

### 两步生成

从视觉来源生成新页面时采用两步制：

1. 先提取来源内容清单：页面类型、导航与页面树、面包屑、筛选、按钮、Tab、字段、表格列与可见行、模块、弹窗/抽屉、图表、AI 消息、文章内容和所有可见文案。无法识别的内容标记“待确认”，不得补写。
2. 清单确认后再生成页面。名称、数量、顺序和层级必须与清单一致；规范只负责把已确认内容映射为一致的视觉与行为。

只有原型已经存在表格、列表或图表区域时，才可用中性示意数据补足视觉密度。示意数据不能新增列、字段、操作、模块或业务结论，也不能使用真实个人隐私和机构敏感数据。

### 页面类型判定

| 页面类型 | 可见依据 | 默认骨架 |
| --- | --- | --- |
| 管理列表 | 筛选、工具栏、表格/列表、分页 | 筛选 → 操作 → 表格/列表 → 分页 |
| 表单/编辑 | 输入、选择、上传、字段分组、提交操作 | 分组表单 → 固定提交区 |
| 详情/阅读 | 只读字段、长文本、分区、关联信息 | 对象摘要 → 内容分区 → 关联内容 |
| 仪表盘 | KPI、图表、图例、坐标轴、明细 | 全局筛选 → KPI/图表 → 明细 |
| 对话工作区 | 消息流、角色、输入区、引用或工具 | 会话区 → 消息流 → 固定输入区 |
| 流程/配置 | 步骤、节点、权限、规则、参数 | 导航/步骤 → 主任务区 → 固定动作区 |
| Modal / Drawer | 居中遮罩或侧边面板 | 保持来源中的承载方式，不互相替换 |
| 混合页面 | 两种以上主结构同时可见 | 以主任务为骨架，其他结构作为分区或子任务 |

页面类型只决定骨架，不改变内容清单。无法可靠判断时先标记“页面类型待确认”。

## 设计原则

- 稳定可信：深色文字、白色表面和克制品牌色优先于大面积高饱和色。
- 信息优先：表格、筛选、表单、状态和任务动作比装饰更醒目。
- 一致复用：优先使用既有 Token、组件语义和页面模式。
- 密度适中：后台保持紧凑，但用 16px 和 24px 节奏清晰分组。
- 状态明确：完整产品覆盖默认、Hover、Focus、Active、Disabled、Loading、Empty 和 Error。
- 边界清楚：一个页面只有一个主任务、一个主骨架和一个明确主滚动区。

## 视觉语言与 Token

### 颜色

| 用途 | Token | 值 |
| --- | --- | --- |
| 品牌主色 | `--gkx-brand` | `#165DFF` |
| 品牌 Hover / Active | `--gkx-brand-hover` / `--gkx-brand-active` | `#4080FF` / `#0E42D2` |
| 品牌浅底 | `--gkx-brand-light` | `#E8F3FF` |
| 页面背景 | `--gkx-bg-page` | `#D8E7FC` |
| 主表面 / 模块底 | `--gkx-bg-surface` / `--gkx-bg-module` | `#FFFFFF` / `#F7F8FA` |
| 分段与弱背景 | `--gkx-bg-subtle` | `#F2F3F5` |
| 主 / 次 / 三级 / 禁用文字 | 文字 Token | `#1D2129` / `#4E5969` / `#86909C` / `#C9CDD4` |
| 边框 | `--gkx-border` | `#E5E6EB` |
| 成功 / 警告 / 危险 | 语义 Token | `#00B42A` / `#FF7D00` / `#F53F3F` |
| 深品牌背景 | `--gkx-cover-blue` | `#0A3888`，只用于封面、登录或明确深色场景 |

品牌蓝用于主操作、链接、焦点、选中状态和信息状态。中性灰承担多数边框、次要文字、占位、禁用和分隔。普通页面不使用紫蓝渐变或随机图表默认色。

图表系列按顺序使用：`#4180FD`、`#58A8F9`、`#FD7E03`、`#4DD164`、`#A872E2`、`#F6BA21`、`#9ED91F`、`#F779B6`、`#16C7C7`、`#E665DE`。同一指标在相关图表中保持同色；超过 10 个系列时优先分组、筛选或改用排序视图，不循环复用颜色。

### 字体

- 字体栈：`PingFang SC`, `PingFang HK`, `Microsoft YaHei`, `Helvetica Neue`, `Arial`, sans-serif。
- 页面标题：20/28px，600；分区标题：16/24px，600。
- 正文和表格：14/22px，正文 400、表头 500。
- 辅助文字：12/20px；字距统一为 0。
- 普通后台不使用视口缩放字体；32px 品牌标题仅用于封面、登录或品牌页。

### 间距、圆角与阴影

- 间距阶梯只使用 4 / 8 / 16 / 24px；组件内部经来源测量的固定值除外。
- 控件圆角 4px；普通卡片 6px；玻璃面板和 Modal 8px。
- 普通卡片与页面分区不使用阴影。
- Modal、Dropdown、Popover、Tooltip 和全局轻提示可以使用克制的高层阴影。
- 不用负 Margin、隐藏空图层或拉伸背景矩形制造间距。

### 文本行为

- 菜单、面包屑、Tab、标签、按钮、状态、表头、普通单元格和操作链接默认单行省略。
- 文章、摘要、说明、评论、AI 消息和长文本详情自然换行。
- 先分配正确宽度，再使用省略；不得通过把 UI 标签挤成多行解决空间问题。
- 省略的关键信息通过 Tooltip、详情区、Drawer 或展开行提供完整内容。

## 通用组件合同

### 按钮与表单

- 标准 Button、Input、Select、DatePicker 和搜索控件高 32px、圆角 4px、文字 14/22px。
- 标准按钮水平内距 16px；图标与文字间距 8px。28px 紧凑按钮只用于密集行内工具。
- 主按钮使用品牌蓝；次按钮使用白色或 `#F2F3F5`；危险色只用于破坏性动作。
- 普通按钮组间距 16px。表格文字操作、分段控件和纯图标工具组使用各自紧凑间距。
- 输入边框 `#E5E6EB`、左右内距 12px；Focus 使用品牌蓝边框和克制的 2px 浅蓝焦点环。
- Select 触发器复用 Input Shell；菜单距触发器 4px，白底、1px 中性边框、4px 内距与圆角；选项行高 32px，选中项使用浅蓝底和品牌蓝字。多选标记复用 14px Checkbox。
- 表单 Label 为 14/22px；Label 与控件 8px，字段组之间 16px。
- Checkbox 为 14px 方形、Radio 为 16px 圆形；必须重置浏览器默认外观并提供 Hover、Focus、Checked、Disabled。
- 必填星号放在 Label 前，并与真实校验联动；不得所有字段一律必填。
- 错误显示危险边框和 12/20px 可执行说明；只读值不得伪装成可编辑输入框。

### Tab 与导航控件

- 一级内容 Tab：高 36px、左右内距 16px、项间距 0；选中项蓝字 500，底部 2px 通项宽下划线。
- 二级内容 Tab：`#F2F3F5` 外层、4px 内距和圆角；单项高 32px、左右内距 16px；选中项白底蓝字，无下划线。
- 一级、二级 Tab 和侧栏导航不得混用视觉层级。
- Tab 名称、数量、顺序和选中项始终来自当前来源。

### 表格

- 表头和数据行默认高 40px；单元格左右内距 16px；表头使用 `#F7F8FA` 与 500 字重。
- 内容列按语义分配宽度，名称、标题、完整标识和路径更宽，状态、枚举和日期更窄；禁止机械等分。
- 普通文本不超过 16 个字时完整显示，超过 16 个字时单行省略，并在 Hover 或键盘 Focus 时显示完整 Tooltip。
- 来源要求完整展示的关键标识可按字段语义突破 16 字阈值；不得为了统一阈值截断关键标识。
- 选择列只在存在真实批量操作时出现，宽 52px；操作列放在最右侧并使用精简文字链接。
- 操作集合、顺序和文案来自当前来源；不得默认补“详情、编辑、删除”。
- 宽度不足时让表格容器横向滚动，只有实际溢出时固定选择列或操作列。
- 分页根据真实数据量出现，页项 32px，当前页使用蓝字浅蓝底。
- 层级、聚合、矩阵、行内编辑、虚拟滚动等变体只在数据结构确实需要时使用；默认从标准数据表开始。

### 状态、Tag 与反馈

- 业务状态统一使用“6px 语义色圆点 + 14/22px 状态文字”，圆点与文字间距 6px。
- 状态不得使用有底色、内距、边框或圆角的胶囊；必须同时显示文字，不能只靠颜色。
- 分类、类型和关键词只有在来源明确使用标签时才采用 Tag 外观。
- 全局轻提示位于页面顶部居中，白底、语义色实心图标、可关闭；信息/成功 3 秒，警告/错误 4.5 秒，最多 3 条。
- 表单内风险与过程反馈使用 Alert；长流程或批量结果必须保留可见结果区，不能只显示 Toast。

### Modal、Drawer 与浮层

| 场景 | 宽度 |
| --- | --- |
| 短确认 | 560px |
| 普通新增、编辑、生成 | 640px |
| 复杂配置 | 960px |
| 表格、权限、多列内容 | 1280px |

- 所有 Modal 使用同一 Shell：Header 56px、Body 四周 24px、Footer 64px、左右内距 24px。
- Footer 按钮高 32px、右对齐、间距统一 16px；取消在左，确认在右。危险确认不建立尺寸或间距例外。
- Header 和 Footer 固定，只有 Body 可纵向滚动；Modal 整体和 Body 都不得横向滚动。
- Modal 保持至少 24px 视口安全边距，即 `max-width/height: calc(100vw/100vh - 48px)`。
- 不可逆操作使用明确标题、主确认句和不可撤销说明；危险确认不使用 Alert 色块。
- 超过 15 个字段，或包含复杂表格、树、多步骤、复杂权限、长阅读和高频编辑时，改用 Drawer、全屏工作区或独立页面。

### 图标

- 默认使用 Arco IconBox 线性图标；描边 1.2px。
- 输入、按钮和表格图标 16px；导航和分区图标 20px。
- 默认 `#4E5969`，弱化 `#86909C`，选中 `#165DFF`，危险 `#F53F3F`。
- 不混用 Emoji、厚重填充图标或无来源的装饰图标；图标不能替代必要文字。

## 状态与交互

- 所有可操作元素必须具备 Hover、Focus-visible、Active 和 Disabled 状态。
- Loading：表格和卡片优先 Skeleton，短时行内等待可使用 Spinner。
- Empty：说明缺少什么，并在适用时提供一个恢复动作；无结果保留当前筛选上下文。
- Error：说明失败原因与下一步；局部错误只替换局部区域。
- 不可逆动作必须二次确认；禁用操作不可触发，并通过 Tooltip 或辅助文字解释原因。
- 动效保持克制，并遵守 `prefers-reduced-motion`。

## 响应式

- 后台以桌面为主，在不改变信息优先级的前提下适配窄屏。
- 1024px 以下侧栏转换为图标栏或 Drawer；768px 以下筛选纵向堆叠，主操作保持可见。
- 宽表格只在表格容器内滚动；整个 Shell 不得产生横向滚动。
- 两栏和三栏工作区先折叠辅助栏，再保护主任务区，禁止挤压标签直到换行。
- 移动端和触屏目标最小 40px；固定高度控件不得裁切中文。

## 无障碍

- 正文与控件满足 WCAG AA 对比度；状态、校验和图表含义不得只靠颜色。
- 表单具有程序化 Label、Required、错误关联和纠正说明。
- 键盘顺序与视觉顺序一致；菜单、Tab、表格操作和展开控件均可达。
- Modal / Drawer 打开后移动并限制焦点，安全时支持 Escape，关闭后返回触发器。
- 表格使用语义化 `table`、`thead`、`tbody`、`th`；排序和选择状态具有可访问名称。
- 纯图标按钮具有可访问名称和可见 Tooltip；装饰图标对辅助技术隐藏。
- 动态反馈使用合适的 Live Region，避免重复播报。

## 目录作用域规则

### `src/**` 生产后台

#### 实现边界

- 入口与路由：`src/main.tsx`、`src/portalRoutes.ts`。
- 通用后台：`src/App.tsx`、`src/styles.css`。
- 各业务页面与同名样式文件负责各自内容；静态资源位于 `public/assets/**`。
- 实现文件只代表当前落地状态，不是导航和页面树的长期定义。信息架构仍从当前路由、原型、PRD 或用户确认内容读取。

#### 生产 Shell

- 桌面侧栏展开 200px、折叠 84px；顶栏高 64px。
- 玻璃内容面板从侧栏右侧、顶栏下方开始，距视口右侧和底部 16px；使用 `rgba(255,255,255,0.48)`、1px 白边、8px 圆角和 `blur(8px)`。
- 面板内部四周 16px；面包屑与唯一白色工作卡片间距 16px。工作卡片圆角 6px、四周内距 16px。
- 一个页面只允许一个全尺寸工作卡片；宽内容的横向滚动归表格或工作区所有，Shell 不使用大 `min-width`。
- 侧栏、顶栏和玻璃面板保持稳定；表格、阅读区、画布或 Modal Body 各自管理滚动。
- 系统名、产品名、用户信息、顶栏工具、导航分组、菜单名、数量、顺序、层级、Active 项和页面树全部来自当前来源。
- 顶栏只固定右对齐、控件尺寸和间距，不默认生成“帮助”“应用”等工具，也不固定 Avatar 文件和用户名称。

#### 侧栏

- 展开菜单列从 `left: 16px; top: 72px` 开始，宽 168px；同级项垂直间距 4px。
- 菜单项高 40px，图标安全框 20px，图标与文字间距 8px，左右内距 16px；图标使用 1.2px 线性描边。
- Active 项使用品牌蓝文字与图标、500 字重、1px 白边、4px 圆角和克制白蓝玻璃高亮。
- 选中二级菜单时，二级项使用通栏 Active 背景；父级只做文字、图标和箭头的上下文高亮。
- 只有真实存在子级的菜单显示 16px 箭头；无子级菜单不得出现组件默认箭头。
- 折叠后菜单项宽 52px，图标水平居中，文字和箭头隐藏。含子级的一级项在 Hover 或键盘 Focus 时显示可访问的右侧子菜单浮层。
- 展开/折叠图标使用 `public/assets/sidebar-expanded.svg` 和 `public/assets/sidebar-collapsed.svg`，定位在内容边缘 `x=200/84, y=28`。
- 菜单名称、数量、层级和 Active 项始终是动态字段。来源只显示局部菜单时，只还原可见项，未知项标记待确认。

#### 顶栏与面包屑

- 顶栏操作区距右侧 16px、顶部 12px；外部工具组间距 16px，紧密工具内部间距 8px。
- 普通工具文字 14/20px、图标 16px；用户入口总高 40px，内部 Avatar 默认 32px。以上只固定几何，不固定内容。
- 面包屑位于玻璃面板顶部，高 20px，文字 12/20px；与工作卡片间距精确为 16px。
- 当前页使用 `#1D2129`、不可点击并设置 `aria-current="page"`；历史层级与分隔符使用 `#86909C`。
- 只有存在真实路由的历史层级才可点击。是否存在首页、名称、数量和顺序由当前信息架构决定。
- 真实首页存在时可使用 `public/assets/breadcrumb-home.svg`，尺寸 20px。普通页面不重复显示页面大标题和副标题，除非来源明确包含。

#### 管理列表

- 顺序：面包屑 → 工作卡片内 Tab（如有）→ 筛选 → 操作 → 表格/列表 → 分页。
- 1440px 基准下每行最多 3 个筛选条件；同一行条件等宽，Label 自适应并右对齐，控件 Fill。
- 条件间、筛选行间、筛选到操作、操作到表格均使用 16px。
- 简单 Input 和 Select 即时筛选，不自动添加“查询”“重置”。只有复杂多条件需要统一提交时才出现这组动作。
- 输入 Placeholder 默认“请输入”，选择器使用“请选择”或真实默认项；“全部”只在业务确实需要全量选项时出现。
- 搜索图标位于右侧，与 Select 箭头使用相同右侧内距。
- 筛选、操作和表格直接位于工作卡片中，不添加包裹卡片或灰底。

#### 表单、详情与阅读

- 普通页面表单按语义分组，优先单列或两列；长文本、上传和复杂选择独占整行。
- 页面表单可以使用左右 Label/Control；Modal 内表单统一为 Label 在上、控件在下。
- 多模块配置先使用 `#F7F8FA` 模块区和 16px 模块间距。简单模块直接放置，复杂模块才使用小型白色内卡。
- 短详情使用 640px Modal；长阅读、多分区、关联列表或多个下游动作使用独立详情页。
- 阅读正文宽度保持 720–880px；只有来源存在时才加入目录、附件、批注和相关内容。
- 三栏阅读工作区建议为左 220px、中心 `minmax(520px, 1fr)`、右 272px，间距 16px；空间不足先折叠右栏，再折叠左栏。
- 中心正文可以换行；目录、资源标题、工具栏和页码保持单行省略。

#### 工作台、画布与仪表盘

- 主从工作台左侧对象列表 280–360px、右侧 Fill；两侧独立滚动，窄屏切换为列表到详情。
- 图谱、地图和搭建器拥有自己的缩放、平移与滚动边界；图谱必须提供列表或文本替代入口。
- 搭建器可使用左资源 240px、中央 Fill、右属性 320–400px；保存、校验和发布为独立动作。
- 只有来源明确包含 KPI、图表和明细时才使用仪表盘模式。
- KPI 无外框与阴影；相邻指标用居中的 1px × 40px 中性分隔线。同级图表各自使用 1px 边框、4px 圆角和 16px 内距，不增加共同外框。
- 图表 Hover/Focus 突出相关系列并显示白底汇总 Tooltip；排名与明细继续使用标准表格，不包第二层卡片。

#### 导入与批量任务

- 多步骤导入使用独立页、Drawer 或全屏工作区：上传 → 映射（如需要）→ 校验 → 确认 → 结果。
- 极小的单步上传确认可以使用 640px Modal，不新增独立尺寸。
- 批量任务必须展示校验、成功、失败、重试和错误下载等真实状态，不能只以 Toast 结束。
- 表格勾选后显示批量操作条，至少包含真实选择数量与取消选择；分页保留在同一底部区域右侧。

#### 生产落地与验收

- 优先复用现有 React 组件。使用 Arco 时保留其行为与语义，再应用本规范视觉覆盖。
- 侧栏不得保留 Arco Menu 默认蓝底、左侧 Active 条、默认缩进、默认箭头或内置折叠按钮。
- 表格不得渲染为行卡片、斑马块、自动换行高行或图标操作列。
- Input、Search、Select 和 DatePicker 的文字与内部图标必须在 32px 控件中垂直居中。
- 内容 Tab 位于工作卡片 16px 安全区内，不得用负 Margin 贴住卡片边缘。
- Modal 统一使用全局 Shell；危险确认只改变文案与按钮语义色，不改变间距。
- 交付前验证动态信息、Shell 几何、局部滚动、响应式、构建、资源、控制台和溢出状态。
- 不得把 `design-preview/**` 的 248px 文档侧栏、目录分组或示例文案带入生产页面。

## 生成与维护

### 工具无关原则

- Figma 使用 Auto Layout、语义图层名、Fill/Hug 和可用组件实例。
- HTML/CSS 使用语义结构、Grid/Flex、CSS 变量和明确滚动容器。
- React 优先复用现有组件；使用 Arco 时覆盖为本项目视觉，不保留默认皮肤。
- 静态预览可使用本地语义组件，但必须匹配相同尺寸、状态、键盘行为和 Token。
- 业务容器使用语义命名，禁止大量 `Frame 1`、`Group`、`Rectangle`、`div1`。

### 组装顺序

1. 读取本文件的全局规则和目标目录对应的作用域章节。
2. 确认页面类型与来源内容清单，特别是动态导航、页面树和字段。
3. 复用既有 Shell、Token、组件与页面模式。
4. 按来源顺序放入模块；业务内容使用结构化布局，不使用散装绝对坐标。
5. 补齐状态、响应式和无障碍，再执行目标目录作用域中的验收。

### 文档维护

- 共性规则写在全局章节；只对一个目录生效的规则写在对应作用域章节。
- 修改共享 Token 或组件时，检查所有目录作用域是否存在冲突。
- 修改局部页面时，不把业务特例提升为全局规则。
- Figma 节点与测量依据集中在“来源索引”，正文只保留可执行结论。
- 每次更新后检查标题、表格、代码围栏、链接、重复数值和冲突规则。
