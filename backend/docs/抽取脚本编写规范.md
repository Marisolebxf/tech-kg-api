# 抽取脚本编写规范（@step · 平台喂数）

面向在 **Schema 管理页上传抽取脚本** 的开发/测试人员。回答三个问题：
**拿什么（输入）→ 怎么处理（逻辑）→ 交什么（输出）**。

- 配套模板（复制即用，只改配置区）：`backend/docs/templates/entity_template.py`、
  `backend/docs/templates/relation_template.py`
- SDK API 全量细节（Context / 水位 / 触发端字段）见 `backend/docs/kg_sdk.md`；
  本文只讲「怎么写对一个脚本」。

## 0. 脚本在链路中的位置

```
平台读源表（按绑定的时间列水位分批）
        ↓  payload["rows"] = 本批行
┌─────────────────────────────┐
│  脚本（只做转换，纯函数）     │   rows ──映射──> 逻辑处理 ──> 输出
└─────────────────────────────┘
        ↓  {"entities"|"edges", "failures"}
平台写图（nGQL INSERT，列级 upsert）→ 同名消歧 → 索引重建 → 推水位
```

脚本**不读主链路数据、不写图、不管水位**——这些全部由平台完成。
脚本里唯一的职责是把一批行变成结构化结果。

## 1. 硬性契约（上传即校验，不满足直接被拒）

| 项 | 要求 |
|---|---|
| 文件 | `.py` 后缀、UTF-8（容 BOM）、非空、≤ 10MB |
| 语法 | `ast.parse` 通过 |
| 步声明 | **唯一方式**：`from kg_sdk import step` 后在顶层函数上标 `@step` / `@step("id")`；出现旧 `transform` 入口或顶层 `STEPS` 清单**即拒**（2026-09-18 起下线） |
| 步数 | ≤ 16；步顺序 = 函数源码出现顺序 |
| step id | `[A-Za-z0-9_-]{1,64}` 且不重复（默认取函数名） |
| 安全校验 | 上传时经 LLM 审计，禁区见 §6 |

执行侧保障：脚本存 S3，每次运行前对 **run 级副本做 sha256 校验**（执行中被改的脚本拒绝运行）；脚本在隔离子进程中执行，资源客户端经 `kg_sdk.Context` 注入。

## 2. 输入：payload 结构

**第 1 步**收到：

```python
payload = {
    "rows": [...],  # 本批行，list[dict]
    "source_table": "库名.表名",
    "kind": "entity" | "relation",  # Schema 类型
    "source": {  # 来源绑定信息
        "id": ...,
        "databaseName": ...,
        "tableName": ...,
        "pkColumn": ...,
        "timeColumn": ...,
        "querySql": ...,
    },
}
```

**第 N>1 步**收到 `{"input": 上一步完整输出, "source_table": ..., "kind": ..., "source": ...}`
（**不再带 rows**）；本批已完成各步的输出可从 `ctx.prev_outputs` 读。

**rows 里的值类型**（MySQL 类型经 JSON 序列化后的口径）：

| 源类型 | 脚本收到 |
|---|---|
| INT / BIGINT / VARCHAR / TEXT | int / str |
| DATETIME / TIMESTAMP | 字符串 `"YYYY-MM-DD HH:MM:SS"` |
| DATE | 字符串 `"YYYY-MM-DD"` |
| DECIMAL | 字符串（数值语义，转换用 `float(...)`） |
| JSON 列 | 字符串（需要时自行 `json.loads`） |
| NULL | `None` |

## 3. 字段映射：row → props

映射决定了「源列写到哪个 Schema 属性上」。三条规则：

1. **props 的键必须在 Schema 目录属性内**。目录外的键写图前被平台**静默丢弃**
   （不报错）——属性名拼错、或属性后来在属性管理里被删了，都表现为
   「这一列悄悄没写上」。这是最常见坑，排查先看键名。
2. **平台代填的列不用输出**：
   - `source_table` / `create_time` / `update_time`（Schema 注入的 NOT NULL
     审计列，缺省自动补）；
   - `id`（身份列未输出时自动补 = 实体 vid）；
   - 其它 NOT NULL 列缺省时平台补类型适配的空值（`""` / `0`）。
3. **溯源列可选填**：`vid` / `source_system` / `source_record_id` /
   `ingest_batch` / `confidence` / `match_method` 等目录里的溯源属性，脚本
   想填就填（键在目录内即写入），不填保持 NULL。

**值类型平台按图库列类型双向兜底**（写图前统一适配）：

| 图库列类型 | 脚本可给 | 说明 |
|---|---|---|
| string | str / int / float / bool | 一律转字符串写入 |
| int64 / double | 数字或可解析字符串 | `"0.95"` 也能解析；不可解析回退零值（可空则 NULL） |
| date / datetime | `"YYYY-MM-DD[ HH:MM:SS]"` 字符串 | 平台包 `date("...")` / `datetime("...")` |
| bool | bool 或 `"true"/"1"/"yes"` | 字符串按内容判定 |

兜底是容错不是依赖：**映射时建议显式转换**（见模板 `FIELD_MAP` 的
`(列名, 转换函数)` 写法），把类型问题在脚本里暴露成 failures，而不是被
平台静默回退成零值。

**写法约定**：映射集中在文件顶部的常量区（模板的 `FIELD_MAP`），
改映射不动逻辑——「指定映射关系就能跑」在模板层面即此实现。

## 4. 逻辑处理

### 4.1 行过滤（一表多 Schema）

同一张表喂多个 Schema 时（如 `entities` 表按 `type_code` 分流到
Course / Document / ...），判别列不匹配的行 **`continue` 静默放行**：

```python
if str(row.get("type_code") or "") != "COURSE":
    continue  # 其他类型实体由各自 Schema 的脚本处理
```

注意：这属于「正常分流」，**不要**报 failures，否则每张表会被每个脚本
重复报一遍别的 Schema 的行。

### 4.2 id / vid 合成

- 实体的 `id` 就是图库 vid。**必须稳定**：同一源行每次产出同一个 vid，
  重跑才是幂等覆盖，否则会写出重复点。
- 多来源主键可能撞车时加前缀（`f"person_{scholar_id}"`）；
  **引用该实体的关系脚本端点必须用完全相同的前缀**（第一大悬挂边来源）。
- vid 建议纯字符串化（`str(row["id"])`），避免 int/str 混用。

### 4.3 残缺行分级处理

| 情形 | 处理 | 后果 |
|---|---|---|
| 判别列不匹配（属于别的 Schema） | `continue` 静默放行 | 无 |
| 业务性缺失（关系端点为空等，源数据常态） | `continue` 静默跳过 | 无 |
| 解析异常 / 毒行（缺主键、类型转不过来） | `failures.append({"recordId": ..., "error": ...})` | 进 **T_EXTRACT_FAIL** 人工审核 case，可在人工审核页按执行重跑 |
| 实体归属拿不准（同名/歧义） | `pendingReview` 项（只收实体） | 平台做同名召回评分，强制人工 **T_LINK** 裁决 |

failures 每执行上限 2000 条（`SCHEMA_EXTRACT_FAILURE_CASE_CAP`），超出只计数。
`error` 文案写清原因与异常类型（`f"{type(exc).__name__}: {exc}"`），
审核页直接展示。

### 4.4 多步流水线

需要「规整 → 查找表富集 → 输出」分阶段时拆多个 `@step`：

- 每步一次 Temporal activity，**第 k 步失败只重试第 k 步**；
- 任意一步返回 `entities` / `edges` 即在该步之后写图；
- 步间传递有大小防护：单值 input 512KB / prevOutputs 128KB / 额外键合计
  256KB，超限截断为 `_truncated` 标记——**大对象不要跨步传**，最后一步
  再展开成实体/边。

### 4.5 Context 资源（查找表富集 / LLM）

```python
from kg_sdk import current_context, step


@step
def enrich(payload):
    ctx = current_context()
    if ctx is None or ctx.mysql is None:
        return payload["input"]  # 未配置则原样透传（降级）
    with ctx.mysql.session_scope() as s:  # mysql 未显式选时自动回退来源绑定数据源
        ...
```

- `ctx.mysql / graph / milvus / llm / embedding` 均懒构造，未配置返回
  `None` 不抛异常——**判空降级**是硬要求；
- 水位（`ctx.config.watermark`）只读，脚本返回值里的 `_watermark` /
  `_checkpoint` 会被平台剥离忽略。

## 5. 输出契约

```python
# 实体（kind=entity）
{"entities": [{"id": vid, "props": {属性: 值, ...}}], "failures": [...]}

# 关系（kind=relation）
{"edges": [{"fromId": vid, "toId": vid, "props": {...}}], "failures": [...]}
```

- 实体 `props` 为空的记录会被跳过（至少输出 `name`）；
- 关系可以不输出 `props`（纯连接边），平台自动补 NOT NULL 审计列；
- 写图为 `INSERT VERTEX/EDGE` **列级 upsert**：重跑幂等、未知列自动剔除
  重试（目录与图库漂移的自愈路径）；
- 实体写图前经**同名消歧**：得分 ≥0.85 自动并入既有实体、0.65–0.85 灰区
  转人工 T_LINK、<0.65 视为新实体——不希望平台自动并的走 `pendingReview`；
- 整链（含索引重建）成功后才推该来源表水位，失败批不推、重跑重读同窗口。

## 6. 禁区（LLM 安全校验判不安全，上传被拒）

判定口径：脚本应是「**接收行 → 返回结构化结果**」的纯计算变换。

| 类别 | 禁止内容 |
|---|---|
| 危险 import | `os` / `subprocess` / `socket` / `shutil` / `ctypes` / `pickle` / `marshal` / `multiprocessing` |
| 动态执行 | `eval` / `exec` / `compile` / `__import__` |
| 网络访问 | `socket` / `urllib` / `requests` / `httpx`（外发请求、动态构造 URL） |
| 文件越界 | 工作目录外读写、读密钥文件（`~/.ssh`、`/etc/passwd`、`.env`） |
| 敏感信息 | `os.environ`、密钥、token |
| 进程派生 | `subprocess.Popen` / `os.fork` / `os.exec*` |
| 代码混淆 | base64/hex/marshal 解码后执行、动态拼字符串再执行 |

需要外部资源时一律走 `kg_sdk.Context`（§4.5）。

## 7. 常见错误对照表

| 阶段 | 现象 | 根因 | 处置 |
|---|---|---|---|
| 上传 | 「必须上传 .py 格式」 | 后缀不对 | 改后缀 |
| 上传 | 「Python 脚本语法错误（第 N 行）」 | 语法问题 | 按行号修 |
| 上传 | 「STEPS 清单声明已下线…」 | 旧多步声明 | 改 `@step` 装饰器 |
| 上传 | transform / workflow 旧入口报错 | 旧单步声明 | 函数标 `@step` |
| 上传 | 「校验未通过」（LLM 安全校验） | 命中 §6 禁区 | 移除危险调用，资源走 Context |
| 触发 | 「Schema 未上传脚本」 | 没传脚本 | Schema 页上传（模板起步） |
| 触发 | 「Schema 未绑定来源表」 | 没绑表 | 来源表弹窗绑定 |
| 运行 | 写图 `Unknown column 'X'` | props 键不在 TAG 上（目录删过属性 / 键拼错） | 平台会剔除重试；根治是对齐键名 |
| 运行 | 实体多出重复点 | vid 不稳定（每次产出不同值） | id 合成规则固定（§4.2） |
| 运行 | 边悬挂 / 端点对不上 | 关系端点 vid 与实体 vid 不一致（前缀漏了） | 两边前缀对齐 |
| 运行 | 属性列悄悄没写上 | 键在 Schema 目录外被静默丢弃 | 核对目录属性名（§3 规则 1） |
| 运行 | 同名实体被合并 | 消歧得分 ≥0.85 自动并入 | 业务上不允许并的走 `pendingReview` |
| 运行 | 跨步数据变成 `_truncated` | 步间传递超大小防护 | 大对象不跨步（§4.4） |

## 8. 模板使用

### 8.1 实体模板 `templates/entity_template.py`

改配置区三处：`DISCRIMINATOR`（判别列，单表单实体设 None）、`FIELD_MAP`
（属性 → 源列/转换）、`VID_PREFIX`（vid 前缀）。逻辑与输出区不动。

### 8.2 关系模板 `templates/relation_template.py`

改四处：`DISCRIMINATOR`、`FROM_COLUMN` / `TO_COLUMN`（端点列）、
`ENDPOINT_VID_PREFIX`（**与实体模板的 VID_PREFIX 一致**）、`FIELD_MAP`
（边属性，可留空）。

### 8.3 多步最小示例（规整 → 富集 → 输出）

```python
from kg_sdk import current_context, step


@step
def normalize(payload):
    rows = payload["rows"]
    return {"items": [{"id": r["id"], "name": (r.get("name") or "").strip()} for r in rows]}


@step
def enrich(payload):
    ctx = current_context()
    items = payload["input"]["items"]
    # ...用 ctx.mysql 查查找表补字段（判空降级）
    return {"items": items}


@step
def emit(payload):
    return {
        "entities": [
            {"id": it["id"], "props": {"id": it["id"], "name": it["name"]}}
            for it in payload["input"]["items"]
        ]
    }
```
