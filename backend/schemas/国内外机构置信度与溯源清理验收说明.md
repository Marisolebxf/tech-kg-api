# 国内外机构置信度、溯源、清理与验收说明

本说明仅适用于周威负责的国内外机构 39 张 DWD 表。共享 Tag 中来源不属于机构表白名单的数据不在处理范围内。

## 置信度

实体分数只使用真实源记录证据：DWD 来源 0.40，稳定机构标识 0.20，统一外部标识 0.10，可识别名称 0.20，国家、地区、地址或更新时间等辅助属性 0.10，最终限制在 0 到 1。

关系分数：DWD 来源 0.55，至少一个明确端点 ID 0.25，至少两个端点 ID 再加 0.10，记录至少三个非空字段加 0.05，统一外部标识加 0.05。缺失真实端点、重名或低于实体对齐阈值的关系不写图。

所有机构域实体和关系写入 `confidence double`；机构主节点同时保留兼容字段 `org_id` 和规范字段 `organization_id`。

## 溯源

`Organization` 与 `organization_base` 使用同一个 `org_{organization_id}` VID。`organization_base` 保存：

- `organization_id`
- `confidence`
- `source_system`
- `source_table`
- `source_record_id`
- `source_url`
- `ingest_batch` / `ingest_time`
- `source_update_time`
- 完整源记录 `extra_json`

机构域生成的 Person、News、Event、Product 和关系边也携带所属 `organization_id`。

## 工作流

抽样 dry-run：

```json
{"stage":"all","scope":"all","max_records":100,"dry_run":true,"report":true}
```

全量 dry-run：

```json
{"stage":"all","scope":"all","max_records":null,"dry_run":true,"report":true}
```

全量写入 dev：

```json
{"stage":"all","scope":"all","max_records":null,"dry_run":false,"report":true,"space":"dev"}
```

写入模式先执行幂等 Schema 创建和已有 Tag/Edge 的 `ALTER ADD`，再处理实体、关系和验收快照。报告默认保存到 `backend/var/reports/organization/`。

## 虚拟数据清理

先执行报告模式：

```bash
cd backend
PYTHONPATH=. .venv/bin/python -m script.cleanup_organization_virtual_graph --dry-run
```

清理脚本只接受明确的机构桩 VID 前缀，或来源标记为 `mock/stub/virtual/placeholder/test` 的机构关系。存在其他领域关系的桩节点进入 blocked 清单，不删除。

审核 JSON 清单后才能写入，两个批次参数必须完全相同：

```bash
PYTHONPATH=. .venv/bin/python -m script.cleanup_organization_virtual_graph \
  --write \
  --cleanup-batch ORG_CLEAN_YYYYMMDD \
  --confirm-batch ORG_CLEAN_YYYYMMDD
```

脚本先删除确认属于机构域的关系，再使用不带 `WITH EDGE` 的 `DELETE VERTEX` 删除桩节点；如果仍有共享关系，图数据库会拒绝删除。
