# dev2 全功能线 E2E 测试方案（不含登录认证、不含九大业务）

> 版本：2026-09-02 · 分支 kgetl · 待用户确认后执行
> 范围：平台总览 / 图谱查询 / Schema 管理与属性管理 / 配置管理 / 任务中心 / 批次抽取与重跑 / 人工审核 / 修正中心 / 实体列表，外加三条冒烟。
> 排除：登录与会话、SSO、路由守卫、成员管理、个人中心、账号安全、操作记录（均为认证相关）。

## 0. 环境与通用约定

- **被测栈**：`docker-compose.dev2.yml`（已在运行）— web `http://localhost:8089`，api `http://localhost:8002`，temporal-worker / temporal / temporal-mysql 配套。
- **认证**：容器内 `AUTH_ENABLED=false`，所有页面与 API 免登录直达；admin 路由守卫直通。
- **默认图空间**：`dev2`（当前已索引 1115 实体）；可用空间：`algo_test` / `dev` / `dev2` / `e2e_verify_space` / `entity_binding_demo` 等。
- **测试数据源库**：`temporal-mysql-dev2` 上的 `techkg_e2e` 库（`widgets` 表含正常行 + 毒行，是既有 e2e 数据，凭据取自根目录 `dev2_extract_e2e.py`）。
- **造数/清数命名**：一律 `e2e_` 前缀，测试后统一回收（删 schema / 删配置 / 删任务走 UI 删除，本身即覆盖删除功能）。
- **断言三层**：① 界面可见反馈（文案/角标/表格行）② API 复核（curl 8002 对应端点）③ 图库复核（graph-console 执行 `DESCRIBE TAG` / `MATCH ... RETURN count(v)`）。
- **原生 confirm 弹窗**：配置删除、任务删除用 `window.confirm`，Playwright 以 `page.on('dialog')` 接受。
- **用例落点**：`frontend/e2e/platform/*.spec.ts` + 新增 `frontend/playwright.platform.config.ts`（baseURL `http://localhost:8089`，chromium）。宿主机执行。
- **已知环境噪音**（非回归，不记 bug）：`review-full-integration.spec.ts` 需独占环境，不在本方案执行；embedding key 过期导致索引构建 401 时抽取降级仍算通过。

## B. 图谱查询（/overview 的「query」Tab）

### B1 参数模式查询
- **前置**：先经 nGQL 或实体列表取 dev2 空间一个真实实体名（如某个 Paper 名称）。
- **步骤**：切到 query Tab（参数模式）→ 填实体名称 → 图谱范围选「科研成果图谱」→ 点「查询图谱」。
- **输入**：真实实体名；范围=科研成果图谱。
- **预期输出**：「综合图谱展示」渲染画布并显示「N 个节点 / N 条关系」统计；下方详情面板出现 摘要|实体|关系|溯源 四个 Tab；图谱范围留空/非法时「查询图谱」不可用或有校验提示。
- **最终状态**：节点数 ≥1，详情 Tab 均可切换。

### B2 nGQL 模式执行
- **步骤**：切「nGQL 模式」→ 图空间选 `dev2` → 输入语句 → 点「执行 nGQL」（也验证 Ctrl+Enter）。
- **输入**：`MATCH (v:Paper) RETURN id(v) AS vid, v.Paper.name AS name LIMIT 5`；再执行 `MATCH (v:Paper) WHERE v.Paper.name == "__none__" RETURN v`。
- **预期输出**：第一条出「nGQL 执行结果 · 5 行记录」表格；第二条显示「语句执行成功，无返回记录」空态文案。
- **最终状态**：两种结果态均可见，无报错。

### B3 溯源与构建详情跳转
- **步骤**：B1 结果中打开「溯源」Tab；若实体有构建来源，点「查看构建详情 →」。
- **预期输出**：溯源 Tab 展示来源信息；跳转到对应流程实例详情页。
- **最终状态**：落地页为 ProcessInstanceDetailView 且无 JS 错误（无来源数据时该按钮不出现，记为条件分支）。

  3. 尝试删除公共属性（带 🔒 的行）。

### E8 任务详情页（执行历史 / 步骤 / IO / 溯源 / 重试）
- **步骤**：任一已完成任务 → 「查看详情」；点执行历史不同行切换；开「输入输出」「异常与日志」「数据溯源」Tab。

- **最终状态**：四个 Tab 数据齐且与执行 API 一致。
- **条件分支**：若有失败执行 → 详情出现「重试（reset 回放）」按钮，点击后产生新执行（Temporal reset）。

## H. 修正中心（/admin/corrections + /admin/reviews）

### H1 列表与查询
- **步骤**：分别打开两个路由；用「查询」modal 按关键词/对象/状态过滤。
- **预期输出**：records 模式汇总卡=记录总数/待审核/同步失败/已完成；review 模式=队列记录/待审核/同步中/同步失败；查询结果正确收敛。注意：API 为空时页面回显示例数据（dataMode=example），需区分标注，不算错误。
- **最终状态**：两种模式渲染正常。

### H2 新增修正申请（含 JSON 校验负分支）
- **步骤**：「新增修正申请」→ 填表 → 先填非法 JSON 提交 → 改合法 JSON 提交。
- **输入**：修正对象=专家·机构（或 Paper）；操作类型=修改；对象 ID=dev2 真实实体 vid；标题/原因 e2e；修正前 `{"name":"旧"}`、修正后 `{"name":"e2e新名"}`。
- **预期输出**：非法 JSON 出「必须是合法的 JSON」错误提示且不提交；合法提交成功入列，状态=待审核。
- **最终状态**：`GET /corrections` 出现新记录。

### H3 审核通过 → 自动同步图库 ★
- **步骤**：切 `/admin/reviews` → 该记录「通过」→ 审核弹窗选「批准并同步」+ 备注 →「确认审核」。
- **预期输出**：状态流转 待审核→待同步→同步中→同步完成（dispatcher 轮询周期内，`CORRECTION_SYNC_INTERVAL_SECONDS`）；同步状态徽标相应变色。
- **最终状态**：图库该实体属性已按修正后数据变更（nGQL 复核 `name`）；记录状态=已完成。
- **前置依赖**：修正对象必须是 dev2 空间真实存在的实体 vid，否则同步失败（失败态也是有价值断言，见 H5）。

### H4 驳回（原因必填）
- **步骤**：再造一条待审核 → 「驳回」→ 不填原因确认 → 填原因确认。
- **预期输出**：不填原因被拦（「驳回时必须填写原因」）；填写后成功，状态=已驳回。
- **最终状态**：记录终态已驳回，不触发图库同步。

### H5 同步失败与重试（条件分支）
- **步骤**：若 H3 对象指向不存在实体 → 同步应失败 → 记录出现「重试」按钮 → 修正对象后重试。
- **预期输出**：同步状态=同步失败(红)，重试后转 同步中→完成（或给出明确失败原因）。
- **最终状态**：操作轨迹 timeline 完整可查（详情 modal）。

### H6 修改 / 撤销自己的待审核申请
- **步骤**：records 模式对自己 PENDING_REVIEW 记录「修改」（改标题再保存）→「撤销」。
- **预期输出**：修改后数据更新；撤销后记录移除/终态。
- **最终状态**：列表不再有待审核的 e2e 记录。

## 执行顺序与优先级

1. **第一批（欠账验收）**：C（属性硬删除/角标/回填）→ F（抽取失败重跑 UI）——这两组是 memory 里明确"待浏览器验收"的。
2. **第二批（主链路）**：E（任务中心）→ D（配置管理）→ I（实体列表）。
3. **第三批（周边）**：A（总览）→ B（查询）→ G（人工审核 A 类，取决于造数可行性）→ H（修正中心）→ J/K/L 冒烟。

## 缺陷记录约定

- 用例失败先区分：功能缺陷 / 环境问题（容器未起、依赖服务 401）/ 数据前置不满足（造数失败）。只有第一类进修复清单。
- 修复遵循容器测试流程：改后端必须 rebuild `tech-kg-api-dev2` 镜像 + `uv sync --dev` 后再容器内 pytest；前端改动走 `docker compose -f docker-compose.dev2.yml build web-dev2` 验证 vue-tsc/build。
