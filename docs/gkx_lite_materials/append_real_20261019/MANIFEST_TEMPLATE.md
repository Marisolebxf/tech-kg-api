# MANIFEST_TEMPLATE — 追加批次清单格式说明（公开版）

真实清单 `MANIFEST.md` 存服务器侧受限区（含 R-id→源主键全映射与核验证据，
不进公开仓库）。本文件规定其格式与字段口径，公开侧只汇总计数与校验值。

## 批次块（manifest 头部）

| 字段 | 说明 |
|---|---|
| batch_id | 固定标识（如 `real-append-20261019`） |
| executed_at | 实际执行时间（未执行=计划时间+标注） |
| target | 实例 A `gkx_lite`（127.0.0.1:30306，容器 tech-kg-mysql） |
| source | 实例 A `gkx_dwd_local`（只读取样，选样脚本固定种子可重放） |
| id_rule | `R<表代码>_<源主键>`，表代码 ZP/ZA/ZJ/SCH/ORG |
| batch_marker | **无业务列标记**（data_source 保持源值 `gkx`；批次只在本清单） |
| rowcounts | 执行前后七表行数对照（差值=本批行数，逐一列出） |

## 记录块（每张表一节）

- 全量 R-id → 源库.表.源主键 映射（受限区明文；公开侧只报行数+sha256）
- 字段映射差异登记：`institution ← 源 affiliation（取首个机构串）`、
  `email=NULL`、`avatar=NULL`、自增列不写
- 年份口径差行：单列小节——`原字段 cover_year_start` + `DOI 注册日` +
  `公开正式刊出年` + `差异类型`（网络首发年 vs 刊出年）。
  处置=**保留源值**；实体属性预期（脚本映射 publication_year←cover_year_start，
  gkx_lite 无 publication_year 列）即输出首发年；此类行不计入「五项全对」，
  以「带解释的真实样本」计数。
- 核验状态（三态 + 冲突单列）：每条 DOI/ORCID 的
  `已核验 / 仅格式有效 / 无法核验 / 元数据冲突(带差异说明)`；
  本批换出记录（v1 换出：DOI 注册缺失）保留原样归档，注明换出原因。

## 测试性关联块（与真实关系分列）

- `dwd_org_industry_chain_dtl` 追加行：机构真实、**产业链归属为本验收构造**
  （为覆盖 BELONGS_TO_NODE 场景）。标记 `test_linkage=true`，
  **不计入真实关系承诺**；真实关系计数只含 AUTHORED_BY（作者行）与
  PUBLISHED_IN（论文-期刊）。

## 审核用例块（30 案）

每案字段：`case_id / 类别（合并|新实体|驳回|重跑）/ 涉及 R-id 与 record_id /
证据分层（强证据|辅助证据|待确认）/ 预期动作与图效果 / 操作前后精确计数 /
注入规则（仅重跑案与标注的触发器）/ 截图与只读图查询语句`。

- 合并案：强证据档预设「合并」并核对属性合并+暂存边端点改写；
  辅助/待确认档**不预设结论**，验收操作一致性与图效果本身。
- 驳回案按四分类标注真值依据：`身份候选错误 / Person 范围不适配（附入库规则原文）/
  信息不足待确认 / 损坏记录（附证据）`；类别为 0 时如实留空并说明结构性原因。
- 重跑案：注入规则（对指定 record_id 抛错的脚本变体名+失败行号）、
  状态迁移预期 OPEN→RERUNNING→RESOLVED（或 attempt+1 新案）。

## 校验块

- 受限区各文件 sha256（前 16 位）+ 行数清单
- 追加后核对项：存量 64 行未变（按主键抽全量比对）、
  新增行数=清单行数、脚本全量输出与阶段计数对账
