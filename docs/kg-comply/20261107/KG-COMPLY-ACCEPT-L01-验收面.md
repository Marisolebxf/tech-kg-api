# KG-COMPLY-ACCEPT-L01 · 合规验收面：展示系统用图需求与图相关算法

## 一分钟说明（给非图谱同事）

这份文件只回答一个问题：**本期合规验收，到底拿哪些功能去验收，哪些不算。**

打个比方：验收像「交房检查」，得先有一张**检查清单**，写清楚检查哪几间房、每间看什么。不写清单，验收时容易被临时加项，也容易把「还没盖的房」算成「已交房」。

- 「验收面」= 这张检查清单。
- 「图」= 知识图谱，存「人、机构、论文、专利、技术点」这些点，和「谁和谁合作、谁写了哪篇」这些连线。
- 「空间」= 图数据库里一块独立区域，本期用 `demo_gkx_chain`（上游任务 `KG-COMPLY-STRUCT-L01` 已书面选定）。
- 本任务**只定验收面、并记录现在能不能跑**；不替燕大灌数据，不改上游结构。

**一句话结论**：本期只验收展示系统里 3 个用图的菜单、共 4 类图算法；技术点层现在能跑，七要素层要等燕大灌完那 24 条关系才能跑；政策、服务机构、企业股权/供应链本期不验收。

## 3. 三档验收方式（解决「页面没做出来怎么验」）

因为三块菜单的前端现状不一样，验收不能只用「看页面」一种方式。分三档，各档判据写死：

| 档 | 看什么 | 通过标准 | 适用于 |
|---|---|---|---|
| A 页面档 | 打开页面，肉眼检查 | 图能渲染、交互可用、数字与接口一致 | 科学技术全景 17–33 |
| B 接口档 | 调接口看返回 | 返回 200 且数据结构符合字段契约；有数时非空 | 维护管理 41；知识图谱 400–407、423–437 |
| C 数据档 | 直接在空间里查 | 查得到点/边；数量与上游记录一致 | 全部算法项 |

**本期以 B + C 为主，A 档只在科学技术全景执行。** 理由：知识图谱四页目前是「开发中」占位，维护管理目标页不在当前前端仓，A 档对这两处无法执行。

> 这不是降低标准，而是把「页面没做」和「数据没跑通」两件事分开记。页面缺是前端缺口，需单独立项补；数据跑不通是本任务要暴露的问题。

## 7. 空态与缺数规则

缺数据时，页面或接口该怎么表现，必须先说死，否则验收时会争「这算不算失败」：

| 情况 | 正确表现 | 禁止 |
|---|---|---|
| 该层没有数据（如政策） | 显示「暂无数据」，或返回 501 未实现 | 显示 0、显示假图、静默空白 |
| 有部分数据 | 有多少显示多少，并标明数据范围 | 用 mock 补满、凑够数量 |
| 算法跑不出（如社群演化） | 明示「需多期数据，本期不支持」 | 用单期数据假装演化 |
| 边端点缺失 | 跳过该条，计数里记一条「因端点缺失跳过」 | 自动补点凑边 |
