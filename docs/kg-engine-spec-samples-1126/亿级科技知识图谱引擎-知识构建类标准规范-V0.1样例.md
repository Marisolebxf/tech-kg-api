## 1 适用范围

### 1.1 目的

本规范围绕知识获取、处理与组织的全流程制定统一准则，明确概念定义、关系类型、属性描述等基础要素的规范要求，确保在知识采集、整理环节中各类知识信息的一致性和准确性，为知识图谱的构建奠定规范的知识基础。

### 1.2 适用范围

本规范适用于：

a) 知识构建类服务全部 7 项服务（概念抽取服务、上下位关系服务、属性识别服务、事件建模服务、时空建模服务、文献知识建模服务、专利知识建模服务）的实施、自检与验收；
b) 图谱构建服务、知识融合服务、知识计算服务中涉及知识采集、处理、组织的共性环节；
c) 甲方对上述服务的进度检查、质量抽查与成果验收。

### 1.3 不适用范围

a) 图谱层级架构、存储结构与建图流程（《图谱构建标准规范》规定）；
b) 知识计算方法的适用场景、计算逻辑与评价标准（《知识计算标准规范》规定）；
c) 科技产业链领域的专项构建要求（《科技产业链分析图谱构建标准规范》规定）；
d) 系统部署、运维与安全管理事项。

### 1.4 规范冲突处理

涉及概念、关系、属性等基础要素登记与取值标准化格式的，以本规范为准；涉及图谱结构与构建流程的，以《图谱构建标准规范》为准；仍有交叉争议的，提交双方技术负责人裁定（裁定机制待确认）。

### 1.5 用词约定

- **应**：必须执行；**不应／不得**：禁止执行；
- **宜**：推荐执行；**可**：允许自行选择执行。

## 3 术语和定义

### 3.1 术语和定义

| 序号 | 术语 | 定义 |
|---|---|---|
| 3.1.1 | 知识图谱 | 以图结构组织的知识库：节点表示概念或实体，边表示语义关系，节点与边均可携带属性。 |
| 3.1.2 | 概念 | 对一类对象的抽象概括，构成图谱的概念层；概念须经概念登记表登记后方可使用。 |
| 3.1.3 | 实体（实例） | 现实世界中可唯一标识的具体对象，是某一概念下的具体实例，构成图谱的实例层。 |
| 3.1.4 | 实体类型 | 实体所属的概念，与概念体系中已登记的概念对应。 |
| 3.1.5 | 关系 | 两个知识单元（概念或实体）之间的有向语义关联。 |
| 3.1.6 | 属性 | 描述概念或实体特征的名值对（属性名、属性值）。 |
| 3.1.7 | 模式（Schema） | 概念、关系类型、属性的定义集合，包括登记表及其版本。 |
| 3.1.8 | 数据源 | 为知识构建提供输入的系统、库表、文件或网页等，须在数据源登记表中登记。 |
| 3.1.9 | 源记录 | 从数据源获取的、作为知识构建输入的一条原始数据；每条源记录应有唯一的源记录 ID。 |
| 3.1.10 | 原始值 | 源记录中未经修改的取值。 |
| 3.1.11 | 标准化值 | 按本规范第 7 章规则处理后入库的取值。 |
| 3.1.12 | 实体 ID | 实体在图谱与成果表中的全局唯一标识，生成规则见 7.5。 |
| 3.1.13 | 消歧 | 判断多条源记录或多个名称是否指向同一实体并予以合并的处理。 |
| 3.1.14 | 证据 | 支撑某条知识成立的来源材料及其位置信息（源数据快照行号、原文、官方页面等）。 |
| 3.1.15 | 置信度 | 对知识正确性的量化评估，取值 0～1（计算口径待确认）。 |
| 3.1.16 | 批次 | 一次交付的数据与作业单元，具有唯一批次号（编号规则见第 10 章）。 |
| 3.1.17 | 台账 | 记录作业过程要素（人员、时间、范围、数量、问题与处置）的登记册。 |
| 3.1.18 | 交付清单 | 列明交付物名称、数量、位置与质检结论的清单。 |
| 3.1.19 | 核验状态 | 人工核验结论的枚举标注：通过、修正后通过、存疑待确认、退回。 |

## 4 总体要求

### 4.1 知识构建全流程及基本要求

| 环节 | 主要工作 | 输出物 | 基本要求 |
|---|---|---|---|
| 知识采集 | 选定数据源、登记来源、获取源数据 | 数据源登记表、源数据快照 | 应登记来源与获取时间；不得使用未登记来源 |
| 数据预处理 | 去重、编码统一、字段解析 | 预处理数据 | 应保留源记录 ID 与原始值，不得就地覆盖 |
| 知识抽取 | 概念、实体、关系、属性的识别 | 候选知识项 | 每一知识项应可回溯至源记录 ID |
| 标准化 | 按第 7 章规则处理取值 | 标准化结果 | 原始值与标准化值应同时保留；不得臆造取值 |
| 消歧与对齐 | 判定同一实体、合并与关联 | 实体 ID、合并记录 | 合并判定应留存证据或判定依据 |
| 知识组织 | 按 Schema 归类、入图入档 | 图数据、登记表更新 | 入库要素应与登记表一致 |
| 质量检查 | 按第 8 章检查与整改 | 质检记录、整改记录 | 不合格批次应整改后复检 |
| 交付归档 | 成果与证据归档 | 交付清单、归档目录 | 归档路径应写入交付清单 |

### 4.2 三项基线原则

a) **可追溯原则**：每条入库知识应有源记录 ID；抽样可追溯是验收的必要条件。
b) **原貌保留原则**：标准化不得覆盖原始值，原始值单独存放（见 7.3 与成果表字段）。
c) **登记先行原则**：概念、关系类型、属性先登记后使用；未登记要素不得直接入库，确需新增的按第 10 章变更流程办理。

## 5 概念定义规范

### 5.1 概念登记要素

概念登记表的必填要素及要求如下：

| 要素 | 要求 |
|---|---|
| 概念编号 | 按 5.2 编号；一经登记不得变更、不得复用 |
| 中文名称 | 唯一；使用中文全称、名词性表述；不应以简称、俗称、外文缩写作正式名（可登记为别名） |
| 英文名称 | 命名风格全库统一（建议大驼峰，待确认） |
| 定义 | "属＋种差"式表述，建议不超过 80 字；不得循环定义、不得以举例代替定义 |
| 上位概念 | 指向已登记概念；每个概念原则上只有一个直接上位概念，跨树复用通过引用实现，不重复登记 |
| 粒度说明 | 说明该概念的覆盖边界：包含什么、不包含什么 |
| 相近概念辨析 | 列出易混概念及区分要点 |
| 典型示例 | 1～3 个实例层示例 |
| 来源依据 | 定义出处（标准文献、权威词典、项目约定等） |
| 状态 | 草稿、生效、废止；仅"生效"概念可用于知识构建 |
| 登记人／登记日期／变更历史 | 留痕 |

### 5.2 概念编号规则

概念编号 = `C-<域码>-<三位序号>`。域码初始集合如下，扩展须经登记：

| 域码 | 领域 | 域码 | 领域 |
|---|---|---|---|
| PER | 人物（含学者） | NWS | 资讯 |
| ORG | 机构 | TRM | 术语 |
| PAP | 论文文献 | JRN | 期刊 |
| PAT | 专利 | PRD | 产品 |
| PRJ | 项目 | IND | 产业链环节 |
| EVT | 事件 | — | — |

### 5.3 概念命名与判定细则

a) 一义一名：同一概念只登记一个正式名称，其他称法登记为别名；一名一义：正式名称不得对应多个概念，多义的应拆分登记。
b) 概念抽取环节的判定四步：候选术语 → 查重（对照已登记概念及别名）→ 归类（新概念、已有概念的实例、或非目标域弃用）→ 登记或复用；判定过程在台账留痕。
c) 废止概念不得再用于新数据；已入库数据的迁移按变更流程办理。

## 6 关系类型规范

### 6.1 关系登记要素

| 要素 | 要求 |
|---|---|
| 关系编号 | `R-<域码>-<三位序号>`；唯一、不得变更或复用 |
| 中文名称 | 语义准确的名词性表述 |
| 关系代码 | 英文大写下划线风格（如 AUTHORED_BY）；唯一；命名应可读出方向（"论文 由 学者撰写"） |
| 定义 | 关系语义与判定条件 |
| 头实体类型／尾实体类型 | 指向已登记概念；跨类型建边须经变更审批 |
| 方向 | 登记后固定；实施时不得反向建边；需要反向查询时使用查询语句实现，不新建反向关系（确需登记逆关系的，在登记表中注明） |
| 多重性 | 1:1、1:N、N:M |
| 证据要求 | 源表直接（关系即源表行）、强证据（须逐条留证）、推断（须标注依据与置信度，口径待确认） |
| 示例 | 至少 1 条 |
| 状态／登记人／日期 | 同 5.1 |

### 6.2 建边操作四步（判型 → 判向 → 判重 → 留证）

a) 判型：只使用已登记关系类型，不新增未登记关系；
b) 判向：严格按登记的头尾实体类型；
c) 判重：同一头尾实体、同一关系类型不得重复建边；多条证据合并至证据链，不另建边；
d) 留证：记录源记录 ID 与证据位置。

### 6.3 禁止事项

a) 不得建立无证据关系；推断关系应按登记表标注推断依据与置信度；
b) 不得以"相关""相似"等模糊语义直接建边，必须落到具体登记关系类型；
c) 自环边（同一实体 ID 指向自身）原则上禁止；确有语义需要（如论文自引）的，须在关系登记表注明后方可执行。

| 关系代码 | 中文名称 | 头实体类型 | 尾实体类型 | 多重性 | 证据要求 |

### 7.3 通用标准化规则（S-01～S-10）

| 编号 | 规则 | 内容 |
|---|---|---|
| S-01 | 日期时间 | 目标格式 YYYY-MM-DD（含时间到分为 YYYY-MM-DD HH:MM）。源精度不足时按源精度存储（YYYY-MM 或 YYYY），不足位不得补造；原始值原样保留 |
| S-02 | 数值 | 去千分位、去单位字符及"约、余、＋"等修饰；数值与单位分列；单位统一（示例：金额统一万元，计数统一"次"）；区间值的折算口径待确认 |
| S-03 | 百分比 | 统一为百分数数值（85% → 85）或小数，二选一并全库一致（待确认） |
| S-04 | 文本 | 去首尾空白、压缩连续空白；全角／半角在同一属性内统一 |
| S-05 | 名称 | 机构、期刊等专名使用官方全称，简称登记为别名；人名使用规范汉字，不用同音字替换 |
| S-06 | 枚举 | 仅允许登记闭集取值；无法映射的取值标"存疑待确认"，不得强行归入；新增枚举值走变更流程 |
| S-07 | 多值 | 全库统一分隔符（建议英文分号“;”，或 JSON 数组，待确认）；多值内每一项均须符合对应规则 |
| S-08 | 空值 | 缺失存 NULL；不得以空串、0、"无"、"未知"或默认值填充冒充 |
| S-09 | 语言 | 规范值使用简体中文；外文原文保留在对应原文属性，两者不混存 |
| S-10 | 计量单位 | 使用法定计量单位；单位清单待确认 |

### 7.5 簿记属性总规则（统一约定，各实体属性登记表不重复列出）

| 簿记字段 | 说明 |
|---|---|
| entity_id | 实体全局唯一标识，= 前缀＋业务主键（前缀表以《图谱构建标准规范》为准）；一经生成不得变更 |
| source_batch_id | 来源批次号 |
| source_record_id | 源记录 ID |
| created_at／updated_at | 入库时间／最近更新时间 |
| operator／checker | 操作人／核验人 |

### 7.6 属性与关系的边界

a) 实体间关联应以关系表达，不作为属性存储；
b) 因工程需要在属性中冗余存储关联信息的（连接键），应在属性登记表中标注"连接键"用途，且以对应登记关系为准。

## 8 质量检查规范

### 8.1 质量维度与检查项

| 维度 | 检查项 | 检查方法 | 合格标准（建议值，最终待确认） |
|---|---|---|---|
| 完整性 | 必填属性非空率 | 程序全量 | 100%；确无来源的在台账说明 |
| 准确性 | 属性取值错误率 | 人工抽样 | ≤1% |
| 一致性 | 取值与登记表类型／值域一致率；标准化格式符合率 | 程序全量 | 100% |
| 唯一性 | 实体重复率；重复边率 | 程序全量 | 消歧后为 0；允许并存的须注明 |
| 可追溯性 | 抽查记录可提供证据比例 | 人工抽样 | 100% |
| 时效性 | 数据时间窗符合批次要求 | 程序 | 待确认 |
| 合规性 | 敏感信息与个人信息处理 | 人工 | 按项目安全规定（待确认） |

### 8.2 抽样规则

a) 按"实体类型 × 批次"分层随机抽样；抽样清单或随机种子应留档，保证可复现；
b) 每层抽样比例与下限：建议不低于 5% 且不少于 30 条，不足 30 条的全查（待确认）。

### 8.3 人工核验

a) 双人制：初核人与复核人不得为同一人；
b) 核验状态枚举：通过、修正后通过、存疑待确认、退回；
c) 初复核不一致的，提交仲裁人裁定（仲裁人待确认）。

### 8.4 批次交验与返工

a) 批次交验应附质检记录与台账；一次交验合格率口径见各服务成果报告；
b) 不合格批次限期整改（时限待确认）后复检，复检范围含不合格项及其关联项；
c) 返工不改变源数据与证据，仅更正处理结果，且修正前后取值均留痕。

### 8.5 质检记录表（字段）

批次号、检查项、检查范围、检查方法、样本量、问题数、问题率、结论、检查人、检查日期、整改情况。
