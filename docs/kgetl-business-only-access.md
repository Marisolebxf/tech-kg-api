# 指定账号仅开放九大业务模块

适用 `kgetl` / `bkg_zpt`，不修改 `main` / `bkg_zp`。

## 本次配置

用户已通过成员接口撤销用户 ID `2687` 的本地管理员身份。要进一步限制其只能使用九大业务模块，在该部署的后端环境设置：

```dotenv
PLATFORM_BUSINESS_ONLY_USER_IDS=2687
AUTH_ENABLED=true
```

配置默认空值，其他账号维持原有权限。匹配用户中心验证后的稳定用户 ID，不通过邮箱、浏览器参数或角色名称匹配。不修改用户中心角色或本地授权记录；此限制优先于既有管理员来源。

合并本次代码后发布 `bkg_zpt` 前后端，并重建后端容器以加载新环境变量。仅合并 PR、仅重启旧容器或仅修改前端，均不能完成生效。前端认证配置也必须为启用状态；免登录模式无法区分真实账号。现有 OAuth、Redis 与 Cookie 配置沿用 `docs/kgetl-role-access.md` 的部署要求。

## 生效后的行为

- 该账号侧边栏仅显示九大业务模块，默认落到科技专家/人才直接关系。
- 总览、综合查询、实体列表、图谱可视化和所有管理页面均不能通过地址直达。
- 保留自己的个人中心、账号安全、操作记录、退出登录以及业务查询所需图空间选择。
- 后端对认证账号执行接口白名单，保留九模块及其必要查询依赖；直接请求其他受保护接口返回 403。前端不会引导该账号进入 403 页面。
- 其他普通用户与管理员保持原有菜单和权限。

## 发布后验收

用目标账号重新登录：`GET /bkg_zpt/api/v1/auth/me` 应返回 `data.user.id=2687`、`data.businessOnly=true`、`data.isAdmin=false`。检查九个业务入口及实际查询结果；访问总览/综合查询地址应回到 `/expert-direct`，直接请求对应受保护 API 应被拒绝。再用另一账号确认权限未变。

自动测试使用模拟身份和隔离容器，不能替代上述线上验收。本次提交本身没有发布服务器或更改线上环境变量。

如需取消此限制，从 `PLATFORM_BUSINESS_ONLY_USER_IDS` 移除 `2687` 并重建后端容器；用户恢复其原有有效权限，不会因此重新授予本地管理员。
