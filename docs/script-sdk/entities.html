EntityRecord

@dataclass(frozen=True) class EntityRecord: tag: str # graph Tag，如 "Person" vid: str # 确定性 VID（见 identity 页） properties: dict[str, Any] # 含溯源 + extra_json merge_protect: bool = False # 机构域置 True identity: dict | None = None # merge_node 匹配键，缺省 {"vid": vid}
  • tag：目标 Tag 名。写入前 Tag 必须已存在（用 nGQL CREATE TAG / init_*.py schema 脚本建好）；属性名必须完全匹配 Tag schema —— 传 schema 外的列会收到 400 SemanticError: Unknown column。
  • identity：除了 vid 还想参与 upsert 匹配时传，如学者 Person 用 {"vid": vid, "source_record_id": sid}（旧口径）。
  • merge_protect：机构域实体（Organization/Event/News/Product/机构角色 Person） 置 True，写入前先读已有节点做合并保护（见下）。

write_records 的写入路径

write_records(records: list[EntityRecord], *, dry_run: bool) -> dict[str, int]
# 逐条 merge_node upsert（新架构统一通道）
graph.merge_node([record.tag], identity, props)

# dry_run 不建连接不写图，只统计
{"scanned": 500, "written": 498, "updated": 2, "dry_run": 0}
  • 写图前先按 merge_protect 分 Tag 批量读回已有节点属性（一条 MATCH (v:Tag) WHERE id(v) IN [...] RETURN id(v), properties(v)）。
  • 批量写发生在主流程攒够 batch_size 条时，连接在每批内建、批末关闭。
  • 典型调用方是 run_entity_extractor，手写循环时才直接调 write_records。

机构域 merge 保护

机构域一份数据可能来自多张表（基本信息、上市公司信息、港股信息…），直接 upsert 会用稀疏行 把已有完整属性冲掉。merge_protect=True 的记录走 merge_existing_properties(existing, incoming)：

规则行为
标准属性 只填空，不覆盖：已有非空值保留；仅当已有值为 None/空白时才接受新值
confidence 只升不降：新值 > 已有值才更新
extra_json 多源累积：已有 source_records 按 "table:record_id" 键合并新源行，整包过 bounded_json
无变化 不发起写入（changes 为空直接跳过，避免无效写放大）
更新时 携带全部已有非空属性 + 增量变更一起写，防稀疏行冲掉 canonical 字段 
# 已有：{"name_cn": "华为", "confidence": 0.9}
# 新行：{"name_cn": None, "confidence": 0.7, "extra_json": "{...}"}

merge_existing_properties(existing, incoming)
# → {}                        # name 不回退、confidence 不降、extra_json 内容相同 → 整体跳过
旧 truncated 摘要的演进处理

合并时如果已有 extra_json 是 bounded_json 降级出的审计摘要 （无 truncated 标记的 legacy 载荷除外），摘要会被完整源行取代 —— 摘要只是属性上限不够时的 临时形态，不是终态。

None 属性与值字符串化

写入前所有记录过一道 _drop_null_props：

  • None 值属性直接丢弃（机构域「空白→NULL→省略属性」口径的落图形态； Nebula 不写该列即视为 NULL）。
  • 非字符串值显式 str()。原因：trs-graph REST 对 string 列做严格类型校验， 传 int/float 会 400 Storage Error: data type does not meet the requirements。 旧 nGQL INSERT 用字符串字面量本就隐式转字符串，REST 路径必须显式。
mapper 里不要预判类型

数值属性按源口径给 float/int 即可（to_float_or_zero 等），字符串化由写入层统一做 —— mapper 自己 str() 一遍会跟「机构域 confidence 数值比较」等保护逻辑打架。

mapper 实战示例

签名约定：mapper(table: str, row: Mapping, batch: str) -> list[EntityRecord]。 返回 [] 表示这一行不产出（缺主键、虚拟源行、过滤规则命中）。

from script.entity_extractors_one_entity.common import (
    EntityRecord, extra_json, org_provenance,
    stable_record_id, text_or_none,
)
from script.entity_extractors_one_entity.mappers import organization_props

# 机构域：动态置信度 + 复合稳定键 + merge 保护
def organization_node(table, row, batch):
    org_id = organization_id_from_row(row)
    if org_id is None:
        return []
    vid = organization_vid(org_id)
    props = {
        **organization_props(row),                       # 业务字段（mappers.py）
        **org_provenance(table=table, row=row,           # 动态置信度溯源
                         record_id=stable_record_id(
                             table, row, ("org_id", "year")),
                         ingest_batch=batch),
    }
    return [EntityRecord("Organization", vid, props,
                             merge_protect=True)]
# 论文域：原文口径 + 固定置信度 1.0 + identity 带源主键
def scholar_person(table, row, batch):
    sid = row.get("scholar_id")
    if not sid:
        return []
    vid = f"person_{sid}"
    props = {"name_zh": text_or_empty(row.get("name_zh")),
             "extra_json": extra_json(row),
             **provenance(table=table, record_id=str(sid).strip(),
                          ingest_batch=batch,
                          source_update_time=row.get("update_time"))}
    return [EntityRecord("Person", vid, props,
                             identity={"vid": vid, "source_record_id": str(sid)})]
