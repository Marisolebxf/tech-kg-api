VID、稳定键与幂等

确定性标识是整个抽取体系的根基：同一条源数据，任何时候重跑都得到同一个点/同一个身份。

为什么标识必须确定性

所有写入都走 upsert：merge_node(labels, identity, props)、带 rank 的 INSERT EDGE、merge_edge(src, dst, type, identityProps, props)。upsert 的匹配键来自 VID/rank —— 如果两次运行对同一行源数据算出不同的 ID，就会产生重复点/边，而不是覆盖更新。因此：

❌ vid = f"person_{uuid4()}"          # 每次都新点，重跑即翻倍
❌ vid = f"person_{row_index}"      # 顺序变了 ID 就漂
✅ vid = f"person_{scholar_id}"     # 源主键 → 稳定
✅ vid = person_vid(kind, org, name, birth, country)   # 复合身份哈希 → 稳定

顶点 VID 公式

工具集内置各实体族的 VID 公式（entity_extractors_one_entity/common.py）：

函数公式用于
organization_vid(org_id)org_{org_id}Organization 点，边端点
project_vid(project_id)project_{project_id}Project
news_vid(record_id)news_{record_id}News
event_vid(table, record_id)event_{table}_{record_id}Event（表名入键，不同表的同名事件不撞）
datasource_vid(table)ds_{table}DataSource 点
person_vid(kind, *identity)person_{md5(kind|org|name|birth|country)}机构角色 Person（无源主键，复合身份哈希）
product_vid(name)product_{md5(NFKC+casefold(name))}（完整 32 位）Product（无主键，按名哈希）
md5_vid(prefix, value, short=True){prefix}_{md5(normalize_key(value))[:16]}自定义族：归一化 + md5 短哈希

有源主键的实体直接拼前缀；无主键的（机构角色自然人、产品）用复合身份哈希。 person_vid 的各分量先做 NFKC + casefold 再 | 连接：

from script.entity_extractors_one_entity.common import person_vid

vid = person_vid("shareholder", org_id, name, birth_date, country)
# 'person_a3f1…'  md5("shareholder|org123|张三|1970-01-01|CN") 截断包装

论文/学者域是直接拼接（person_{scholar_id}、paper_{paper_id}）——两个域的 Person 点 靠 --source 通道区分，互不冲突。

bounded_vid：64 字节安全阀

NebulaGraph 固定长度字符串类型的 VID 上限 64 字节。所有 VID 公式最后都过一道 bounded_vid：超限则按字节截断并附加全文 md5 后缀，保证截断后仍然唯一且确定：

bounded_vid(value: str, max_bytes: int = 64) -> str
bounded_vid("org_常规ID")          # ≤64 字节：原样返回
bounded_vid("event_t_超长复合键…")   # 超限：截断 + "_a1b2c3…"（md5 后缀）
自定义 VID 必须包 bounded_vid

如果你的源主键可能超长（复合键、URL、UUID 拼接），自定义公式务必套一层 bounded_vid(...) —— 直接拼接超 64 字节会让 trs-graph 写入报错。

行级稳定键

当一行数据没有可靠主键时，用稳定键作 source_record_id（溯源 + upsert identity）：

stable_record_id(table, row, preferred_fields=()) -> str # 复合键字段全非空 → "a|b|c"；否则整行排序 JSON 的 md5 兜底
source_record_id(row, *fields) -> str # 候选链版：任一字段非空取候选链拼接；全空 → 整行 sha256 前 24 位
# 机构域：年报事件的复合稳定键（org_id + year），缺字段时整行哈希兜底
rec_id = stable_record_id(table, row, ("org_id", "year"))

归一化基础件：md5_hex(value)、normalize_key(value)（NFKC + 空白折叠 + casefold）、 clean_text(value)。凡参与哈希的文本一律先归一，否则全角/半角、大小写差异会造出两个"不同"实体。

边 rank：边的确定性身份

Nebula 边的多重性靠 rank 区分。同一对端点之间同源的边用确定性 rank 保证重跑覆盖：

stable_rank(value: str) -> int # sha256 前 8 字节大端 → 63 位正整数
edge_rank(edge_type, source_vid, target_vid, source_record_id) -> int
rank = edge_rank("INVESTS_IN", src_vid, dst_vid, rec_id)
# 同一源记录重跑 → 同一 (type, src, dst, rank) → 属性覆盖更新

另一个通道是 REST merge 模式，身份走 identityProps（默认 source_record_id）。 两通道的选择见 关系抽取与写入。

端点解析（关系脚本专用）

关系脚本经常拿不到端点的主键，只有名字/标题。relation_extractors_one_relation/resolvers.py 提供与实体侧同一套 VID 公式的端点解析器 —— 这一点是硬约束：边端点算出的 VID 必须与实体脚本写点时的公式一致，否则验存永远 miss。

函数/类作用
keyword_vid(keyword) 三域统一公式：NFKC + 空白折叠 + casefold 后完整 md5（修复了旧脚本论文/项目/专利三处不一致）
paper_source_id(raw) 论文 ID 去掉 __数字 后缀（作者表里 paper_id 带 __序号，主表不带）
paper_stub_vid(prefix, key) 论文域 md5 桩：{prefix}_{md5(key)[:16]}（DOI 桩等允许悬空的端点）
ExactOrganizationResolver 机构名 → org_id：加载 7 张机构表的全部名称列，仅精确匹配且唯一时解析成功；.load(engine) 构造，resolve_exact(name) 查询
resolved_organization_vid(...) 先试精确名解析，失败视值为机构 ID，两者皆无则抛 ValueError
organization_vid_from_row(row, resolver, id_fields=, name_fields=) ID 候选链优先，缺 ID 走精确名解析
person_vid_for_row(row, kind, name_field) 实体侧统一 Person 公式的 row 版：kind | first(org_id, external_id) | name | birth | country
parse_entity_list(value) 容错解析机构列表字段：接受 JSON 数组/对象或单个精确文本名 
from script.relation_extractors_one_relation.resolvers import (
    ExactOrganizationResolver, organization_vid_from_row,
)

resolver = ExactOrganizationResolver.load(engine)   # 一次性加载 7 表名→id 映射
vid = organization_vid_from_row(
    row, resolver,
    id_fields=("org_id", "company_id"),
    name_fields=("name_cn", "name_en"),
)

VID 公式使用规则

  1. 边端点永远 import 实体侧公式（entity_extractors_one_entity.common 或 resolvers），绝不自己另写一份 —— 复制粘贴一份"看起来一样"的公式是端点验存 miss 的头号原因。
  2. 参与哈希的文本先 normalize_key / NFKC + casefold。
  3. 可能超长的 VID 套 bounded_vid。
  4. 没有主键的实体用复合身份哈希（person_vid 模式）或行级稳定键，不要用自增序号。
