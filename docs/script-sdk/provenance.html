溯源与置信度

每个点、每条边自带「从哪来、什么时候进的、可信到什么程度」—— 落图即审计。

溯源属性一览

溯源属性与业务属性平级，直接作为点/边属性落图（新架构不使用 organization_base mixin tag）：

属性含义示例
source_system源系统标识gkx_element
source_table源 MySQL 表dwd_org_base_info
source_record_id源记录主键/稳定键org123 / proj1|paper|paper_9f2a…
source_url源记录原始链接新闻/资讯表的 source_url 候选链
ingest_batch写入批次号ENTITY_20260828T093000Z
ingest_time本批写入时间（UTC）2026-08-28T09:30:01+00:00
source_update_time源行更新时间增量水位的对账依据
confidence置信度 [0, 1]见下文打分
match_method端点匹配方式source_primary_key / name_exact
match_evidence匹配证据（人话）dwd_org_base_info.org123 主键/稳定键直接抽取

三个溯源构造器

provenance() —— 实体通用（论文/学者/项目/专利域）

provenance(*, table, record_id, ingest_batch, source_url=None, source_update_time=None, confidence=1.0, source_system="gkx_element") -> dict
props = {
    "name": ...,
    "extra_json": extra_json(row),
    **provenance(table=table, record_id=sid, ingest_batch=batch,
                 source_update_time=row.get("update_time")),
}
# match_method 固定 source_primary_key、confidence 默认 1.0（主键直抽）

org_provenance() —— 机构域（动态置信度）

org_provenance(*, table, record_id, row, ingest_batch) -> dict

从行内自动取：机构 ID 候选链、entity_confidence 动态打分、URL 四级候选链 （source_url → original_link → original_textlink → web_link）、更新时间候选链 （updated_time → update_time）。

edge_provenance() —— 边（最小集）

edge_provenance(*, source_table, source_record_id, ingest_batch) -> dict

只带四个字段：source_table / source_record_id / ingest_batch / ingest_time。 边还需要 confidence / match_method / match_evidence 时自行并入 （匹配类边从 matcher 的 match_audit_props(method, evidence) 取）。

from script.relation_extractors_one_relation.common import edge_provenance

props = {
    **edge_provenance(source_table=table,
                      source_record_id=f"{project_id}|{output_type}|{target_vid}",
                      ingest_batch=batch),
    "match_method": result.method,
    "match_evidence": result.evidence,
    "confidence": 0.8,
}

置信度打分

entity_confidence(row, source_table=...) —— 机构域实体

四段累加，最后 clamp 到 [0, 1] 保留 4 位小数：

条件分值
基线（dwd_ 前缀 DWD 溯源表 / 其他表）+0.40 / +0.30
有机构 ID（7 字段候选链任一）+0.20
有外部标识（external_id / credit_no）+0.10
有展示身份（name_cn/company_name/news_title 等 12 个候选）+0.20
有地域/时间属性（country/province/updated_time 等）+0.10

典型结果：DWD 表带全量字段 = 1.0；只有名字的资讯行 ≈ 0.7；裸行 0.4。

relation_confidence(row, source_table=...) —— 机构域关系

源可靠性基线（DWD 0.55 / 其他 0.45）+ 显式端点 ID 数（≥1 +0.25，≥2 +0.10）+ 行内非空值数（≥3 +0.05）+ 外部标识（+0.05）。

置信度的方向性约定

  • 机构域 merge 保护下 confidence 只升不降（见 实体写入）。
  • 匹配类边（名称匹配、标题匹配）的 confidence 反映匹配置信度，不是源数据质量； 主键直抽固定 1.0。

ingest_batch 与重跑定位

批次号是「这次运行写了哪些数据」的定位锚：

# 缺省自动生成：ENTITY_/RELATION_ + UTC 时间戳
{"ingest_batch": "ENTITY_20260828T093000Z", "sources": {...}}

# 显式指定（幂等重跑/对账场景：同一逻辑批次共用一个号）
$ uv run python -m script...person_entity --ingest-batch BACKFILL_2026Q3

# 图上按批回查
MATCH (v) WHERE v.entity_extractors.ingest_batch == "BACKFILL_2026Q3" RETURN count(v)
输出即报告

主流程函数返回的 summary（scanned / valid / written / updated / invalid） 本身就是结构化运行报告，CLI 路径直接 print_json、workflow 路径原样返回给 Temporal —— 两条入口的观测口径一致。
