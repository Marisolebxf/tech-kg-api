MySQL 分页与增量

iter_rows() · apply_since() —— 大表安全读取与增量水位注入。

获取引擎

mysql_engine(database: str = "gkx_element") -> sqlalchemy.engine.Engine

内置脚本路径：读 MYSQL_USERNAME / MYSQL_PASSWORD / MYSQL_HOST / MYSQL_PORT 环境变量， pymysql + pool_pre_ping（连接失效自动重连）。

from script.entity_extractors_one_entity.common import mysql_engine

engine = mysql_engine("gkx_element")
try:
    ...
finally:
    engine.dispose()        # 主流程函数已内置 try/finally dispose，手写循环时才需要
用户上传脚本

走 Context 时不要用 mysql_engine()，改用 ctx.mysql.engine（连接参数由 activity 注入）， iter_rows() 本身接受任意 Engine —— iter_rows(ctx.mysql.engine, ...) 直接可用。

iter_rows：分页迭代器

iter_rows(engine, sql, *, batch_size: int, limit: int | None = None, cursor_column: str | None = None, params: dict | None = None) -> Iterable[dict[str, Any]]

分页读取，逐行 yield dict(row)。默认 LIMIT/OFFSET 模式：框架自动在 SQL 后拼 LIMIT :limit OFFSET :offset，每页一个独立连接（避免长事务）。指定 cursor_column 时切换到 keyset 游标模式（见下节）。

  • batch_size：每页行数（CLI 默认 500）。
  • limit：总行数上限（调试 / 试跑用），框架按剩余量裁剪最后一页。
  • params：:name 绑定参数字典，与 SQLAlchemy text() 同约定。
from script.entity_extractors_one_entity.common import iter_rows

SQL = "SELECT * FROM dwd_scholar WHERE status = :status ORDER BY scholar_id"

for row in iter_rows(engine, SQL, batch_size=500,
                      limit=1000, params={"status": 1}):
    process(row)
SQL 要有确定性排序

OFFSET 模式下不带 ORDER BY 的分页不保证无重复/无遗漏（InnoDB 并发写入时页会漂移）。 约定：源 SQL 一律显式 ORDER BY 主键或唯一列。

keyset 游标模式

大表深分页时 OFFSET 会越来越慢。指定 cursor_column 走 keyset：要求 SQL 里带 :cursor 绑定参数并按该列唯一排序，框架以每页末行的列值作为下一页游标：

# 专利域脚本口径：数字字符串主键走 CAST 游标
SQL = """
SELECT p.* FROM dwd_patent p
WHERE CAST(p.id AS UNSIGNED) > :cursor
ORDER BY CAST(p.id AS UNSIGNED)
"""

for row in iter_rows(engine, SQL, batch_size=500,
                      cursor_column="id", limit=None):
    process(row)
模式触发条件SQL 要求适用
LIMIT/OFFSET cursor_column=None（默认） 隐式追加分页子句，无需占位符；建议 ORDER BY 中小表、调试
keyset 游标 传入 cursor_column SQL 含 :cursor 绑定 + 按该列唯一排序 大表、深分页（专利域）

apply_since：增量条件注入

apply_since(sql: str, since: str | None, col: str = "updated_time") -> str

把 col > :since 注入源 SQL，自动处理三种形态：

apply_since("SELECT * FROM t", "2026-08-01")
# SELECT * FROM t WHERE updated_time > :since

apply_since("SELECT * FROM t WHERE status = 1", "2026-08-01")
# ... WHERE status = 1 AND updated_time > :since

apply_since("SELECT * FROM t WHERE status = 1 ORDER BY id", "2026-08-01")
# ... WHERE status = 1 AND updated_time > :since ORDER BY id   ← ORDER BY 保持末位

配合 iter_rows 时记得把绑定值传进 params：

sql = apply_since(SQL, since)
rows = iter_rows(engine, sql, batch_size=500,
                 params={"since": since} if since else None)
主流程已代劳

run_entity_extractor / run_relation_extractor 收到 since 参数后会对每个源自动 apply_since 并注入 :since 绑定 —— 只有自己手写读取循环（收集候选键等场景）才需要直接用这两个函数。

与水位（watermark）配合

推荐的增量抽取闭环：

def workflow(payload: dict) -> dict:
    # ① 优先级：显式 payload > 上次成功运行的水位
    ctx = current_context()
    since = payload.get("since")
    if ctx and ctx.config.watermark:
        since = since or ctx.config.watermark

    # ② 增量跑（框架注入 since 条件与绑定）
    summary = run_entity_extractor(..., since=since, sources=sources)

    # ③ 报告本次最大更新时间，供框架写回水位
    summary["watermark"] = max_source_update_time(summary)
    return summary
  • 水位格式为 ISO 时间戳字符串，由 activity 在 step 成功后统一写回（_write_watermark）。
  • --since 增量模式在旧脚本支持的域（Paper/Journal/Report/News/机构域）均可用； 首次运行传 since=None 即全量。
