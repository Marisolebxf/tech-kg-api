为什么有两套口径

历史脚本对「空值」有两种约定，数据已在图里，改口径会造成脏数据，因此工具集两套都保留、命名区分：

口径空值行为使用域代表函数
机构域口径 空白 → None（写图时省略该属性） Organization / Event / News / Product / 机构角色 Person text_or_none
原文口径 value or ""，保留原文（含内部空白） 学者 / 论文 / 项目 / 专利 text_or_empty
不要混用

同一实体的属性族必须使用同一套口径，否则 merge upsert 时会把另一套口径写的值当成「空」覆盖或跳过。 新脚本按上表对号入座；拿不准时看同域既有脚本的 mapper。

文本语义

机构域（空白 → NULL + 截断）

text_or_none(value, *, max_length: int = 20000) -> str | None
  • strip 后空白返回 None；超 20000 字符截断（告警日志）。
  • bytes 按 utf-8 replace 解码；datetime/date 转 ISO 文本。
clean_text(value) -> str

strip + 折叠所有空白为单空格，空白返回空串。仅用于内部键 / VID 计算，不作展示属性。

原文域（value or ""）

text_or_empty(value) -> str # str(value) if value else ""，保留原文
str_or_empty(value) -> str # 专利域：仅 None 转 ""，0/False 保留
paper_text(value) -> str # 论文域：text_or_empty + 换行替换为空格
date_text(value) -> str # 项目域：datetime→"%Y-%m-%d %H:%M:%S"，date→ISO
datetime_text(value) -> str | None # 专利域：None→None，其余转 "T" 分隔文本
text_or_empty("  张三  ")   # '  张三  '   —— 原样保留
text_or_none("  张三  ")    # '张三'       —— strip
text_or_none("   ")          # None         —— 空白视为缺失
text_or_empty("   ")         # '   '        —— 原样保留

数值语义

to_float_or_none(value) -> float | None # 机构域：非法值 → None
to_int_or_none(value) -> int | None
to_float_or_zero(value) -> float # 项目域：非法值 → 0.0
to_int_or_zero(value) -> int

to_float_or_none 是防御最强的转换，专门对付真实脏数据：

to_float_or_none("1,200.5万")   # None（清洗后无法解析则放弃，不猜）
to_float_or_none("1,200.5")     # 1200.5（去千分位逗号）
to_float_or_none("-")             # None（'-', 'n/a', 'n.a.', 'null', 'none' 视为缺失）
to_float_or_none(float("nan"))    # None（NaN/Inf 一律 None）
to_float_or_none(True)            # None（bool 不当数字）

JSON 处理

解析源字段（专利域：MySQL 里存 JSON 字符串）

parse_json(value) -> Any # 字符串尝试 json.loads，失败原样返回
json_snapshot(value) -> str # 紧凑快照，None → ""
original_text(value) -> str # JSON 数组各元素 text/content 换行连接
normalized_language(value) -> str # JSON 数组 join 成逗号串
original_text('[{"text": "摘要一"}, {"text": "摘要二"}]')
# '摘要一\n摘要二'

normalized_language('["zh", "en"]')     # 'zh,en'

序列化输出（写进图属性的 JSON）

extra_json(row) -> str # 整行源数据快照（json_safe + sort_keys）
compact_json(value) -> str # 紧凑、排序、datetime/Decimal 安全
bounded_json(value, *, max_length=64000) -> str
json_safe(value) -> Any # 递归转 JSON 可序列化结构
normalize_json(value) -> Any # 标量级：datetime→ISO、Decimal→float、NaN→None

bounded_json 是机构域的安全阀：超 64000 字符的 extra_json 不硬截断， 降级为审计摘要（truncated / sha256 / original_length / preview），既不炸 Nebula 属性上限又可追溯原文：

bounded_json(huge_payload)
# '{"original_length":180000,"preview":"...","sha256":"ab12…",
#   "truncated":true}'

字段候选链

同一语义在不同源表里字段名不同（机构 ID 有 7 种写法、姓名有中英文两列），用候选链取第一个非空：

first_value(row, *names) -> Any # 机构域：按 text_or_none 判空
first(row, *fields) -> Any # 新架构：按 clean_text 判空
from script.entity_extractors_one_entity.common import first_value

org_id = first_value(row, "organization_id", "org_id",
                          "company_id", "entity_eid")

机构 ID 的标准候选链已固化为 ORGANIZATION_ID_FIELDS + organization_id_from_row(row)。

新脚本怎么选口径

你的实体/关系属于…文本数值extra_json
机构域（Organization / Event / News / Product / 机构角色 Person） text_or_none to_float_or_none bounded_json（merge 保护下多源累积）
学者 / 论文 / 项目 text_or_empty / paper_text to_float_or_zero extra_json（整行快照）
专利 str_or_empty / original_text / json_snapshot 同上 extra_json
虚拟源行过滤

机构域写点前会过一道 is_virtual_source_row(row)：data_source/source_system 字段标注了 mock/stub/virtual/placeholder/test（含前后缀组合）的合成行不建点。 run_entity_extractor 不自动调它 —— 需要时在 mapper 里显式调用并返回 []。
