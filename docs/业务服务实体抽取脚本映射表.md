# 业务服务实体抽取脚本映射表

本文先只整理“实体”，不整理关系。口径是：九个业务服务运行依赖的图谱实体 Tag，以及这些实体对应的抽取脚本、MySQL 来源和抽取依赖。

需要注意：仓库里并不是严格的一种实体一个脚本。有些实体有独立主脚本，例如 `Person`、`Project`、`Patent`；有些实体由一个领域 ETL 脚本批量产出，例如机构域的 `Organization/Event/News/Product`；还有些实体在多个脚本里都会被创建或补充，例如 `Keyword`、`News`、论文作者 `Person`。

## 实体与抽取脚本总表

| 图实体 Tag | 实体含义 | 是否独立主实体脚本 | 主抽取脚本 | 主要 MySQL 来源 | 抽取方式/依赖 | 支撑的业务服务 |
| --- | --- | --- | --- | --- | --- | --- |
| `Person` | 科技专家、学者、论文作者、机构角色人员 | 是，但存在多来源补充 | `backend/script/load_scholar_entities.py` | `dwd_scholar`，补充 `dwd_scholar_talent_flag`、`dwd_scholar_research_direction` | 学者主表直接抽取，VID 为 `person_{scholar_id}`。机构域高管、法人、股东等角色人员也会由 `organization_entity_etl.py` 生成；论文作者也可能由 `paper_journal_chain_etl.py` 生成。 | 专家直接关系、单节点间接关系、两点合作成果、同事、校友、论文合作、企业关系、TOP-N 事件、产业链全景 |
| `Organization` | 企业、机构、高校、研究院等组织实体 | 是，领域聚合脚本 | `backend/script/organization_entity_etl.py` | 国内外机构要素库多表，例如 `dwd_org_base_info`、`dwd_forg_base_info`、高校/研究院/上市公司等机构表 | 机构域直接抽取；多源属性可能合并到 `extra_json`；VID 通常为 `org_{源机构ID}`。学者任职缺机构 ID 时可能先产生机构名桩节点，后续由机构对齐认领。 | 同事关系、企业关系、TOP-N 事件、产业链全景、单节点间接关系 |
| `Project` | 科研项目、基金项目、国内外项目 | 是 | `backend/script/load_project_graph.py` | `dwd_zh_project`、`dwd_en_project`，补充 output 表 `dwd_zh_project_output`、`dwd_en_project_output` | 项目主表直接抽取为 `Project`，VID 为 `project_{id}`；output 表主要回填成果计数和成果 JSON，不创建 Paper/Patent/Report 桩节点。 | 两点合作成果、专家企业关系、产业链全景、单节点间接关系 |
| `Paper` | 中文/外文论文 | 是，论文领域工作流 | `backend/script/workflow/paper_journal_chain_etl.py` | `dwd_zh_paper`、`dwd_en_paper` | 论文表直接抽取为 `Paper`；论文作者、期刊、关键词、引用关系由同一工作流继续处理。旧入口/相关脚本包括 `load_paper_journal_graph.py`、`paper_journal_relation/load_paper_relation.py`。 | 论文合作、两点合作成果、专家直接关系增强、校友互动摘要、产业链全景 |
| `Journal` | 期刊/会议出版载体 | 不是九业务最小必需，但论文服务增强需要 | `backend/script/workflow/paper_journal_chain_etl.py` | `dwd_zh_journal`、`dwd_en_journal`，以及论文表 `journal_id` | 期刊表直接抽取为 `Journal`，并由论文 `journal_id` 连接。 | 论文合作、产业链全景成果展示增强 |
| `Patent` | 专利 | 是 | `backend/script/load_patent_graph.py` | 全球专利要素库；实体 SQL 在 `backend/dao/sql/patent_entity_extract.sql` 聚合专利主表与明细表 | 专利 SQL 聚合后直接抽取 `Patent`，VID 通常为 `patent_{patent_id}`；关键词和专利族可在同一实体脚本中生成。 | 两点合作成果、专家企业关系、产业链全景、专家直接关系增强、单节点间接关系 |
| `PatentFamily` | 专利族 | 专利实体脚本附带 | `backend/script/load_patent_graph.py` | 全球专利要素库中的 `simple_family_number` 等字段 | 随专利实体抽取生成，依赖专利记录中存在专利族标识。 | 产业链全景和专利分析增强；九业务中不是最小必需实体 |
| `Keyword` | 关键词、主题词、技术方向词 | 多脚本附带创建 | `backend/script/load_project_graph.py`、`backend/script/load_patent_graph.py`、`backend/script/workflow/paper_journal_chain_etl.py` | 项目 `keywords`，专利关键词字段，论文分类/关键词表 | 通常按规范化文本生成 `keyword_{md5}`；项目 ETL 允许创建 Keyword；专利、论文 ETL 也会创建并挂接。 | 论文合作、产业链全景、单节点间接关系增强 |
| `Report` | 报告成果、中文/外文报告 | 论文/报告工作流附带 | `backend/script/workflow/paper_journal_chain_etl.py` | `dwd_zh_report_paper` 及中文/外文报告要素库 | 在论文/报告链路中直接抽取或作为项目 output 匹配目标；项目 ETL 不创建 Report 桩节点，只匹配已存在 Report。 | 两点合作成果增强、产业链全景代表成果 |
| `Event` | 企业事件、风险事件、财务事件、融资/工商/司法/招投标等事件 | 是，机构领域聚合脚本 | `backend/script/organization_entity_etl.py` | 机构事件类多表，例如年报财务、上市财务、工商变更、融资、招聘、经营异常、行政处罚、司法案件、失信被执行人、招投标、破产等 | 机构域事件表直接抽取为 `Event`，VID 通常为 `event_{source_table}_{source_record_id}`；后续关系脚本再连接 `Organization -> Event`。 | TOP-N 事件、专家企业关系风险提示、产业链全景 |
| `News` | 机构资讯、产业链资讯 | 是，但有机构域和产业链两条来源 | `backend/script/organization_entity_etl.py`、`backend/script/industry_chain_etl/load_industry_chain_graph.py`、`backend/script/workflow/paper_journal_chain_etl.py` | `dwd_org_important_news_info`、`dwd_industry_chain_news_info` | 机构资讯由机构实体 ETL 抽取；产业链资讯由产业链 ETL 或论文/期刊/产业链合并工作流抽取。 | TOP-N 事件、产业链全景、专家企业关系背景增强 |
| `Product` | 企业产品、主营产品、经营产品 | 是，机构领域聚合脚本 | `backend/script/organization_entity_etl.py` | `dwd_org_org_product_info`、`dwd_forg_product_info` 等产品/经营信息表 | 机构产品表直接抽取或从经营信息中规范化产品名生成；后续关系脚本连接 `Organization -> Product`。 | 专家企业关系企业背景、产业链全景 |
| `IndustryChain` | 产业链 | 是 | `backend/script/industry_chain_etl/load_industry_chain_graph.py` | `dwd_industry_chain_info` | 产业链表直接抽取，VID 为 `chain_{chain_code}`。合并工作流 `paper_journal_chain_etl.py` 也包含产业链实体加载。 | TOP-N 事件、产业链全景 |
| `IndustryNode` | 产业链节点 | 是 | `backend/script/industry_chain_etl/load_industry_chain_graph.py` | `dwd_industry_chain_info`、`dwd_org_industry_chain_dtl` | 链节点从产业链信息表直接抽取，VID 为 `node_{node_id}`；企业挂链关系依赖已有 `Organization`。 | TOP-N 事件、产业链全景、单节点间接关系 |
| `DataSource` | 数据源/来源元数据 | 非业务实体，基础治理用 | `backend/script/organization_entity_etl.py` 或 schema 初始化脚本 | ETL 过程中的源表配置 | 主要用于溯源治理，不是九个业务服务的核心查询实体。 | 平台治理和溯源，不是九业务最小依赖 |

## 按抽取脚本反查实体

| 抽取脚本 | 主要产出实体 | 备注 |
| --- | --- | --- |
| `backend/script/load_scholar_entities.py` | `Person` | 学者/专家主实体脚本；只落 Person，不写关系。 |
| `backend/script/organization_entity_etl.py` | `Organization`、`Person`、`Event`、`News`、`Product`、`Project`、`IndustryNode`、`DataSource` | 机构域实体聚合脚本；当前实现声明“只写实体，不写边”。其中 `Project/IndustryNode` 多为机构域表中出现的相关实体，九业务主项目和产业链实体仍以项目/产业链脚本为准。 |
| `backend/script/load_project_graph.py` | `Project`、`Keyword` | 主产出是 Project；Keyword 可由项目关键词创建；其他端点实体只匹配不创建。 |
| `backend/script/load_patent_graph.py` | `Patent`、`Keyword`、`PatentFamily` | 专利实体和专利关键词/专利族；专利发明人、申请人、权利人是关系脚本处理。 |
| `backend/script/workflow/paper_journal_chain_etl.py` | `Paper`、`Person`、`Journal`、`Keyword`、`Report`、`IndustryChain`、`IndustryNode`、`News` | 合并工作流，覆盖论文、期刊、报告、产业链和产业资讯；会同时写部分关系。 |
| `backend/script/industry_chain_etl/load_industry_chain_graph.py` | `IndustryChain`、`IndustryNode`、`News` | 产业链专用 ETL；同时写链内结构边和企业挂链边。 |
| `backend/script/load_paper_journal_graph.py` | `Paper`、`Journal` 等论文期刊实体 | 旧/独立入口，具体以当前部署采用的工作流为准。 |

## 建议的实体脚本归属口径

如果后续要在平台上按“一种实体一个抽取脚本”管理，建议按“主责脚本”归口，而不是按所有可能创建它的脚本归口：

| 图实体 Tag | 建议主责脚本 |
| --- | --- |
| `Person` | `load_scholar_entities.py` |
| `Organization` | `organization_entity_etl.py` |
| `Project` | `load_project_graph.py` |
| `Paper` | `paper_journal_chain_etl.py` 或拆出的论文实体脚本 |
| `Journal` | `paper_journal_chain_etl.py` 或拆出的期刊实体脚本 |
| `Patent` | `load_patent_graph.py` |
| `PatentFamily` | `load_patent_graph.py` |
| `Keyword` | 建议独立成公共 `keyword_entity_etl.py`；当前分散在项目、专利、论文脚本中 |
| `Report` | `paper_journal_chain_etl.py` 或拆出的报告实体脚本 |
| `Event` | `organization_entity_etl.py` |
| `News` | 建议按来源拆成机构资讯和产业链资讯；当前由机构 ETL、产业链 ETL、合并工作流都可能创建 |
| `Product` | `organization_entity_etl.py` |
| `IndustryChain` | `industry_chain_etl/load_industry_chain_graph.py` |
| `IndustryNode` | `industry_chain_etl/load_industry_chain_graph.py` |
| `DataSource` | 平台治理/溯源初始化脚本，不建议算作业务实体抽取脚本 |

## 结论

按现有代码，九个业务服务最核心的实体脚本可以先认定为六条主线：

1. 学者实体：`load_scholar_entities.py` -> `Person`
2. 机构实体：`organization_entity_etl.py` -> `Organization/Event/News/Product/机构角色Person`
3. 项目实体：`load_project_graph.py` -> `Project/Keyword`
4. 专利实体：`load_patent_graph.py` -> `Patent/Keyword/PatentFamily`
5. 论文/报告/期刊实体：`paper_journal_chain_etl.py` -> `Paper/Journal/Report/Keyword/论文作者Person`
6. 产业链实体：`industry_chain_etl/load_industry_chain_graph.py` -> `IndustryChain/IndustryNode/News`

如果要严格做到“一种实体一个脚本”，需要把当前聚合脚本拆分：特别是 `organization_entity_etl.py`、`paper_journal_chain_etl.py`，以及分散在多个领域里的 `Keyword/News/Person` 创建逻辑。
