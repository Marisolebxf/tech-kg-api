> 单路由组：`/api/v1/manual-reviews`（**admin 组**，`biz/handler/manual_review.py`，鉴权经网关身份 `get_review_identity`）。
> 前端：`/manual-review`（OperationsCenterView, mode=review）、`/manual-review/task/:instanceId`（ManualReviewWorkspaceView 审核工作台）。
>

## 一、功能描述

生产审核服务：**事后队列**（抽取流水线完整跑完后，异常对象整批进审核队列，审核员裁决；不做运行中暂停等待）。三类产活模板、简化状态机、乐观锁并发控制。

### 1. 队列分类（查询期模板映射，非表列）

| category | 模板 | 含义 |
|---|---|---|
| **A 入库决策** | T_DIRECT、T_LINK | 候选实体/关系入库直判 / 同名冲突实体对齐裁决 |
| **C 抽取失败重跑** | T_EXTRACT_FAIL | 逐行抽取失败记录重跑 |

3 个模板挂在 7 个流水线步骤上（source/normalize/schema/extract/align/validate/persist）：extract→T_EXTRACT_FAIL、align→T_LINK、T_DIRECT 挂抽取 workflow 的自定义 step。旧别名 `T_ENTITY` 归一化为 `T_LINK`。2026-09-17 起为**直审模式**：打开 case 即可直接提交裁决，一切提交即执行（P0 亦然）——审批环节（PENDING_APPROVAL 四方签核）已移除。风险策略 SLA：P0=claim 15min/resolve 30min，P1=1h/4h，P2=4h/1d。

### 2. case 状态机

```
直审主线：OPEN →（submit）→ RESOLVED
可选领取（存量路径）：OPEN → CLAIMED → IN_REVIEW →（submit）→ RESOLVED
失败/旁路：REJECTED、CANCELLED、EXPIRED（终态集：RESOLVED/REJECTED/CANCELLED/EXPIRED）
T_EXTRACT_FAIL 重跑生命周期：RERUNNING、RERUN_FAILED
```

- **直审**：submit 可从 OPEN 直接提交（`SUBMITTABLE_STATUSES = {OPEN, CLAIMED, IN_REVIEW}`），无需先领取；已被他人领取的 case 仍限领取人/review_admin 操作；并发仍是 version 乐观锁——先提交者生效，后提交者报版本冲突。OPEN 直审时 assignee 记为提交人。
- 领取为可选保留：claim 用 CAS（`UPDATE ... WHERE status=OPEN AND version=v`）；心跳超时的 CLAIMED/IN_REVIEW 由 `reclaim_expired` 回收 OPEN。
- **提交即执行**：一切 submit 直接落 RESOLVED（含 P0），不产生 PENDING_APPROVAL；T_LINK entity-confirm 在 submit 内真实写图（`_apply_link_verdict`）。
- **无移交通道**：submit 只记录决议（decision + audit），不再有 APPLYING/VERIFYING 等下发中间态。
- 旁路：T_DIRECT 两步决策不走 submit（OPEN→RESOLVED/REJECTED）；T_EXTRACT_FAIL 点重跑即 RERUNNING。

### 3. 建案入口（唯一的 ingress）

`service/manual_review_production.py: create_direct_case` —— 由 `service/temporal_workflows.py` 在 workflow 内直接调用（不走 HTTP）：

- **T_LINK**：实体对齐同名冲突（`detect_extract_collisions`）；
- **T_EXTRACT_FAIL**：逐行抽取失败（`record_extract_failures`，exception_code=KG_EXTRACT_RECORD_FAILED）；
- **T_DIRECT**：低置信候选隔离（confidence < 0.85 的实体/关系候选）。

幂等键：`dedupe_key = sha([task_id, step_id, object_id, sha(snapshot)])`；confidence < 0.7 → P0，否则 P1；快照带 `_kind/_nodeLabel/_edgeType/_fromId/_toId/_confidence` 元字段。

### 4. 裁决后的落地路径

- **A. T_DIRECT 直写图库（旁路）**：accept → `_coerce_to_schema`（DESCRIBE TAG/EDGE 对齐 schema）→ entity 走 nGQL `INSERT VERTEX` 列级幂等 upsert / relation 走 `create_edge`；仅写 case/audit。可带修正后候选（覆盖快照后写图并记审计）。
- **B. T_LINK**：submit 记录 `entityVerdict`（merge/create）+ `targetEntityId` 并随提交真实执行（`_apply_link_verdict`）：merge 把扣留记录以 `INSERT VERTEX` 列级幂等 upsert 到所选候选 vid、补写待定关系；create 按预留 vid 新建。存量写后 case（无 `_incoming` 快照）仅记录决议。
- **C. T_EXTRACT_FAIL**：不走 submit，直接经 `workflow_operations_service.execute_definition` 触发 `kg.schema.extract` 重跑（与 Schema 管理模块共用闭环）。

### API 一览

`/api/v1/manual-reviews`（admin 组，`biz/handler/manual_review.py`）：

| 端点 | 作用 |
|---|---|
| `GET /production/queue` | 审核队列（queue tab/status/statusGroup/kind/risk/domain/templateId/assigneeId/category/keyword/updatedWithin(1h/24h/7d/30d)/sort=updatedAt+order=asc\|desc/分页；不传 sort 默认 风险级→创建时间升序） |
| `GET /production/{case_id}` | case 详情（含快照/诊断） |
| `POST /production/{case_id}/claim` | 领取（可选保留，CAS，OPEN→CLAIMED；直审模式无需领取） |
| `POST /production/{case_id}/heartbeat` | 心跳续约（超时被 reclaim 回收） |
| `POST /production/{case_id}/release` | 释放回 OPEN |
| `POST /production/{case_id}/transfer` | 转派（review_admin） |
| `PUT /production/{case_id}/draft` | 存草稿（→IN_REVIEW） |
| `POST /production/{case_id}/submit` | 提交决策（直审：OPEN 可直接提交，一切提交即执行；T_LINK 写前扣留 case 随提交真实写图） |
| `POST /production/{case_id}/direct-decide` | T_DIRECT 两步决策（accept 写图 / reject 丢弃，不走 claim/submit） |
| `POST /production/rerun-extract-failures` | T_EXTRACT_FAIL 批量重跑（caseIds ≤2000 → 合并为 RERUN 执行；接受 OPEN/RERUN_FAILED） |
| `POST /production/delete-cases` | T_EXTRACT_FAIL 硬删除（caseIds ≤2000，review_admin；连同草稿/证据/裁决/审计，非 C 类 id 跳过，返回 deleted/skipped） |
| `POST /production/{case_id}/cancel` | 取消（review_admin） |
| `DELETE /production/{case_id}` | 物理删除未处理 case（review_admin；终态保留作历史 → 409） |
| `GET /production/{case_id}/audit-logs` | 审计日志 |
| `POST /production/{case_id}/evidence/upload-url` | S3 预签名上传 URL |
| `POST /production/{case_id}/evidence/complete` | 附件完整性校验落库（sha256/大小/类型白名单） |
| `POST /production/internal/reclaim-expired` | 手动回收过期领取（review_admin） |

## 三、表结构（业务库 5 张表，`db_model/manual_review.py`）

| 表 | 用途 | 关键列 / 说明 |
|---|---|---|
| `manual_review_case` | case 主表 | id（`MR-{YYYYMMDD}-{hex12}`）、`dedupe_key` UNIQUE（sha([task_id,step,object_id,fingerprint])）、source_task_id、pipeline_step_id、template_id、risk_level（P0/P1/P2）、scope（OBJECT）、**status**、assignee/submitted_by、**version**（乐观锁）、heartbeat_at、input/candidate_snapshot、diagnosis、workflow 上下文（type/id/run_id/task_queue）、isolation_scope |
| `manual_review_draft` | 草稿 | case_id(PK)、payload、updated_by |
| `manual_review_decision` | 决策 | case_id(idx)、action_id、result(JSON)、status（APPROVED/REJECTED，legacy 或有 PENDING_APPROVAL 存量）、submitted_by |
| `manual_review_evidence` | 附件 | case_id(idx)、sha256、bucket/object_key（S3 预签名上传）、trust_level、size_bytes |
| `manual_review_audit_log` | 审计 | case_id(idx)、event_type、actor、old/new_status、detail(JSON) |

索引要点：case 表 `ix_review_queue(status,risk_level,domain,created_at)`（队列查询）、`ix_review_assignee(assignee_id,status)`。

> 原 `manual_review_correction` / `manual_review_outbox` / `manual_review_execution` / `manual_review_execution_event` 四张表的模型已删；存量表未 DROP（历史数据），新代码不再读写。

## 四、关键 env

`REVIEW_SNAPSHOT_MAX_BYTES`(2MB)、`REVIEW_EVIDENCE_MAX_BYTES`(20MB)、`REVIEW_EVIDENCE_CONTENT_TYPES`（附件类型白名单）、`REVIEW_S3_*`（证据附件桶，默认 `tech-kg-review-evidence`）、`REVIEW_HEADER_*`（网关身份头名，默认 `X-User-Id` 等）。

## 五、工作时序图

### 5.1 workflow 建案（唯一 ingress，幂等 + 对象隔离）

```mermaid
sequenceDiagram
    autonumber
    participant WF as 抽取/对齐 workflow<br/>(temporal_workflows.py)
    participant SVC as create_direct_case
    participant DB as 业务库 manual_review_case

    note over WF: T_LINK 同名冲突 / T_EXTRACT_FAIL 逐行失败 /<br/>T_DIRECT 低置信候选（confidence<0.85）
    WF->>SVC: {task_id, execution_id, step_id, kind, candidate, object_id, reason, confidence, template_id}
    SVC->>SVC: 模板×step 匹配校验；快照 ≤2MB
    SVC->>SVC: dedupe_key = sha([task_id, step_id, object_id, sha(snapshot)])
    alt dedupe_key 已存在
        SVC-->>WF: 幂等返回 duplicate（不重建）
    end
    SVC->>DB: INSERT case（id=MR-{date}-{hex12}, status=OPEN, risk 评定：confidence<0.7→P0）
    SVC-->>WF: {reviewId, status, riskLevel, isolationStrategy=ISOLATE_OBJECT, duplicate}
```

### 5.2 审核处置主线（直审：打开 → 提交即执行 → RESOLVED）

```mermaid
sequenceDiagram
    autonumber
    actor R as 审核员
    participant FE as 审核工作台
    participant API as /production/* handler
    participant SVC as ManualReviewService
    participant DB as 业务库

    R->>FE: 打开 case（无需领取）
    R->>FE: 填写裁决（T_LINK：entityVerdict + targetEntityId）→ 提交
    FE->>API: POST /production/{id}/submit（version 乐观锁，两人同开先提交者生效）
    SVC->>SVC: T_LINK entity-confirm？→ _apply_link_verdict 真实写图
    SVC->>DB: decision=APPROVED + status=RESOLVED（一切提交即执行，无审批环节；assignee 记提交人）
    note over SVC: 领取为可选保留路径（claim/heartbeat/release/reclaim）：已被他人领取的 case 限领取人/review_admin 提交。
```

### 5.3 T_DIRECT 两步决策（直写图库旁路）

```mermaid
sequenceDiagram
    autonumber
    actor R as 审核员
    participant FE as 工作台(T_DIRECT 五段式布局)
    participant API as /production/{id}/direct-decide
    participant SVC as ManualReviewService
    participant TG as trs-graph / Nebula

    R->>FE: 查看候选（candidate_snapshot 含 _kind/_nodeLabel/_confidence 等元字段；<br/>confidence<0.7 → P0）
    alt accept（可先修正候选字段）
        R->>FE: accept / accept-fix
        FE->>API: {accepted: true, candidate?}
        SVC->>TG: _coerce_to_schema：DESCRIBE TAG/EDGE 对齐 schema（多余字段塞 extra_json）
        alt 实体
            SVC->>TG: nGQL INSERT VERTEX（列级幂等 upsert，不走 /nodes/merge）
        else 关系
            SVC->>TG: create_edge(fromId, toId, edgeType, props)
        end
        SVC-->>FE: RESOLVED（仅写 case + audit）
    else reject
        R->>FE: reject
        SVC-->>FE: REJECTED（丢弃候选）
    end
```

### 5.4 T_EXTRACT_FAIL 重跑闭环（跨模块）

```mermaid
sequenceDiagram
    autonumber
    actor R as 审核员
    participant FE as 运营中心(C 队列)
    participant API as manual-review handler
    participant SE as schema_extraction.rerun_failed_records
    participant SVC as ManualReviewService
    participant OPS as workflow_operations_service
    participant TP as Temporal(kg.schema.extract)

    note over SVC: case 来源：抽取 workflow 的 record_extract_failures activity<br/>逐行落 T_EXTRACT_FAIL（exception_code=KG_EXTRACT_RECORD_FAILED）
    R->>FE: 勾选失败 case（可批量，>20 条需确认）
    FE->>API: POST /production/rerun-extract-failures {caseIds}
    API->>SE: rerun_failed_records
    SE->>SVC: list_extract_fail_cases（OPEN/RERUN_FAILED）
    SE->>SE: 按 schemaId 分组合并 → payload 带 recordIdsBySource + triggerSource=RERUN
    SE->>SVC: mark_extract_rerun（OPEN→RERUNNING，先标防竞态）
    SE->>OPS: execute_definition 触发重跑执行
    alt 触发失败
        SE->>SVC: revert_extract_rerun（回滚 OPEN）
    end
    SE->>SVC: attach_rerun_execution（rerunExecutionId 补写 snapshot）
    SE-->>FE: 新执行 id（反馈条可跳转执行详情；执行历史在任务详情页查看）
    TP->>SVC: workflow 收尾 activity resolve_failure_cases → resolve_extract_rerun
    alt 重跑成功
        SVC->>SVC: 相关 case → RESOLVED
    else 仍失败
        SVC->>SVC: 原 case RESOLVED(superseded) + create_direct_case 重建 attempt+1 新 case 供再重跑
    end
```
