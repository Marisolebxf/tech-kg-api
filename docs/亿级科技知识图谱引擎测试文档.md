# 亿级科技知识图谱引擎测试文档（dev2 主栈）

场景：在 dev2 主栈**新建一个图空间**，从零走完 建 Schema → 绑来源表 → 传脚本 → 跑抽取 → 验收。样例 6 个实体 + 3 个关系，全部按页面上鼠标怎么点来写，验收数字是精确值（见 Step 6）。

- 访问地址：`https://edu.itic-sci.com/bkg_zpt`
- 登录：统一认证登录——输入账号、密码、验证码后进入平台

样例对象：

- 数据实体 3 个：Paper 论文、Journal 期刊、IndustryChain 产业链
- 关系端点实体 3 个（关系要连它们，必须先建）：IndustryNode 产业链节点（BELONGS_TO_NODE 终点）、Organization 机构（BELONGS_TO_NODE 起点）、Person 科技专家（AUTHORED_BY 终点）
- 关系 3 个：PUBLISHED_IN（论文→期刊）、AUTHORED_BY（论文→专家）、BELONGS_TO_NODE（机构→产业链节点）

## Step 1 新建图空间（配置管理页）

1. 左侧导航 **「配置管理」** → 左侧分类切到 **「图数据空间」** → 右上 **「＋ 新建图数据空间」**。
2. 弹窗里：图数据空间名称填新空间名（仅字母/数字/下划线，字母或下划线开头，如 `gkx_lite_2`）；说明选填 → **「创建」**。创建后有秒级传播延迟——紧接着建 Schema 若偶发 DDL 失败，等几秒重试即可。
3. 数据源用已有的 **`dev2-default`**（指向 `gkx_lite` 库），无需新建。
4. 到 **「平台总览」**，右上角**全局图空间选择器**（级联下拉：公共图空间 → 具体空间名）切到新空间——之后 Schema 管理、图谱构建、统计全都跟随这个选择。

## Step 2 建 Schema（Schema 管理页，逐个建）

**实体的点法**：「Schema 管理」→「标准实体」标签页 → 右上 **「＋ 增加」** → 填 实体名 / 中文名 / 说明 → 属性表里带锁图标的公共必选属性已自动带出，点「添加属性」按下方表格逐个补业务属性（属性名 + 类型）→ 底部「nGQL 预览」扫一眼 → **「预览并创建」→「确认创建」** 两步 → 应看到 toast「已创建并执行图 DDL」。

**关系的点法**：切「关系」标签页 →「＋ 增加」→ 填 关系英文名 / 中文名 / **起点实体** / **终点实体**（下拉选）→ 补业务属性 → 同样「预览并创建」→「确认创建」（执行 CREATE EDGE）。

**六个实体要填的东西：**

| 实体名 | 中文名 | 业务属性（属性名＋类型，逐个添加） |
|---|---|---|
| `Paper` | 论文 | title_zh(string)、title_en(string)、doi(string)、publication_year(string)、publication_date(string)、language(string)、document_type(string)、publication_type(string)、volume(string)、issue(string)、start_page(string)、end_page(string)、is_oa(string)、source_url(string)、source(string)、created_time(string)、updated_time(string)、output_awards(string) |
| `Journal` | 期刊 | name_zh(string)、name_en(string)、name_abbr(string)、issn(string)、eissn(string)、country(string)、founding_time(string)、impact_factor(string)、is_sci(string)、jcr_zone(string)、cite_nums(string)、annual_publication(string)、publication_cycle(string)、source(string)、zh_core(string)、sub_quartile(string)、top(string)、scope_zone(string) |
| `IndustryChain` | 产业链 | chain_code(string)、chain_name(string) |
| `IndustryNode` | 产业链节点 | node_id(string)、node_name(string)、node_type(string)、level(string)、node_seq(string)、node_imp_level(string)、node_stage(string)、node_path(string) |
| `Organization` | 机构 | name_cn(string)、name_en(string)、province(string)、city(string)、org_kind(string)、founded_year(int64) |
| `Person` | 科技专家 | name_zh(string)、name_en(string)、scholar_org(string)、paper_nums(int64)、h_index(int64) |

**三个关系要填的东西：**

| 关系英文名 | 中文名 | 起点实体 | 终点实体 | 业务属性 |
|---|---|---|---|---|
| `PUBLISHED_IN` | 论文发表关系 | Paper | Journal | volume(string)、issue(string)、start_page(string)、end_page(string)、publication_year(string) |
| `AUTHORED_BY` | 论文署名关系 | Paper | Person | author_order(string)、is_corresponding(string)、citations(int64) |
| `BELONGS_TO_NODE` | 企业归属产业链节点 | Organization | IndustryNode | chain_score(double) |

注意三点：

- **说明字段别用 `+` 或 `!@#￥%&`**：弹窗校验会拦「说明不能包含异常字符」，多个表名用「与」连接（如「dwd_scholar 与 dwd_zh_author」）。
- 不用手填的：实体公共必选属性 `id/name/create_time/update_time/source_table`（关系是 `create_time/update_time/source_table`）弹窗里自动带出且带锁；溯源列建 TAG/EDGE 时平台自动注入。
- **先建实体再建关系**，否则关系弹窗的起点/终点下拉里选不到 Person/Organization/IndustryNode。

## Step 3 绑来源表（全绑在 gkx_lite 一个数据源上）

点法：列表找到该 Schema 的行 → 操作列 **「···」→「来源表」** → 弹窗里 **「＋ 绑定来源表」** 逐行加：数据源/库/表按下表选 → **主键列自动带出且正确，直接用**；**时间列要手动选 `updated_time`** → **「保存绑定」** → toast「来源表绑定已保存」，弹窗自动关闭。注意：**保存绑定不会自动触发抽取**，抽取在 Step 5。

| Schema | 数据源→库 | 表（行数） | 主键列（自动带出） | 时间列（手选） |
|---|---|---|---|---|
| Paper | → `gkx_lite` | `dwd_zh_paper`(10) | id | updated_time |
| Journal | → `gkx_lite` | `dwd_zh_journal`(5) | pk_id | updated_time |
| IndustryChain | → `gkx_lite` | `dwd_industry_chain_info`(10) | pk_id | updated_time |
| IndustryNode | → `gkx_lite` | `dwd_industry_chain_info`(10) | pk_id | updated_time |
| Organization | → `gkx_lite` | `dwd_org_base_info`(6) | dwd_id | updated_time |
| Person | → `gkx_lite` | `dwd_scholar`(6) | dwd_id | updated_time |
| Person | → `gkx_lite` | `dwd_zh_author`(19) | pk_id | updated_time |
| PUBLISHED_IN | → `gkx_lite` | `dwd_zh_paper`(10) | id | updated_time |
| AUTHORED_BY | → `gkx_lite` | `dwd_zh_author`(19) | pk_id | updated_time |
| BELONGS_TO_NODE | → `gkx_lite` | `dwd_org_industry_chain_dtl`(8) | chain_code（复合主键取首列） | updated_time |

某行没选完整（数据源/库/表缺一）就点保存会被拦：toast「存在未选择完整的来源表绑定（数据源/库/表均需选择）」。说明：

- **时间列必须手动点选**：选完表后时间列自动带出的常是空，直接保存会存成空串，增量水位列就没了。
- 同一张表绑给多个 Schema 是正常的（`dwd_industry_chain_info` 同时绑 IndustryChain 和 IndustryNode）。

## Step 4 传脚本

点法：该 Schema 行 → 操作列 **「更换脚本」**（从未传过时显示「上传脚本」）→ 弹窗里选文件（仅支持 .py）→ 提交 → 应看到「正在上传并校验...」→「**脚本已通过安全校验并保存**」→ 列表「脚本状态」列从「未上传」变「已上传」。文件取自物料包 `docs/gkx_local_1_materials/scripts/page_test/`（页面直传精简版，文件名与下表一致）：

| Schema | 脚本文件 |
|---|---|
| Paper | paper_entity_step.py |
| Journal | journal_entity_step.py |
| IndustryChain | industry_chain_entity_step.py |
| IndustryNode | industry_node_entity_step.py |
| Organization | organization_entity_step.py |
| Person | person_entity_step.py |
| PUBLISHED_IN | published_in_relation_step.py |

若被拒：偶发的「LLM 调用失败」多为限流，等 20 秒左右点「重新选择」重传即可；若提示具体风险指控（对这套模板脚本属误判）或反复调用失败，先去「配置管理 → 语言模型」确认**默认**配置测试通过，必要时把默认切到一条可用的配置再重传。

「查看脚本」可随时看已传内容。

## Step 5 跑抽取（图谱构建 → 新建任务）

1. 左侧导航 **「图谱构建」**（本页就是任务列表）→ 右上 **「新建任务」**。
2. 弹窗里照这个填：
   - 任务名称：随意（如 `精简样例链`）
   - 任务类型：**「多脚本串行」**
   - 「串联 Schema 队列」搜索框依次添加 9 个：IndustryChain、IndustryNode、Journal、Organization、Person、Paper、PUBLISHED_IN、AUTHORED_BY、BELONGS_TO_NODE；用行内 **「上移」「下移」** 排成**先实体后关系**（边要等端点实体先在图里）；至少 2 个、最多 20 个
   - 批大小（对每个 Schema 生效）：`2000`（默认 500；库总共 64 行，500 也一次读完）
   - MySQL 数据源 / 数据库：默认跟随 Schema 绑定，**不用动**
   - 增量游标 since：留空
   - 执行模式：**「一次性」** → 创建。
3. 点任务卡进 **「任务详情」**：每个 Schema 一个抽屉，抽屉里是脚本转换步；上方执行历史看每次触发的终态。
4. 终态怎么读：`COMPLETED` 全部成功；`FAILED` 整链中止（链上任一环失败即中止，修完从失败环重跑）；`ABNORMAL` **≠失败**——抽取完成但有个别失败行转了人工审核，图已写入。
5. 只想跑一个 Schema：任务类型选「单脚本抽取」，选目标 Schema 即可。

## Step 6 验收（精确数字）

1. **任务详情**：执行历史终态 `COMPLETED`（或 `ABNORMAL`，个别失败行在「人工审核」里处理）。

2. **实体列表**（「图谱查询 → 实体列表」）：「实体类型」逐个切，数量应**精确等于**下表（64 行源数据全量进图，一行不多一行少）：

| 实体 | 期望数 | 来源 |
|---|---|---|
| Paper 论文 | **10** | dwd_zh_paper 10 行 |
| Journal 期刊 | **5** | dwd_zh_journal 5 行 |
| Person 科技专家 | **6** | dwd_scholar 6 人（author 表 19 行署名的 author_id 均落在 A2026L001–006） |
| Organization 机构 | **6** | dwd_org_base_info 6 行 |
| IndustryChain 产业链 | **2** | IC0101 集成电路产业链、IC0202 人工智能产业链 |
| IndustryNode 产业链节点 | **10** | 2 链×5 节点 |

边（PUBLISHED_IN **10**、AUTHORED_BY **19**、BELONGS_TO_NODE **8**）在任务详情每个 Schema 的写入数里核对。

3. **点开任意一条实体**：属性有值且与源表一致（如 Paper P2026L001 的 doi/volume；Person 的 paper_nums/h_index 来自 dwd_scholar）；溯源列 source_table 记录**裸表名**（如 `dwd_zh_paper`，不带库名前缀——脚本取 `source_table` 最后一段）。实体列表页顶部的关键词搜索框搜《轻量级知识图谱构建综述》应唯一命中 `paper_P2026L001`。

4. **图上查关系**：「图谱查询 → 综合查询」nGQL 控制台执行（当前图空间选新空间，DDL 禁止执行）：

   ```ngql
   GO FROM "paper_P2026L001" OVER PUBLISHED_IN YIELD dst(edge) AS dst, $$.Journal.name_zh AS journal
   -- 1 行：journal_J001 中国科学:信息科学

   GO FROM "paper_P2026L001" OVER AUTHORED_BY YIELD dst(edge) AS dst, $$.Person.name_zh AS expert
   -- 3 行：person_A2026L001 张守拙、person_A2026L002 李慎行、person_A2026L003 王铸精
   ```

5. **幂等复跑**：再新建一个同配置任务跑一遍——执行很快结束且上表计数全部不变（水位已高 → 空读快过，不重复写图）。
