# 亿级科技知识图谱引擎测试文档

在 Chrome 完成：**新建空间 → 建 Schema → 绑定来源 → 上传脚本 → 抽取 → 查询与算法 → 人工审核 → 增量复跑**。

当前 `gkx_lite` 已追加人工审核真实样本，不能再按旧版 **39 实体 / 37 关系**验收全表。该数字仅是历史轻量样例基线；历史结果保留在历次测试报告中，不重复列入操作流程。

## 1. 准备

- 平台：[亿级科技知识图谱引擎](https://edu.itic-sci.com/bkg_zpt/overview)，统一认证登录。
- 使用已有 `gkx_lite`，**不重新执行初始化 SQL**。脚本：[基础脚本目录](gkx_local_1_materials/scripts/page_test/)。
- 人工审核触发脚本、故障注入脚本和真实证据卡由管理员提供；真实姓名、完整映射和内部原件不进入公开仓库，见[物料说明](gkx_lite_materials/append_real_20261019/README.md)。材料缺失时注明未测，不猜身份、不直接修改审核表造案件。
- 「配置管理 → 图数据空间」新建专用空间，如 `gkx_ui_YYYYMMDD_01`，回「平台总览」切换至该空间。后续写入和裁决仅针对本轮新空间，不改旧图、旧案件及水位。
- 本轮暂不测试 **Louvain**，不更换算法 JAR。PageRank、Degree 仍需验收。

## 2. 建 Schema

「Schema 管理 → 标准实体 / 关系 → 增加」，填写名称、业务属性；先建实体，再建关系并选择端点。提交「预览并创建 → 确认创建」，核对成功提示和列表。

公共属性由平台提供，不重复添加。下表未标注类型的属性均为 **string**。

| 实体 | 中文名 | 业务属性 |
|---|---|---|
| Paper | 论文 | title_zh、title_en、doi、publication_year、publication_date、language、document_type、publication_type、volume、issue、start_page、end_page、is_oa、source_url、source、created_time、updated_time、output_awards |
| Journal | 期刊 | name_zh、name_en、name_abbr、issn、eissn、country、founding_time、impact_factor、is_sci、jcr_zone、cite_nums、annual_publication、publication_cycle、source、zh_core、sub_quartile、top、scope_zone |
| IndustryChain | 产业链 | chain_code、chain_name |
| IndustryNode | 产业链节点 | node_id、node_name、node_type、level、node_seq、node_imp_level、node_stage、node_path |
| Organization | 机构 | name_cn、name_en、province、city、org_kind、founded_year(**int64**) |
| Person | 科技专家 | name_zh、name_en、scholar_org、paper_nums(**int64**)、h_index(**int64**) |

| 关系 | 中文名 | 起点 → 终点 | 业务属性 |
|---|---|---|---|
| PUBLISHED_IN | 论文发表关系 | Paper → Journal | volume、issue、start_page、end_page、publication_year |
| AUTHORED_BY | 论文署名关系 | Paper → Person | author_order、is_corresponding、citations(**int64**) |
| BELONGS_TO_NODE | 企业归属产业链节点 | Organization → IndustryNode | chain_score(**double**) |

| IndustryNode | dwd_industry_chain_info | 10 | pk_id | industry_node_entity_step.py |
| Journal | dwd_zh_journal | 9 | pk_id | journal_entity_step.py |

## 4. 首轮抽取与基础验收

「图谱构建 → 新建任务」：多脚本串行，队列依次为 **IndustryChain → IndustryNode → Journal → Organization → Person → Paper → PUBLISHED_IN → AUTHORED_BY → BELONGS_TO_NODE**；批大小 `2000`，since 留空，一次性，确认「创建后立即执行」已勾选。

记录任务/执行 ID，在详情核对 9 步状态、每来源处理行数、失败记录及输入输出。**COMPLETED 只说明执行结束，不代替业务验收**；仍须检查是否有待审实体、暂存边。失败或 ABNORMAL 要列明原因，不用重试成功掩盖首轮失败。

### 4.1 数量和属性

在实体列表逐类查询，并在综合查询执行：

```ngql
MATCH (v) RETURN labels(v) AS entity_type, count(v) AS total
MATCH ()-[e]->() RETURN type(e) AS relation, count(e) AS total
FETCH PROP ON Paper "paper_P2026L001" YIELD properties(vertex) AS props
FETCH PROP ON Person "person_A2026L001" YIELD properties(vertex) AS props
GO FROM "paper_P2026L001" OVER PUBLISHED_IN YIELD dst(edge) AS dst, $$.Journal.name_zh AS journal
GO FROM "paper_P2026L001" OVER AUTHORED_BY YIELD dst(edge) AS dst, $$.Person.name_zh AS expert
```

- 无来源变化时，Paper/Journal/Organization/IndustryChain/IndustryNode 分别为 **90/9/16/2/10**。Person 与 AUTHORED_BY 受消歧和待审扣留影响，按实际写入、扣留、合并及裁决逐项对账，不按源行数强算。
- PUBLISHED_IN 预期 90；BELONGS_TO_NODE 预期 18。关系核对图上唯一边，不用脚本输出行数代替。
- 搜索《轻量级知识图谱构建综述》唯一命中 `paper_P2026L001`，volume=`56`。
- 检查 `person_A2026L001` 至 `006`：姓名与学者来源的 scholar_org/paper_nums/h_index 均保留；001 的 h_index=`18`。
- 样例发表查询返回 `journal_J001 / 中国科学:信息科学`；署名返回 001–003 三位样例专家。新增真实样本与旧样例分列，不把行级 VID 数冒充真实人数。

### 4.2 总览、算法与交互

- 总览总量与图查询一致。「昨日新增」按来源写入数求和；详情中「净新增」是相邻日图统计快照差，二者不必相等。快照缺失不按 0 验收。可用 `overview?day=YYYY-MM-DD` 指定统计日。
- PageRank、Degree 选择本轮三种关系。先保存只读边集合，按**实际端点并集**核对结果 VID；Degree 逐点核对出入度，入度和=出度和=边数。PageRank 按实际参数独立复算，不直接套用旧版 34 行。
- 检查筛选、分页、详情、CSV 导出与取消。页面最多展示 200 行，筛选和 CSV 覆盖已返回的完整结果；核对响应总量和 truncated，不把显示上限当成算法漏点。记录首次失败、恢复结果和未测项。Louvain 本轮跳过。

## 5. 人工审核

与基础空间隔离，新建审核空间；只需按第 2–3 节建 **Person、Paper、AUTHORED_BY**。Person 用管理员提供的 **23 案触发版**，其余用基础脚本。先仅绑定 Person 的学者来源，单独执行并查询确认学者已入图；再追加作者来源，执行 Person → Paper → AUTHORED_BY。**绑定行排在前面不代表来源一定串行**；若建案时候选尚未入图，案件快照可能无候选，不能靠抽取结束后刷新详情补救。追加绑定后须核对实际读取量；本轮观察到原学者来源也被重读，不预设其空读，也不手工删除或降低水位。

「人工审核 → 入库决策」核对本轮空间、来源任务、固定 23 案及额外自然灰区案件。额外案件单独记，不强行要求队列总数=23。

| 组别 | 固定案数 | 验收重点 |
|---|---:|---|
| 合并 | 8（强证据4、辅助4） | 按证据卡选候选；辅助证据不预设身份结论。合并前保存目标属性，合并后旧 h_index/paper_nums/scholar_org 等不能因输入缺列而清空，暂存边端点正确补写 |
| 新实体 | 9 | 独立 VID、来源属性和对应边正确，不误并同名异人 |
| 驳回 | 6 | 按既定 Person 范围/质量规则判定；挂起点不入图、暂存边不补写 |

「均不匹配，驳回候选」实际表示**该记录不入 Person 图**，案件终态为已完成（RESOLVED），不是“配对错但仍应入图”；后者应选择新实体。信息不足的自然灰区案件不为了凑数量强行裁决。

每案保留：case ID、动作、前后属性/图计数、关系端点、状态与审计。重点区分“决议已落库”和“属性合并正确”。普通账号访问权限需用实际非管理员会话测试；管理员查看门禁代码不能代替权限验收。

## 6. 抽取失败重跑

使用**另一新空间、新 Schema 和新绑定**，不得在已推进水位的基础空间换故障脚本后声称首轮故障被覆盖。管理员提供受限重跑方案：Paper/Person 用基础版，AUTHORED_BY 在首次读取就用标明故障注入的版本。

固定 7 案验收分四项记录：

1. 注入首跑：确实读取目标记录、生成 T_EXTRACT_FAIL，7 条唯一目标边查无，失败原因带注入标记。
2. 换回基础脚本，逐案「重跑」：只处理选中记录，待处理→重跑中→已完成，7 条边端点/rank/属性正确补齐，审计可追溯。若队列显示失败而执行已成功，分别保存证据；打开执行日志后再查队列，仍不能把此前状态误报记为通过。
3. 终态再提重跑：记录入口拒绝/跳过，以及是否新增执行、决议和审计。
4. 实际重复写图：仅在有受控重提交通道时测试；目录唯一性阻止重复 Schema 等导致无法执行时，记**实际写图幂等未测**，不能用入口拦截代替。

管理员原固定子集为 6 篇论文、45 个作者行，目标关系 38→45；仅当读取范围和注入清单相同才套用此数。无页面自定义 SQL 入口时，来源范围须先由管理员准备，不绕内部接口改绑定。不得重置终态案件、删除审计或降低水位来制造通过。

纯页面替代用例：新隔离空间绑定全表，署名脚本仅对既有样例作者 `A2026L001 / A2026L002` 抛带 `FAULT_INJECTION` 标记的异常，其余映射不变；先查询确认对应 7 条唯一边，再验收缺边→补回。该用例的实际输入和边数另记，不冒充上述固定子集。

## 7. 增量复跑与交付

在无来源变化时，新建同 Schema、同绑定任务再跑：预期 9 步成功、来源读取和写入为 0，图数量不变。这是**增量空读**，不是全量重复写的幂等验证。
