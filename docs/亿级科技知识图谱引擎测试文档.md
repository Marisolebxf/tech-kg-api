# 亿级科技知识图谱引擎测试文档

场景：**新建一个图空间**，从零走完 建 Schema → 绑来源表 → 传脚本 → 跑抽取 → 验收。样例取 3 个实体（Paper 论文 / Journal 期刊 / IndustryChain 产业链）+ 3 个关系（PUBLISHED_IN / AUTHORED_BY / BELONGS_TO_NODE），全部按页面上鼠标怎么点来写。

## Step 1 新建图空间（配置管理页）

1. 左侧导航 **「配置管理」** → 左侧分类切到 **「图数据空间」** → 右上 **「＋ 新建图数据空间」**。
2. 弹窗里：图数据空间名称填新空间名（仅字母/数字/下划线，字母或下划线开头，如 `gkx_test_1`）；说明选填 → **「创建」**。
   - 页面提示属实：真实执行 CREATE SPACE，创建后有**秒级传播延迟**——紧接着建 Schema 若偶发 DDL 失败，等几秒重试即可。
3. 顺手确认数据源：同页分类切 **「MySQL 数据源」**，列表里应有 `MYSQL-DWD-LOCAL`（指向库 `gkx_dwd_local`）；没有就「＋ 新建配置」补一个。
4. 到 **「平台总览」**，右上角**全局图空间选择器**切到新空间——之后 Schema 管理、图谱构建、统计全都跟随这个选择。

## Step 2 建 Schema（Schema 管理页，逐个建）

**实体的点法**：「Schema 管理」→「标准实体」标签页 → 右上 **「＋ 增加」** → 填 实体名 / 中文名 / 说明 → 属性表里带锁图标的公共必选属性已自动带出，点「添加属性」按下方表格逐个补业务属性（属性名 + 类型）→ 底部「nGQL 预览」扫一眼 → **「确认创建」** → 应看到 toast「已创建并执行图 DDL」。

**关系的点法**：切「关系」标签页 →「＋ 增加」→ 填 关系英文名 / 中文名 / **起点实体** / **终点实体**（下拉选）→ 补业务属性 → 确认创建（执行 CREATE EDGE）。

**三个实体要填的东西：**

| 实体名 | 中文名 | 业务属性（属性名＋类型，逐个添加） |
|---|---|---|
| `Paper` | 论文 | title_zh(string)、title_en(string)、doi(string)、publication_year(string)、publication_date(string)、language(string)、document_type(string)、publication_type(string)、volume(string)、issue(string)、start_page(string)、end_page(string)、is_oa(string)、source_url(string)、source(string)、created_time(string)、updated_time(string)、output_awards(string) |
| `Journal` | 期刊 | name_zh(string)、name_en(string)、name_abbr(string)、issn(string)、eissn(string)、country(string)、founding_time(string)、impact_factor(string)、is_sci(string)、jcr_zone(string)、cite_nums(string)、annual_publication(string)、publication_cycle(string)、source(string)、zh_core(string)、sub_quartile(string)、top(string)、scope_zone(string) |
| `IndustryChain` | 产业链 | chain_code(string)、chain_name(string) |

**三个关系要填的东西：**

| 关系英文名 | 中文名 | 起点实体 | 终点实体 | 业务属性 |
|---|---|---|---|---|
| `PUBLISHED_IN` | 论文发表关系 | Paper | Journal | volume(string)、issue(string)、start_page(string)、end_page(string)、publication_year(string) |
| `AUTHORED_BY` | 论文署名关系 | Paper | Person | author_order(string)、is_corresponding(string)、citations(int64) |
| `BELONGS_TO_NODE` | 企业归属产业链节点 | Organization | IndustryNode | chain_score(double) |

说明两点：

- 不用手填的：实体公共必选属性 `id/name/create_time/update_time/source_table`（关系是 `create_time/update_time/source_table`）弹窗里自动带出且带锁；溯源列 `vid/source_system/source_record_id/source_url/source_update_time/confidence/match_method/match_evidence/ingest_batch/ingest_time` 建 TAG/EDGE 时平台自动注入。
- `AUTHORED_BY` 的终点 `Person`、`BELONGS_TO_NODE` 的两端 `Organization`/`IndustryNode` 若新空间里还没有，先按实体的点法建出来（骨架即可；完整属性清单参照物料包 `docs/gkx_local_1_materials/schemas.json`）。**先建实体再建关系**，否则起点/终点下拉里选不到。

## Step 3 绑来源表（照 gkx_local_1 的来源表原样绑）

点法：列表找到该 Schema 的行 → 操作列 **「···」→「来源表」** → 弹窗里 **「＋ 绑定来源表」** 逐行加：数据源选 `MYSQL-DWD-LOCAL`（下拉显示"名称（host）"）→ 库选 `gkx_dwd_local` → 表按下表选 → 主键列/时间列会按表结构自动带出，和下表不一致再手改 → **「保存绑定」** → toast「来源表绑定已保存」。注意：**保存绑定不会自动触发抽取**，抽取在 Step 5。

| Schema | 表 | 主键列 | 时间列 |
|---|---|---|---|
| Paper | `dwd_en_paper` | dwd_id | updated_time |
| Paper | `dwd_zh_paper` | pk_id | updated_time |
| Paper | `dwd_scholar_papers` | dwd_id | - |
| Journal | `dwd_zh_journal` | pk_id | updated_time |
| Journal | `dwd_en_journal` | dwd_id | updated_time |
| IndustryChain | `dwd_industry_chain_info` | row_pk | - |
| PUBLISHED_IN | `dwd_zh_paper` | pk_id | updated_time |
| PUBLISHED_IN | `dwd_en_paper` | dwd_id | updated_time |
| AUTHORED_BY | `dwd_zh_author` | pk_id | - |
| AUTHORED_BY | `dwd_en_author` | dwd_id | - |
| AUTHORED_BY | `dwd_scholar_paper_relation` | dwd_id | - |
| AUTHORED_BY | `dwd_scholar_paper_relation_element` | row_id | - |
| BELONGS_TO_NODE | `dwd_org_industry_chain_dtl` | row_pk | - |

某行没选完整（数据源/库/表缺一）就点保存会被拦：toast「存在未选择完整的来源表绑定（数据源/库/表均需选择）」。

## Step 4 传脚本

点法：该 Schema 行 → 操作列 **「更换脚本」**（从未传过时显示「上传脚本」）→ 弹窗里选文件（仅支持 .py）→ 提交 → 应看到「正在上传并校验...」→「**脚本已通过安全校验并保存**」（通道带语法/入口静态检查 + LLM 审核，被拒会给原因）→ 列表「脚本状态」列从「未上传」变「已上传」（跑抽取前带「未运行」角标）。文件取自物料包 `docs/gkx_local_1_materials/scripts/`：

| Schema | 脚本文件 |
|---|---|
| Paper | paper_entity_step.py |
| Journal | journal_entity_step.py |
| IndustryChain | industry_chain_entity_step.py |
| PUBLISHED_IN | published_in_relation_step.py |
| AUTHORED_BY | authored_by_relation_step.py |
| BELONGS_TO_NODE | belongs_to_node_relation_step.py |

「查看脚本」可随时看已传内容；脚本由 `script/tools/build_portable_steps.py` 自动生成，**勿手改**。

## Step 5 跑抽取（图谱构建 → 新建任务）

1. 左侧导航 **「图谱构建」**（本页就是任务列表）→ 右上 **「新建任务」**。
2. 弹窗里照这个填：
   - 任务名称：随意（如 `精简样例链`）
   - 任务类型：**「多脚本串行」**
   - 「串联 Schema 队列」搜索框依次添加 6 个：IndustryChain、Journal、Paper、PUBLISHED_IN、AUTHORED_BY、BELONGS_TO_NODE；用行内 **「上移」「下移」** 排成**先实体后关系**（边要等端点实体先在图里）；至少 2 个、最多 20 个
   - 批大小（对每个 Schema 生效）：`2000`（默认 500）
   - MySQL 数据源 / 数据库：默认跟随 Schema 绑定，**不用动**
   - 增量游标 since：留空
   - 执行模式：**「一次性」** → 创建。
3. 点任务卡进 **「任务详情」**：每个 Schema 一个抽屉，抽屉里是脚本转换步；上方执行历史看每次触发的终态。
4. 终态怎么读：`COMPLETED` 全部成功；`FAILED` 整链中止（链上任一环失败即中止，修完从失败环重跑）；`ABNORMAL` **≠失败**——抽取完成但有个别失败行转了人工审核，图已写入。
5. 只想跑一个 Schema：任务类型选「单脚本抽取」，选目标 Schema 即可。
6. 新空间首跑即全量；跑完再触发一次是幂等的（水位已高 → 空读快过，不重复写图）。

## Step 6 验收

1. **任务详情**：执行历史终态 `COMPLETED`（或 `ABNORMAL`，个别失败行在「人工审核」里处理，可一键重跑）。
2. **实体列表**：类型切「论文」，看「共 N 个实体」——N 应与来源表行数同量级（三个源合计约 74 万，首跑耗时按此预估）；期刊、产业链同理。
3. **点开任意一条实体**：属性有值且与源表一致；溯源列 source_table 指向所绑的 `gkx_dwd_local.dwd_*` 表。
4. **图谱可视化**：搜一篇论文或一个机构名，周边关系能展开、连线可点。
5. **幂等复跑**：再触发一次任务，执行很快结束且实体计数不变。
