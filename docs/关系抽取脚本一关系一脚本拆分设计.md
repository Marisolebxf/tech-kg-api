# 关系抽取脚本"一关系一脚本"拆分设计

本文记录 `backend/script/relation_extractors_one_relation/` 的拆分设计与等价性决策，
配套单元测试 `backend/tests/unit/test_relation_extractors.py`。

## 背景与拆分原则

关系逻辑原本散落在 6 类旧脚本中（写入机制、幂等方式、点边耦合各不相同）：

| 旧脚本 | 边 | 写入机制 | 幂等方式 |
| --- | --- | --- | --- |
| `organization_relation_etl.py` | 11 种（32 条 spec） | nGQL `INSERT EDGE @rank` | 确定性 rank（sha256） |
| `load_scholar_relations.py` | AFFILIATED_WITH/COAUTHOR_WITH/AUTHORED_BY 兜底 | REST `merge_edge` | identityProps=source_record_id |
| `workflow/paper_journal_chain_etl.py` | 论文/期刊/产业链 8 种 | nGQL 多值 INSERT | rank@0 覆盖 |
| `load_patent_graph.py` | HAS_KEYWORD/MEMBER_OF_FAMILY | nGQL 多值 INSERT | rank@0 覆盖 |
| `load_patent_relations.py` | INVENTED_BY/APPLIED_BY/OWNED_BY/CITES/OUTPUT_OF | nGQL `INSERT EDGE @rank` | rank=序号 + 唯一 --replace |
| `load_project_graph.py` | FUNDED_BY/LEADS/HAS_PARTICIPANT/HAS_KEYWORD/HAS_OUTPUT | REST `merge_edge` | identityProps=source_record_id |
| `industry_chain_etl/load_industry_chain_graph.py` | 产业链 5 种 | nGQL 多值 INSERT | rank@0 覆盖 |

拆分原则（与实体包同口径）：

1. 一种边一个入口脚本；同名边跨域冲突按域分脚本（如 `patent_cites_relation.py` vs
   `paper_cites_relation.py`；`HAS_KEYWORD` 三个域各一个脚本）。
2. 边脚本一律不建顶点，端点缺失跳过计数；桩端点（AFFILIATED_WITH 机构名桩、论文
   DOI 桩、`paper_rp_` 桩）显式 `validate_endpoints=False`。
3. 数据内容严格等价：端点 VID、边属性、置信度、匹配决策、rank 语义沿用旧逻辑。
4. 双写通道保留旧机制：rank 模式（nGQL INSERT EDGE @rank）与 REST merge 模式，
   每条边按旧口径选择通道。

## 等价性决策清单（有意偏离旧口径的点，均为修复既有缺陷）

| # | 决策 | 旧口径问题 | 新口径 |
| --- | --- | --- | --- |
| 1 | Keyword VID 三域统一 | 专利=md5(casefold)、项目=md5(lower)、论文=md5(原文)，同一关键词会生成多个顶点 | 统一 `keyword_{md5(NFKC+空白折叠+casefold(kw))}`（专利域公式） |
| 2 | 机构域 person 端点 VID 统一为实体侧公式 | 关系侧 shareholder 不带 birth/country、executive 缺 external_id 回退，边起点对不上实体点 | 统一 `kind\|first(org_id, external_id)\|name\|birth\|country` |
| 3 | 6 条死配置不迁移 | dwd_zh/en_project 的 PARTICIPATES_IN/FUNDED_BY、industry_chain_dtl 的 BELONGS_TO_NODE/prod_dtl 的 PRODUCES 永不执行（source_table 不在表目录） | 不迁移；产业链边由产业链脚本承接、项目边由项目脚本承接 |
| 4 | 专利/项目域 Milvus 提升不在边脚本内 | 提升是独立的可选对齐步骤 | 保持独立对齐脚本（见"对齐修正配套"） |
| 5 | 专利 domain --replace 删除语义不迁移 | 唯一有 DELETE 的边脚本 | 新脚本只插不删，重灌前由运维显式清理 |
| 6 | 对齐修正脚本不并入本包 | `align_scholar_affiliations`/`align_paper_relations`/`align_project_relations` 已是解耦的单一职责脚本 | 原地保留，README 引用，避免代码重复 |

## 各边口径速查

### 产业链（rank@0，无属性或最小属性）
- `HAS_NODE` chain_{code}→node_{id}；`CHILD_OF` node→父；`DOWNSTREAM_OF` node→下游（均无属性）
- `BELONGS_TO_NODE` org_{antitypic}→node_{id}，chain_score double，org 端存在性过滤
- `COVERS_CHAIN` news_{id}→chain_{code}，(source_table, ingest_batch, ingest_time)

### 机构域（确定性 rank，edge_props 六件套 + extra_json，relation_confidence 动态打分）
- 11 种边、32 条活跃 spec 见 `catalog.py`；INVOLVED_IN 覆盖 17 张事件表
  （event 通用 / bankruptcy_party / bankruptcy_admin / bid_party 四种 extractor）
- 端点解析：ExactOrganizationResolver（7 张基础表精确唯一名）；股东/实控人按类型分流

### 学者域（REST merge）
- `AFFILIATED_WITH`：org_id 直连 1.0 / 机构名 md5 桩 0.6，work_experience_* 三属性随边
- `COAUTHOR_WITH`：有向单条，co_paper_count，1.0
- `AUTHORED_BY` 兜底：两端验存，0.9（cross_domain_id_match），paper 端用原始 id

### 论文链路（rank@0）
- `AUTHORED_BY`：paper 端去 `__数字` 后缀，(author_order, is_corresponding, 1.0)
- `PUBLISHED_IN`：publication_id 非空，仅 confidence
- `CITES`/`CITED_BY`（0.5）/`RELATED_TO`（0.7）：DOI 16 位 md5 桩端点
- `REFERENCED_BY`：`paper_rp_{paper_id}` 桩 → report，0.8，report_id 数组展开

### 专利域（rank@序号或 0）
- `HAS_KEYWORD`：keywords JSON 解析，(1.0, dwd_patent, patent_id)
- `MEMBER_OF_FAMILY`：(1.0, source_family_number, dwd_patent_family, patent_id)
- `CITES`：标识符双格式唯一命中，1.0（exact_patent_identifier），rank 0 去重
- `INVENTED_BY`：精确名 + 机构∩项目证据二次确认（0.90/0.80），未确认进 review JSONL
- `APPLIED_BY`/`OWNED_BY`：精确唯一机构名 0.98，多命中/Person 命中进 review

### 项目域（REST merge，identity=source_record_id）
- `FUNDED_BY`/`LEADS`/`HAS_PARTICIPANT`：ProjectEntityMatcher 精确匹配，仅 matched 写边，
  ambiguous/not_found 进 ProjectIngestReport
- `HAS_OUTPUT`：doi/专利号/标题精确链，source_record_id=`{project_id}|{output_type}|{target_vid}`
- `HAS_KEYWORD`：统一 keyword_vid
