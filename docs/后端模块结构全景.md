## 3. 模块间关系（树形 + 允许的横向引用）

**父子关系（严格树）**：每个业务/平台模块是「handler → application → service → (dao/db_model/infra)」的纵向切片；handler 只被 `biz/router/register.py` 挂载，装配层是树的根；`main.py` 是根的根。

**三条横向依赖规则**（树中唯一允许的跨枝引用）：

1. **12 个业务模块 → `service/base_module.py` + `service/module_catalog.py`**：业务 Service 继承 `KGModuleScaffoldService`，模块目录/描述统一来自 catalog；
2. **M8 → M7**：`expert_enterprise_mining` 抽取+消歧后回调 M7.1/M7.2/M7.3 的构建/标注/分析接口（唯一业务模块间调用链）；
3. **所有 service → `infra/*` 单件**：MySQL/Redis/trs-graph/Milvus/LLM/S3 一律经 infra 单件访问，service 不直连。

**性能旁路**：`infra/result_cache.py` + `biz/prewarm_business.py` 横切在所有 handler 之前（命中直接返回预序列化 JSON，绕过 Pydantic）。

**P3 ↔ ⑦ 平台喂数脚本**：`script/entity_extractors_one_entity/*` 与 `script/relation_extractors_one_relation/*` 是被 `kg.schema.extract` 工作流以子进程调用的转换脚本（只输出 JSON，不写图）；平台侧写图/消歧/索引/推水位。
