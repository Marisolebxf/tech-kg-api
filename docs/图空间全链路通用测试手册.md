**水位语义(后面反复用到)**:普通表绑定按 `update_time` 记水位(存在 `gkx_element.kg_script_watermark`,逐绑定一行)。每次执行只读 `update_time > 水位` 的**增量行**,全部批次成功后推进水位。所以:重跑不会重复读旧行;**想让某行被重新处理,把它的 `update_time` 改成当前时间(bump 过水位)即可**;空跑也会推水位(第 5.3 步会用到这个知识)。

## 第 4 步 上传 10 个抽取脚本

**脚本契约**(所有脚本同构):`from kg_sdk import step` + `@step def extract(payload)`,吃 `payload["rows"]`,实体输出 `{"entities":[{"id":vid,"props":{...}}],"failures":[{"recordId","error"}]}`,边输出 `{"edges":[{"fromId","toId","props":{...}}],"failures":[...]}`。逐行异常进 failures(毒行隔离),不抛出。函数名不得叫 transform/workflow。

在对应 schema 的**脚本编辑**区粘贴全文保存。保存时有语法检查 + **LLM 安全校验**两道关;LLM 环节偶发「LLM 返回格式异常」(实测 10 个脚本遇 2 次),**直接重试一次即可,不是脚本问题**。

> 【截图 S8:脚本编辑器(以 Organization 为例,已粘贴)】

### 4.1 Organization(机构)

```python
"""Organization(机构)抽取:dwd_org_base_info 行 → 机构实体。"""
from kg_sdk import step


@step
def extract(payload):
    entities, failures = [], []
    for row in payload.get("rows") or []:
        try:
            name = (row.get("name_cn") or "").strip()
            if not name:
                raise ValueError("缺少必需名称字段 name_cn")
            entities.append({
                "id": str(row["org_id"]),
                "props": {
                    "name": name,
                    "province": row.get("province") or "",
                    "city": row.get("city") or "",
                    "industry": row.get("industry_l1_name") or "",
                    "regStatus": row.get("reg_status") or "",
                    "capital": str(row.get("registered_capital_value") or ""),
                },
            })
        except Exception as exc:
            failures.append({"recordId": str(row.get("org_id") or ""), "error": f"{type(exc).__name__}: {exc}"[:1000]})
    return {"entities": entities, "failures": failures}
```

### 4.2 Officer(高管)

```python
"""Officer(高管)抽取:dwd_org_executive_info 行 → 高管实体(vid=org_id__姓名)。"""
from kg_sdk import step


@step
def extract(payload):
    entities, failures, seen = [], [], set()
    for row in payload.get("rows") or []:
        try:
            name = (row.get("executives_name") or "").strip()
            if not name:
                raise ValueError("缺少必需名称字段 executives_name")
            vid = f"{row['org_id']}__{name}"
            if vid in seen:  # 同一人在同一机构多行(多职位),合并为一个实体
                continue
            seen.add(vid)
            entities.append({
                "id": vid,
                "props": {"name": name, "position": row.get("executives_position") or ""},
            })
        except Exception as exc:
            failures.append({"recordId": str(row.get("row_id") or ""), "error": f"{type(exc).__name__}: {exc}"[:1000]})
    return {"entities": entities, "failures": failures}
```

### 4.10 COAUTHOR_WITH(合著,边)

```python
"""COAUTHOR_WITH(合著)边:Expert↔Expert,同一论文的前 2 作者两两成对(脚本内派生)。"""
from collections import defaultdict

from kg_sdk import step


@step
def extract(payload):
    edges, failures = [], []
    by_paper = defaultdict(list)
    for row in payload.get("rows") or []:
        if row.get("paper_id") and row.get("author_id"):
            by_paper[str(row["paper_id"])].append(str(row["author_id"]))
    for paper_id, authors in by_paper.items():
        unique = list(dict.fromkeys(authors))
        for i in range(len(unique)):
            for j in range(i + 1, len(unique)):
                a, b = sorted([unique[i], unique[j]])
                edges.append({"fromId": a, "toId": b, "props": {"paperId": paper_id}})
    return {"edges": edges, "failures": failures}
```

## 第 5 步 运行三类任务

> ### ⛔ 串行红线(本手册最重要的一条,先读三遍)
> 实体类抽取收尾会做**整空间向量索引重建**,重建持 worker 进程级全局单飞锁。同一 worker 上**任何空间**的重建进行中时,你的实体任务索引步会 `EntitySearchReindexInProgressError` 重试 5 次(约 1 分钟耗尽)后**整任务 FAILED**——行已写图,但不建审核案、不进昨日新增。因此:
> 1. **单脚本任务:一个跑到终态,再建/触发下一个**(实测 10 个全串行一次通过);
> 2. 触发前看到别的空间在重建(实体检索页/worker 日志有迹象)就等它结束;
> 3. 索引步可能**静默跑十几分钟**(实测一次 18 分钟,进度日志每 5000 行一条,小空间全程无输出),**别误判卡死**;
> 4. 任务列表状态是**惰性刷新**:Temporal 已终态而列表仍 RUNNING 时,**打开一次任务详情**即回落真实状态。

### 5.1 单脚本任务 ×10(先实体后关系,严格串行)

## 第 8 步 红线与排障速查

| 红线 | 说明 |
|---|---|
| **串行触发** | 实体任务一个跑完再触发下一个;索引重建是全局单飞锁,并发=后到的 FAILED(行已写图但不建案不计昨日新增);周期任务避开别的空间的重建时段 |
| **图空间显式带** | 触发任务必须显式 `graphSpace:"ewrdf"`;不带最坏静默写进 worker 默认空间 dev2 |
| **资源红线** | 只绑 ewrdf_test 7 张小表,batchSize=200;**勿对 gkx_element 的 dwd_* 大表做全表绑定**;共享图过载时变慢属正常,勿反复重启 |
| **图侧时间索引** | 平台建 TAG 只自动建 `idx_{tag}_name`,**没有 update_time 索引**;任何按 update_time 的时间窗 LOOKUP(含昨日新增明细反查)要先 `CREATE TAG/EDGE INDEX idx_*_ut ON x(update_time(20))` + **`REBUILD TAG/EDGE INDEX`**(异步 job,`SHOW JOBS` 确认 FINISHED;只 CREATE 不 REBUILD 索引只含建后增量,LOOKUP 漏全部历史行——症状:FETCH 可见、按属性 WHERE 查空) |
| **图网关错误体** | trs-graph REST 400/500 响应是 `{"error","message","status"}`、没有 summary.errorCode——脚本判错要查 `error` 字段,只查 summary 会把 400 当成功吞掉 |
| **字符集** | mysql 客户端必须 `--default-character-set=utf8mb4`,否则中文 0 命中/输出 `??` |
| **vid 上限** | 空间 vid=FIXED_STRING(64);本套数据最长 Officer 复合 vid ~44 字节,安全;自造数据别超 64 |
| **T_DIRECT 存量案** | 现行链路不产生 T_DIRECT;库里看到存量 T_DIRECT 勿在本空间测 accept(会写默认空间) |
| **幂等重跑** | 水位增量语义,重跑不重复读;重喂=bump `update_time`;INSERT VERTEX 覆盖幂等;消歧合并过的顶点重跑不会拆开 |

**症状 → 处置**:

| 症状 | 原因 | 动作 |
|---|---|---|
| 任务 FAILED,错误含 EntitySearchReindexInProgress | 撞别的空间索引重建 | 等锁空闲后 trigger 重触发;想让它读的行先 bump 过水位 |
| 列表 RUNNING 十几分钟不动 | 控制库惰性刷新 | 打开一次任务详情即回落;索引步本身也可能静默十几分钟 |
| 任务详情「进入人工处理」404 | 前端链接硬编码(已知缺陷) | 走 运营中心→人工审核 队列 |
| 审核队列空的 | 空间过滤没切/案在别的空间 | 队列切到本空间;确认执行终态是 ABNORMAL/COMPLETED 而非 FAILED |
| 中文查询 0 命中/`??` | 客户端字符集 | 加 `--default-character-set=utf8mb4` |
| MATCH 返回空对象不报错 | 属性没带 tag 前缀 | 用 `v.Tag.prop` |
| 时间窗 LOOKUP 查空但 FETCH 可见 | 时间索引没 REBUILD | CREATE INDEX 后必须 REBUILD,`SHOW JOBS` 确认 |
