### 3.4 上传抽取脚本

**脚本规范（重要）**：平台只接受 **`@step` 装饰器**声明的抽取函数（每个脚本一个文件、UTF-8、`.py` 后缀）；上传时经语法检查 + LLM 安全校验，逐阶段有进度提示。

**脚本 1：`emit_paper.py`**（在 Paper 的详情页上传）

```python
"""论文实体抽取。"""
from typing import Any, Mapping

from kg_sdk import step


@step
def emit_paper(payload: Mapping[str, Any]) -> dict[str, Any]:
    rows = payload.get("rows") or []
    entities, failures = [], []
    for row in rows:
        pid = str(row.get("id") or "").strip()
        title = str(row.get("title") or "").strip()
        if not pid or not title:
            failures.append({"recordId": pid, "error": "ValueError: 缺少 id 或标题"})
            continue
        entities.append({
            "id": "paper_" + pid,
            "props": {
                "id": pid,
                "title": title,
                "author_name": str(row.get("author_name") or ""),
                "publish_year": int(row.get("publish_year") or 0),
            },
        })
    return {"entities": entities, "failures": failures}
```

**脚本 3：`emit_writes.py`**（在 WRITES 上传）

```python
"""撰写关系抽取：papers 行 → 专家撰写论文边。"""
from typing import Any, Mapping

from kg_sdk import step


@step
def emit_writes(payload: Mapping[str, Any]) -> dict[str, Any]:
    rows = payload.get("rows") or []
    edges, failures = [], []
    for row in rows:
        author = str(row.get("author_name") or "").strip()
        pid = str(row.get("id") or "").strip()
        if not author or not pid:
            failures.append({"recordId": pid, "error": "ValueError: 作者或论文 id 缺失"})
            continue
        edges.append({
            "fromId": "expert_" + author,
            "toId": "paper_" + pid,
            "props": {"wrote_year": int(row.get("publish_year") or 0)},
        })
    return {"edges": edges, "failures": failures}
```

## 4. 图谱构建：任务与全流程

入口：左侧导航「图谱构建」。确认顶栏图空间 = 测试空间（任务列表按空间过滤；可开「全部空间」开关）。

### 4.1 新建任务（单 Schema）
新建任务 → 任务类型「数据抽取」→ 选目标 Schema（Paper）→ 批大小留空（默认 500）→
MySQL 数据源/数据库默认已自动带出（跟随 Schema 来源绑定，一般不用改）→ 执行模式「一次性」+ 勾选「创建后立即执行」→ 创建。

**预期**：任务出现在列表，状态先「运行中」后「已完成」；运行中可点「暂停」（按钮变「暂停中…」，数秒后变「已暂停」，再点「恢复」继续）。

### 4.2 新建任务（多脚本串行）
任务类型「多脚本串行」→ 按顺序添加：论文 → 专家 → 撰写（≥2 个，可上下移调序）→ 创建并立即执行。

**预期**：三环严格按顺序串行执行；详情页步骤顺序 = 添加顺序；任一环批次级失败整链失败，环内个别行失败不影响后续环。

### 4.3 预期结果

| Schema | 预期 | 说明 |
|---|---|---|
| Paper | 4 行读取 / 4 写图 / 0 失败 | 全部成功 |
| Expert | 4 行读取 / 3 写图 / **1 失败** | `e4` 姓名为空被脚本拒绝 → 生成 1 条人工审核 case |
| WRITES | 4 行读取 / 4 写图 / 0 失败 | 生成 4 条「撰写」边（张三 2 条） |

### 4.4 增量水位验证
同一任务再次「重新执行」（或周期到点）：**读取 0 行**（上次成功后水位已推进）——这是增量语义，不是故障。
如需全量重跑：Schema 详情 →「来源表」→「回填历史数据」（清水位）。

## 6. 人工审核链路验证（抽取失败 → 重跑 → 关闭）

1. 左侧「人工审核」→ 队列按类别 **C（抽取失败）**：应看到 1 条 `T_EXTRACT_FAIL` case（来源记录 e4，错误信息含「缺少 id 或姓名」）。
2. 先到数据库修复数据：`UPDATE kg_itest.experts SET name='赵六' WHERE id='e4';`
3. 回到审核队列该 case → 重跑（按页面「重跑」操作下发）。
4. **预期**：产生新执行（触发来源=RERUN），只读取 e4 这 1 行（ids 模式）；成功后 `expert_赵六` 入图，case 自动关闭（RESOLVED）。
5. 队列中该 case 消失（或状态变已解决）。

## 7. 已知非问题（测试时不要当 bug 提）

1. **MATCH 查询刚写入的数据短暂查不到**：Nebula 传播延迟（分钟级），实体列表页立即可见。
2. **重复失败行每次执行都新建审核 case**：当前设计如此（重跑关闭旧的、失败重建新的）。
3. **暂停**：暂停的是任务调度与后续步骤（当前步会正常跑完，之后挂起）；正在执行的批次不会中断。恢复后从挂起点继续。
4. **已完成任务没有「执行」按钮**：产品如此；需要重跑用「回填历史数据」或新建任务。
5. **详情页刚写入的数据 MATCH 查询短暂为空** 同第 1 条。
6. 上传脚本失败提示「单步 transform 入口已下线 / STEPS 已下线」：旧写法已被规范移除，必须用 `@step`（见 3.4 脚本）。
