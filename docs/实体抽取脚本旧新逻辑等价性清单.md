# 实体抽取脚本旧新逻辑等价性清单

本文约束 `backend/script/entity_extractors_one_entity/` 的重构实现：新脚本按"一种实体一个脚本"组织，**实体数据内容（输入表、过滤、VID、字段映射、默认值、置信度、跳过规则）与旧实体脚本严格一致**。2026-08 已按本清单完成一轮对齐修复并配套单元测试（`backend/tests/unit/test_entity_extractors_mappers.py`）。

保留的新架构差异（有意为之，非等价破坏）：

- 写图用逐条 `merge_node` HTTP upsert（非批量 nGQL `INSERT VERTEX`）；不写 `organization_base` mixin tag，溯源字段直接作为节点属性。
- 完整源行保留在 `extra_json`（机构域沿用旧 `bounded_json` 64K 上限与审计摘要降级；机构域节点在多源写入时合并为 `extra_json.source_records` 信封结构）。
- 统一附加 `vid`、`match_method`、`match_evidence` 属性；`ingest_batch`/`ingest_time` 为运行时动态值（旧部分脚本写死常量）。
- 机构域实体（Organization/Event/News/Product/Person-org-role）写前读取已有节点并复刻旧"合并保护"：保留已有非空标准属性、confidence 只升不降、`extra_json.source_records` 多源合并。
- 边（MEMBER_OF_FAMILY/HAS_KEYWORD/PUBLISHED_IN 等）不在实体脚本范围内，由关系脚本承接。

| 默认值 | 学者数值空值置 0、文本置空串、置信度 1.0；机构角色置信度为 `entity_confidence` 动态打分（0.4–1.0），空白属性写 NULL（不上报） |
| 跳过规则 | 缺稳定人员 ID 或缺可用姓名不建点 |
| 新脚本 | `person_entity.py`，`--source scholar/paper-author/organization-role` |

## 仍需验证

- 真实库 dry-run JSON diff：对同一批输入比对新旧脚本产出的 tag/vid/properties（`--dry-run` 目前输出计数，不输出逐点 JSON）。
- 真实库列存在性：新脚本 SQL 假定列存在（`SELECT *` 不受影响，专利聚合 SQL 需真实库验证）。
- 机构域 NULL 语义：新写图层不上报 None 值属性（等价旧 nGQL 写 NULL），需在真实 trs-graph 服务上确认 merge_node 行为一致。
- 机构域合并保护依赖 `execute_read` 的 MATCH 查询批量读点，需在真实图空间验证可用性。
- Paper `__数字` 后缀孤立点行为新旧一致地保留（实体 VID 用原始 id，仅关系端点去后缀）。
