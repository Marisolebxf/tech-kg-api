# 容器清单与分类说明

> 梳理自根目录各 docker-compose 文件 + `docker ps` 实际运行状态（2026-10-09）。
> 仓库 = `backend/`（FastAPI）+ `frontend/`（Vue3）monorepo，容器全部由 Docker Compose 编排。

## 一、应用核心（项目本体）

| 容器 | 干嘛的 |
|---|---|
| `api` / `api-dev2` | **后端主程序**（FastAPI）。所有业务接口：知识图谱构建、schema 管理、人工审核、修正中心等都从这里出 |
| `web` / `web-dev2` | **前端**（Vue3 打包后由 nginx 托管）。浏览器访问的就是它，页面里的 `/api` 请求由它反向代理给后端 |
| `temporal-worker` | **后台干活的**。和 api 同一个镜像，但不接请求，专门执行耗时任务：写图、批量抽取数据、重建索引。避免长任务卡死 API |

> 一个镜像三种用法：api 是 HTTP 服务，worker 是后台进程，区别只在启动命令。

## 二、工作流引擎（任务调度）

| 容器 | 干嘛的 |
|---|---|
| `temporal` | **任务队列/调度中枢**。api 把"建图任务"丢给它，它负责分配给 worker、失败重试、记录执行历史。类似 Celery 但更可靠 |
| `temporal-mysql` | Temporal 自己的数据库（存任务状态、执行记录），和业务库分开避免互相影响 |
| `temporal-ui` | Temporal 的网页控制台（宿主端口 8233），人用来查看/排查任务执行情况 |

## 三、数据存储

| 容器 | 干嘛的 |
|---|---|
| `tech-kg-mysql`（外部，gkx-mysql 项目） | **业务主库**。存学者/机构/论文/专利等业务数据（`gkx_element` / `gkx_local`）、审核记录、修正记录 |
| `trs-graph-service`（外部） | **图数据库网关**（Java 服务）。底层是 NebulaGraph 图数据库（`trsgraph` 系列容器），所有"实体-关系"图谱数据存在这里。后端不直连 Nebula，都走这个 HTTP 网关 |
| `auth-redis` | **登录会话存储**。用户登录态、审计日志存 Redis（带过期时间），重启不丢 |

## 四、AI / 向量检索

| 容器 | 干嘛的 |
|---|---|
| `milvus` | **向量数据库**。把文本转成向量后存这里，做相似检索（专利语义搜索、实体对齐去重） |
| `milvus-etcd` | Milvus 的元数据存储（Milvus 自带依赖） |
| `m3e-embedding` | **本地向量化服务**。把中文文本转成 512 维向量（m3e 小模型，CPU 跑），OpenAI 兼容接口。不用调外部 API，省钱且内网可用 |

> LLM 调用（智谱 glm）不走容器，是直接调线上 API。

## 五、对象存储

| 容器 | 干嘛的 |
|---|---|
| `operator-rustfs` | **S3 兼容文件仓库**（MinIO 的 Rust 替代品）。存三样：用户上传的抽取脚本、大批量中间数据（claim-check，防止撑爆 Temporal）、Milvus 内部数据 |
| `operator-rustfs-volume-init` | 一次性工具容器，启动时改一下数据卷的文件属主（chown 10001）就退出 |

## 六、安全沙箱（防用户脚本作恶）

| 容器 | 干嘛的 |
|---|---|
| `script-runner` | **受信执行器**。平台允许用户上传 Python 脚本做数据抽取，这个容器负责启动隔离环境。全栈加固：只读文件系统、禁提权、限 CPU/内存/进程数。全栈唯一持有 docker.sock 的容器 |
| 沙箱容器（临时生成） | 用户脚本真正运行的地方：**断网、只读文件系统、无任何挂载**、UID 65532，只能通过 SDK 接口拿数据，防注入防逃逸 |

## 七、多环境（同一套代码跑三份）

| 栈 | compose 文件 | 端口（api/web） | 用途 |
|---|---|---|---|
| **main** 生产 | `docker-compose.yml` | 8001 / 8088 | 正式环境 |
| **dev2** 测试 | `docker-compose.dev2.yml` | 8002 / 8089 | 日常开发联调（本仓库主力栈，另有 8091 根路径实例给 e2e） |
| **gray** 灰度 | `docker-compose.gray.yml` | 8008 / 8097 | 验证"消歧人工复核"新分支，免登录演示 |

- 三套栈**共享**重的基础设施（MySQL、图库、Milvus、Redis、S3、m3e），只各自部署轻的应用层（api / worker / web + 专属 temporal）。
- 状态隔离手段：独立卷（`workflow-state-dev2` 等）、独立任务队列（`tech-kg-workflows-gray`）、独立控制面库（`techkg_control_gray`）。
- overlay 文件（不定义容器，只覆盖 env）：`deploy-role-auth.yml` 钉死前端认证开启；`deploy-business-rbac.yml` 开启业务数据权限。
- `backend/docker-compose.yml` 是遗留的本地开发 compose（MinIO 版），当前架构已用 rustfs 替代，实际部署不用。

## 调用关系总览

```
浏览器 → web(nginx) → api ──→ MySQL（业务数据）
                      │   ──→ trs-graph → NebulaGraph（图谱）
                      │   ──→ Milvus ←── m3e-embedding（向量化）
                      │   ──→ rustfs（脚本/大文件）
                      └─ 任务 → temporal → worker → 沙箱跑用户脚本
                                         └→ redis（登录态）
```

## 常用操作速查

```bash
# dev2 栈发布（含 overlay 时按 deploy-business-rbac.yml 头部注释的完整链）
docker compose -f docker-compose.dev2.yml up -d --build

# 后端测试必须在容器里跑（宿主机没有任何基础设施）
docker exec -w /app tech-kg-api-dev2 .venv/bin/python -m pytest tests -m "not external" -q

# Temporal UI：http://<host>:8233
# RustFS 控制台：http://<host>:9021
```
