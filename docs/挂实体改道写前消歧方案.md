# 挂实体改道写前消歧方案（T_DIRECT 退役，v2）

日期：2026-09-17 · 分支：`feat/unify-prewrite-disambiguation`

## 1. 背景与决策

抽取脚本工作流原本四个输出键：`entities`/`edges`（写图）、`failures`（→ T_EXTRACT_FAIL 重跑）、
`pendingReview`（→ T_DIRECT 直接写图审核）。全平台 44 个脚本中只有两个专利关系脚本产出
`pendingReview`（`invented_by_relation.py` / `applied_by_relation.py`），语义是「这条边建不建拿不准」。

问题：歧义的本质不是边，而是**端点实体是谁**。停在边层面（T_DIRECT）会丢掉结构性信息——
同一发明人在 N 件专利里被反复挂起，N 条 case 互不相关；且 T_DIRECT 与消歧 v2（T_LINK）两套
人裁语义并存。

决策（2026-09-17）：**改道挂实体**。脚本把拿不准的端点实体按归一名生成确定性 vid 挂起，
边照常输出指向该 vid；平台对挂起实体做同名召回+评分建 T_LINK（与消歧 v2 同一套人裁）。
平台的两个分岔保持不变：**失败等待重跑 / 进消歧**，不再产生新 T_DIRECT。

## 2. 机制

### 2.1 脚本侧（两个专利脚本）

- `patent_matching.pending_entity_vid(prefix, name)`：`pending-{person|org}-{sha256(normalize_name)[:12]}`
  ——同名（NFKC + casefold + 清洗后相同）恒同 vid，N 件专利的同一发明人归并到**同一个** T_LINK case。
- 歧义分支不再产出 `ReviewRecord`（关系级挂起），改产出 `PendingEntity`（实体级挂起） +
  一条指向挂起 vid 的边（`resolution_status=pending_review`、`match_method=manual_pending`），
  经 `pending_entity_items()` 转成 `pendingReview` **实体项**。
- 覆盖三类歧义：发明人同名多候选 / 只有姓名证据 / 人才表未找到（invented_by）；
  机构名命中多个 / 疑似个人只有姓名（applied_by，机构挂 Organization、个人挂 Person）。
- stats 键 `*:pending_entity` 替代 `*:review`。

### 2.2 平台侧（`_enqueue_pending_review`）

- **实体项**：图库同名召回（`entity_disambiguation.recall_same_name`，与
  `resolve_entity_batch` 共用，DESCRIBE 探测名字列 + properties 降级）→ `score_candidate` 评分
  → 建 T_LINK case，快照与消歧 v2 灰区分支同构（`newIds`/`existingCandidates` top-5/
  `_incoming`/`_pendingRelations`/`_graphSpace`/`_resolution.policyVersion=script-pending-gray-v1`）。
- **强制灰区**：不走 `decide()` 的 auto-merge——挂起实体的边端点悬在未决 vid 上，自动并入
  已有实体会让边永远挂在无人裁决的 vid（`park_or_rewrite_edges` 只认 case.object_id）。
  分数再高也等人裁。
- **关系项**：已废弃，丢弃并告警（两个脚本已改挂实体，不再产出）。
- 幂等：`objectId`（确定性 vid）+ 稳定 candidate（只含 `{name, props:{name}}`，行级 id 在
  item 层不进快照）→ dedupe_key 稳定，重跑不重建 case。

### 2.3 落图闭环（复用既有 T_LINK 执行器，零改动）

1. `write_records`（关系）→ `park_or_rewrite_edges`：端点命中 OPEN T_LINK case.object_id 的边
   暂存进 case 快照（不写图，不产生悬挂点）；
2. 人工裁决 merge → 挂起实体属性并入目标 vid + 暂存边端点改写后补写；
   create → 实体落在挂起 vid + 暂存边原样补写；reject → 实体不落，边丢弃；
3. 前端（ManualReviewWorkspaceView）：空候选的 T_LINK（「人才表未找到」类）降级为
   create/reject 两键（merge 无目标可选，禁用），提示文案明确「新实体落图 / 驳回丢弃暂存边」。

## 3. 改动清单

| 前端 | `ManualReviewWorkspaceView.vue` | T_LINK 空候选降级 create/reject 两键 |
| 测试 | `tests/unit/test_pending_entity_reroute.py` | 确定性 vid / 项形状 / 强制灰区建案 / 空候选 / 幂等 / 关系项丢弃 / 失败不阻塞 |

## 4. 兼容性

- 存量 OPEN 的 T_DIRECT case 不受影响（direct_decide 保留，处理完即清零）；
- `pending_review_items`/`ReviewRecord` 保留（旧 ETL `load_patent_relations.py` 与既有测试在用）；
- 消歧 v2 主链（`resolve_entity_batch`）行为不变，仅召回代码位置移动。
