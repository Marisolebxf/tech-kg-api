### 0.2 选表预检（决定批跑规模与灰案量）

在 gkx_element 上执行（以 dwd_org_base_info 为例）：
```sql
SELECT COUNT(*), COUNT(DISTINCT org_id) FROM dwd_org_base_info;          -- 行数 / 主键唯一性
SELECT COUNT(*) FROM (SELECT name_cn FROM dwd_org_base_info GROUP BY name_cn HAVING COUNT(*)>1) t;  -- 重名组数
SELECT COUNT(*) FROM dwd_org_base_info WHERE name_cn IS NULL OR TRIM(name_cn)='';                   -- 空名行(会变 T_EXTRACT_FAIL 案)
SELECT MAX(updated_time) FROM dwd_org_base_info;                          -- 时间列高水位
```
- 主键唯一 + 无重名 + 无空名 → 全自动入库，**零灰案零失败案**（首选这种表做干净验证）。
- 有重名 → 同名实体对齐落灰区，产生 T_LINK 人工审核案（要验证审核链路时刻意选这种）。
- 注意 dwd 系列时间列多为 `updated_time`（不是 update_time），绑定来源表时别选错。

## 1. 新建图空间

**页面操作**：左侧导航「配置管理」→「图数据空间」→ 新建：名称（仅字母/数字/下划线、字母或下划线开头、≤64 字符，如 `dev2batch1015`）+ 说明 → 创建。

**平台在做什么**：校验名称模式 → Nebula `SHOW SPACES` 查重 → 业务归属策略先落库（RBAC）→ Nebula `CREATE SPACE (vid_type=FIXED_STRING(256), partition_num=100, replica_factor=1)` → 轮询等 schema 传播可见 → Milvus 自动建同名向量库并登记映射 → 作废 30s 空间列表缓存。

**预期与检查点**：
- 状态 ready，无"向量库创建失败"警告；
- 顶栏全局图空间选择器能切到新空间。

## 2. 新建实体 Schema

**页面操作**：切到新空间 →「Schema 管理」→ 新建实体：
- 标识 key：小写字母开头，仅小写/数字/`-`/`_`（如 `enterprise-1015`）；
- 英文名（nGQL TAG 名）：PascalCase（如 `Enterprise`）；中文名：如「企业」；
- 属性：至少 1 个；主名列必须建（如 `name`, string, 必填），再配业务属性（province/city/industry_name/reg_status/registered_capital 等）。

**平台在做什么**：目录落 `kg_schema_definition`/`kg_schema_property` → 生成 DDL 并在**目标空间**执行：`CREATE TAG`（自动注入 NOT NULL 的 id/name/create_time/update_time/source_table 审计列 + vid/source_* 等溯源列）+ `CREATE TAG INDEX` + `REBUILD INDEX`。

**预期与检查点**：
- DDL 状态 succeeded（**新空间刚建完 DDL 可能自动重试 2~3 次才过**——索引传播延迟，等待即可，不算缺陷）；
- 属性列表出现系统注入的必填列与溯源列，属正常。

## 3. 绑定来源表

**页面操作**：Schema 详情 →「来源表」→ 添加：
- 数据源：`dev2-default`（MYSQL-430EAF90）；库 `gkx_element`；表 `dwd_org_base_info`；
- 主键列 `org_id`；时间列 `updated_time`；
- （可选）查询 SQL：需要筛数据时填，**必须暴露主键列与时间列**，走水位/keyset 读取。

**平台在做什么**：`kg_schema_source` 落库；实体/关系可绑多表，**每表独立水位**。后续抽取按绑定分批读源：querySql 绑定走水位/keyset 游标，裸表走 LIMIT/OFFSET。

**预期与检查点**：保存成功，来源列表显示该表；无"表不存在/列不存在"报错。

## 4. 上传抽取脚本

**页面操作**：Schema 详情 →「脚本」→ 上传 `.py` 文件 → 等待 LLM 安全校验（SSE 进度）完成并保存。

**脚本契约**（唯一入口声明，单步即可）：
```python
"""Enterprise(企业)抽取:gkx_element.dwd_org_base_info 行 → 企业实体(vid=org_id)。"""
from kg_sdk import step


@step
def extract(payload):
    entities, failures = [], []
    for row in payload.get("rows") or []:
        rid = str(row.get("org_id") or "")
        try:
            name = (row.get("name_cn") or "").strip()
            if not name:
                raise ValueError("缺少必需名称字段 name_cn")
            entities.append({
                "id": rid,                      # vid = 记录主键
                "props": {
                    "name": name,               # 主名列，必给非空
                    "province": row.get("province") or "",
                    "city": row.get("city") or "",
                    "industry_name": row.get("industry_l1_name") or "",
                    "reg_status": row.get("reg_status") or "",
                    "registered_capital": str(row.get("registered_capital_value") or ""),
                },
            })
        except Exception as exc:
            failures.append({"recordId": rid, "error": f"{type(exc).__name__}: {exc}"[:1000]})
    return {"entities": entities, "failures": failures}
```
要点：`from kg_sdk import step` + `@step` 装饰顶层函数（步顺序=函数源码出现顺序）；输入 `payload["rows"]`，输出 **只** 含 `entities`/`failures`；**脚本绝不直接写图**——写图由平台用 nGQL `INSERT VERTEX` 列级幂等 upsert 完成；空值属性列会被跳过不写。

**平台在做什么**：语法 + 入口静态检查（纯 AST 解析）→ LLM 安全校验 → 脚本本体存 RustFS S3（bucket `tech-kg-schema-scripts`）→ `kg_schema_script` 登记 sha256/版本/函数名。

**预期与检查点**：脚本状态"可用/needsRun"；校验若报"模型不可用/ModelSelectionDenied" → 坑 B，给 Schema 配上 `LLM-8E37FDC1` 再传。

## 5. 新建图谱构建任务

**页面操作**：「图谱构建/任务中心」→ 新建任务：
- 类型 `extract`（单脚本抽取）；选刚才的 Schema；
- 批大小：500（1~5000，真实表建议 500）；
- 调度：一次性（once）；
- **LLM 配置：手动选 `LLM-8E37FDC1`**（不要用默认！坑 B）；
- 数据源/库：dev2-default / gkx_element；图空间：新空间。

**平台在做什么**：预检（Schema 已传脚本 + 已绑来源 + S3 对象真实存在，缺一即拒绝建任务）→ 生成 `schema-extract-{schemaId}` workflow 定义 → `workflow_jobs` 落库（启用态）。

**预期与检查点**：任务出现在任务中心列表，状态"启用"，尚未有执行历史。

## 6. 触发与监控

**页面操作**：任务行点「运行/触发」→ 打开任务详情 → 执行历史看状态流转（RUNNING → COMPLETED / FAILED），详情抽屉里看各批转换步、失败原因、溯源。

**平台在做什么**（Temporal 全链路，队列 `tech-kg-workflows`，dev2 worker）：
1. 读源：按来源绑定分批读（水位/keyset 或 LIMIT/OFFSET），批载荷走 S3 中转（dev2 默认开）；
2. 转换：**脚本在隔离沙箱容器（script-runner）里执行**（坑 A 的接线就是给它用的）；
3. 消歧：同名实体对齐（0.6 名 + 0.4 属性打分；灰区落 T_LINK 审核案扣留写图）；
4. 写图：nGQL `INSERT VERTEX` 列级 upsert（幂等，重跑不重复不覆盖已有值）；
5. 失败行：转 T_EXTRACT_FAIL 审核案（人工审核页可一键重跑）；
6. 环末：增量索引 upsert（新空间首跑必跳过，见第 8 节）+ 水位推进。

**预期与检查点**：
- 终态 COMPLETED；1674 行/batch 500 ≈ 4 批，实测 ~75 秒；
- 若 FAILED 且原因含"隔离脚本运行器未配置" → 坑 A 未修；
- 若 FAILED 且原因含 ModelSelectionDenied/模型 → LLM 选了默认废配置 → 编辑任务改 LLM-8E37FDC1 重触发。

## 7. 数据验收（三层断言）

**① 图库计数对齐**（graph-console 或 api 容器，注意 TRS 语法用 `id(vertex)` 不能用 `id($$.Tag)`）：
```ngql
USE dev2batch1015;
LOOKUP ON Enterprise YIELD id(vertex) | YIELD COUNT(*) AS n;   -- 应 = 源表行数 1674
```

**② 抽样属性比对**：取源表某 org_id →
```ngql
FETCH PROP ON Enterprise "<org_id>" YIELD properties(vertex) AS p;
```
name/province/city 等应与源行一致；`source_table` 应为 `gkx_element.dwd_org_base_info`；create_time/update_time 已自动注入。

**③ 台账核对**：
- 水位（业务库 gkx_element）：`SELECT definition_id, step_id, watermark FROM kg_script_watermark WHERE definition_id='schema-extract-{schemaId}';` —— step_id 形如 `source:{来源绑定id}`，watermark ≈ 源表时间列最大值；
- 审核队列：`SELECT COUNT(*) FROM manual_review_case WHERE graph_space='dev2batch1015';` —— 选了无重名表应为 0；有 T_LINK/T_EXTRACT_FAIL 案则去人工审核页核对并处置（裁决 merge/create 真实写图）；
- 任务中心执行历史：COMPLETED + 批次明细可见。

## 8. 实体索引引导 + 检索冒烟（新空间必做，否则检索永远空）

**为什么**：增量索引 upsert（②a 方案）需要既有索引基座；全新空间首环必返回 `{"mode":"skip","reason":"space index not built"}`（任务详情索引环节可见，属**计划内跳过**，不是失败）。需要做一次全量重建建基座。

**8.1 触发方式**（⚠️ 前端目前**没有**重建按钮——平台工作台上的"全量重建"是演示桩，别用。走管理 API）：
在**已登录**的浏览器页面开开发者控制台（F12 → Console），在平台页面域名下执行：
```js
fetch('/api/v1/entity-search/reindex', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({space: 'dev2batch1015'})
}).then(r => r.json()).then(console.log)
```
预期返回 `entityCount: 1674`，`typeCounts: {"Enterprise": 1674}`，embedding 模型 moka-ai/m3e-small（1674 实体实测 ~19 秒）。同一时间只允许一个重建在跑（并发会报"索引重建正在进行中"）。

**平台在做什么**：全空间 图 → m3e embedding + BM25 词表 → Milvus `kg_entity` 集合（按 graph_space 字段隔离）+ `kg_entity_search_state` 落 BM25 统计。

**8.2 检索冒烟**：平台「实体列表/实体检索」页，图空间切到新空间，搜「深圳」→ 应命中（如"深圳大学"等），混合检索（向量+BM25）生效。

## 9. 常见故障速查表

| 症状 | 根因 | 处置 |
|---|---|---|
| 任务 FAILED："隔离脚本运行器未配置" | worker 缺 `SCRIPT_RUNNER_URL`（坑 A） | 按 0.1 三文件 compose 重建 worker 后重新触发 |
| 任务 FAILED：ModelSelectionDenied / 模型不可用 | 用了 is_default=1 且无 key 的 LLM-DDDE9DC5（坑 B） | 任务/Schema 改选 LLM-8E37FDC1；或管理员把有效配置设为默认 |
| 任务 COMPLETED 但实体检索为空 | 新空间无索引基座，首环计划内跳过 | 第 8 节 reindex 一次 |
| 新建 Schema 卡几秒 / DDL 重试 | 新空间 schema 传播延迟，服务端自动重试 | 等待即可，最终 succeeded 即正常 |
| worker 日志"同名写锁获取降级为无锁" | worker 无 Redis env，既定降级路径 | 无需处理（不影响正确性） |
| 抽取出现失败行 | 源行缺必填字段（如空名） | 走人工审核 T_EXTRACT_FAIL 案 → 页面上重跑 |
| 建任务被拒"须已传脚本且绑定来源" | 预检未过 | 回第 3/4 节补齐再建 |
| 图查询 `id($$.Tag)` 语法错 | TRS 定制 Nebula 语法差异 | 用 `YIELD id(vertex)` / `properties(vertex)` |
