## 附：00921/00929 排查记录（2026-09-19，yunfei3 栈实测）

在 yunfei3 栈（api 8004、控制库 techkg_control_yunfei3、worker 队列 tech-kg-workflows-yunfei3）建周期任务实测（`48 20 * * *` 与 `*/4 * * * *`，Asia/Shanghai，runNow=false）：

- **机制全链路正常，无法复现**：Schedule 注册（TEMPORAL_CREATED、未暂停、calendar 东八区正确）→ 到点真实触发 → 每次触发一条执行记录（trigger=SCHEDULE，前端「定期触发」）→ 任务列表最近执行如实刷新；连续两周期（20:48/20:52）各自独立执行、全部 COMPLETED；删任务连带删 Schedule。
- **workflow id 冲突疑点排除**：代码里 ScheduleActionStartWorkflow 的 id 虽是静态串，但 Temporal 服务端对 schedule 触发自动追加触发时间戳（`…-sched-workflow-2026-09-19T12:52:00Z`），连续触发不撞 id。
- **报障最可能原因**：①「首次执行时间」语义坑——`每天 02:00 → 0 2 * * *`，下午建任务选 02:00 则今天已过、首次触发在**明天** 02:00，弹窗文案「首次执行时间即第一次触发」过度承诺（改进方向：预览直接算出下次具体触发时间）；②测试环境不明（信息包环境栏【待填】，两个栈控制库均无测试当天的周期任务记录）。
- **遗留隐患（未修）**：Schedule overlap_policy 默认 SKIP——上一轮抽取还在跑时到点触发被静默跳过（不报错、不留执行记录），大表抽取耗时超过周期间隔时会出现真·到点没触发。
