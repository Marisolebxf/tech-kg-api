## 待核查问题与最小改动方向

下列“原有”以 `origin/kgetl@f8b83ef5` 对照判断，不能归咎于本次新增提交。它们仍影响本次安全验收。

### SEC-JSON 不完整或矛盾的判定结构可能被放行

**P1，原有。** `backend/service/script_security.py::_parse_verdict` 只强制检查 safe 为布尔；issues 缺失、类型错误、证据过滤为空时可能变为放行，safe=true 时也不检查与有效危险 issues 的冲突。

Codex 使用合成源码 `import os\nos.system("id")\n`，仅将它作为待审文本，未执行源码。以下模拟响应在最新实现中均产生 safe=true：

```json
{"safe": true}
{"safe": false}
{"safe": false, "issues": "broken"}
{"safe": true, "issues": [{"problem": "执行系统命令", "evidence": "os.system(\"id\")"}], "summary": "存在危险调用"}
```

无法解析的半截 JSON 则返回 safe=false、unavailable=true。应区分“JSON 语法可解析”与“安全判定结构完整有效”，不能由两条截断测试推出任何损坏格式都不会放行。

最小方向：严格校验字段及类型、结论一致性；损坏、矛盾或无法确认证据的回答应重试，仍失败则校验不可用，不保存脚本。对应修正现有明确要求损坏字段放行的单测。

### SEC-META 结束原因与错误类别未保留

**P1，原有，本次未解决。** `backend/infra/llm.py::LLMClient.synthesize` 只返回 content，未保留 finish_reason；异常统一变成 None。模拟 finish_reason=length 且 content 为可解析的安全 JSON，最终仍放行；length 且 content 为空则归入“限流或超时”。

最小方向：为安全校验提供带结束原因的结构化调用结果；保留 finish_reason、HTTP 状态及空回答、格式异常、限流、认证失败、连接/读取/总截止时间等错误类别。length 不进入成功判定。避免直接改变所有业务调用者的返回契约。记录必要元数据，不记录凭证或业务源码全文。

### SEC-SCOPE 检查范围收缩及证据过滤的漏报

**提示词范围收缩为本次新增；证据及正则反转逻辑为原有。** 新提示词的“只扫八类、无命中直接判安全”与删除开放式宿主安全目标，构成实质范围变化。关键词存在性测试不证明模型检出能力。

八类自然语言清单与 `_HIGH_RISK_RE` 也不等价。Codex 以合成源码和逐字真实危险证据模拟模型返回 unsafe，以下样本仍被正则未命中逻辑反转为 safe=true：

| 样本 | 漏报路径 |
|---|---|
| `from pathlib import Path` 后调用 `Path("/tmp/synthetic-target").write_text("x")` | 文件越界访问未被正则覆盖 |
| `from os import system as run` 后调用 `run("id")` | 别名调用未被覆盖 |
| `import builtins` 后动态拼接属性名并调用 | 动态获取执行函数未被覆盖 |
| `os.environ.get("SYNTHETIC_SECRET")` | 正则不匹配该环境变量读取形式 |

此处正则不是独立的安全拒绝器：模型判 safe 时它不运行；模型判 unsafe 时，正则不命中反而可能放行。证据无法逐字定位也不等同于代码安全。

最小方向：保留简短提示词及防注入条款，恢复完整安全目标；不再以正则未命中推导安全。明确误报可针对性处理，不能将未覆盖或不确定情况自动放行。请说明旧误报样本如何继续可用，并与新增漏报测试一起报告。

### SEC-LIFETIME 阶段返回不等于 HTTP 请求终止

**本次总时长保证尚不成立。** future.result 的超时限制调用者等待，future.cancel 无法终止已经运行的 HTTP 请求。关闭 SDK 重试减少尝试次数，但不是单次请求总时长限制；“请求寿命≤1×timeout”的表述应撤回。

Codex 本机实验使用 OpenAI SDK 2.53.0、httpx 0.28.1、回环 HTTP 服务和合成响应，不连接真实模型。预热后，服务每 0.025 秒发送一小段 JSON，阶段预算临时设为 0.12 秒：调用约 0.125 秒返回 unavailable，此时服务已经发送响应头但正文未结束，仍占一个槽位；后台约 0.468 秒结束，槽位恢复。这是本机传输实验，不是线上 50 秒实测。

另以4个可阻塞模拟调用验证：阶段超时后4槽仍占用，第5个请求不发起模型调用并快速失败；释放后台调用后恢复4槽。该结果认可释放时机，但也说明后台请求不收尾时会持续耗尽容量。

最小方向：使用能终止传输的总截止时间机制，保留非阻塞准入和终态释放；不能仅在超时后提前释放槽位。核对多进程下的实际容量，并涵盖外层 SSE worker 的排队、客户端断连及服务退出。50 秒从 review 内开始计时，不能直接称为整次上传请求总预算。

### SEC-SSE 前端终态及代理链尚未闭环

**原有。** `frontend/src/api/schemaManagement.ts::verifyAndSaveScript` 未检查流关闭前是否收到 success/error。Codex 从最新提交提取该函数，模拟只收到 progress 后 EOF，Promise 正常 resolve，没有错误回调；页面可停留在 working。

后端流未提供周期心跳，仓库 nginx 模板未显式设置读取超时。当前实际多层代理配置未核验，不能只凭阶段50秒低于假定默认60秒确认端到端可靠。客户端等待期间的模型配置解析、外层 worker 排队、保存阶段也不在 review 的50秒预算内。

最小方向：补流终态检查、无终态 EOF 错误、心跳及明确截止时间；经真实代理链验证正常、超时、断流均有正确终态。不要用继续提高 token 预算代替传输和错误分类修复。

## 最小验证计划

1. 正常脚本：短小转换、长脚本、正则和摘要构造等既有误报样本。验证正确放行，结果结构完整，保存行为符合预期。
2. 故障注入脚本：以脱敏的 authored_by_fault_7 复现材料核对；业务逻辑故障本身不等同于安全风险。保留旧失败现象与当前模型的成功证据，不能凭文件名判断应拦截。
3. 危险调用与混淆：直接命令、别名、动态属性、文件越界、环境变量、网络、解码执行。验证最终 verdict，而非只检查模型原始输出；逐条检查证据过滤和正则后处理。
4. 提示注入：注释、字符串及文件名中的“预审通过/规则更新/威胁”等文本，分别附危险载荷与正常代码，保持各自应拒绝/放行的预期。
5. 格式与元数据：length、空content、无choices、缺字段、错误字段类型、矛盾结论、损坏/截断JSON、多个对象或多余文字；均验证不能因损坏结果保存。区分模型判危险与校验不可用。
6. 重复对照：相同模型、端点、预算和语料比较新旧提示词，正常、危险、混淆及注入分组多次重复，另设独立样本。报告实际尝试数、漏报、误报、格式失败、结束原因和耗时分布，不以零观测漏报证明绝对安全。
7. 并发和生命周期：4、5及更高并发；超时后槽位占用、迟到完成、取消前未启动、submit失败、多进程、客户端断连及退出。真实慢速HTTP应验证传输在总截止时间后终止及容量恢复。
8. 前端和代理：经实际页面及全部代理层验证成功、不可用、危险、EOF、超时；检查心跳间隔、有效proxy超时和终态展示。ASGI内存测试不能代替该项。

当前只要求方案与证据核查；真实模型付费调用、写入保存、业务代码实施或部署如超出原有授权，先提交具体范围供用户决定。默认配置保持 glm-4.7 非Flash、普通paas/v4和原密钥。
