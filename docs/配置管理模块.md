# 配置管理模块（代码结构 / 表结构 / 功能说明）

> 前端路由 `/configurations`（`meta.admin: true`，仅平台管理员可见）。
> 后端五个 router 全部注册在 **admin 路由组**（`require_authenticated_user` + `require_platform_admin`，见 `backend/biz/router/register.py:96-108`）。

## 一、功能描述

配置管理页是平台的**外部资源连接配置中心**，管理 5 个分类：

| 分类 | kind | 管理对象 | 持久化 |
|---|---|---|---|
| 语言模型 | `llm` | OpenAI 兼容 LLM 连接（base_url / model / api_key） | `platform_llm_config` |
| 向量模型 | `embedding` | embedding 模型连接（多一个 dimensions 维度） | `platform_embedding_config` |
| MySQL 数据源 | `mysql` | 关系库连接（host/port/库/账号密码） | `platform_mysql_datasource` |
| 向量数据空间 | `milvus` | Milvus 向量库连接（uri 为空回退 env `MILVUS_*`） | `platform_milvus_config` |
| 图数据空间 | — | NebulaGraph 图空间绑定关系 | `kg_user_graph_space` + trs-graph |

核心交互功能：

- **首屏并行加载**：四类配置用 `Promise.allSettled` 一次拉齐（让左侧分类计数固定展示），图空间单独拉取；切换分类不重拉，仅首拉失败时补拉；增删改后的刷新由各 mutation 内的 `loadByCategory` 覆盖。
- **列表**：关键词搜索（名称/id/类型/地址/模型）+ 状态筛选（正常/异常/停用）。
- **新建弹窗**：LLM/embedding 强制**"验证通过才能保存"**——用弹窗里的原始参数真实探活（`POST /verify`），任何字段改动会使已验证状态失效需重验（`watch(form, deep)` 重置 `verified`）；mysql/milvus 无此门槛。
- **详情抽屉**：编辑保存、**测试连接**（后端真实探活，成功置"正常"/失败置"异常"）、设为默认、停用/启用、删除。
- **凭据安全**：api_key/password/token 明文入库但**响应只回脱敏掩码**（`••••••••` + 末 4 位）+ `hasXxx` 布尔；更新时留空保留原值。
- **图数据空间**：新建会**真实执行 Nebula `CREATE SPACE`**（`vid_type=FIXED_STRING(64)`，partition/replica 可由 `GRAPH_SPACE_PARTITION_NUM` / `GRAPH_SPACE_REPLICA_FACTOR` 覆盖，默认 100/3），并轮询 `SHOW SPACES` 等传播（0.5s × 20 次 = 最多 10s）后自动绑定；管理员可绑定已有空间；解绑只删绑定行，**绝不 DROP 空间**。普通用户只能看到默认业务空间 + 自己绑定的空间。

## 三、表结构（5 张表）

四张配置表结构同构，差异只在连接字段。通用列：`id VARCHAR(64) PK`、`name VARCHAR(128)`、`description VARCHAR(500)`、`owner VARCHAR(128)`、`is_default BOOL`（全局唯一默认，service 层 `clear_other_defaults` 保证）、`status VARCHAR(32)`（中文枚举：正常/停用/异常）、`created_at/updated_at DATETIME`，索引 `(is_default, status)`。

**`platform_llm_config`**（id 形如 `LLM-XXXXXXXX`）

| 列 | 类型 | 说明 |
|---|---|---|
| base_url | VARCHAR(256) | OpenAI 兼容入口 |
| api_key | VARCHAR(256) | 明文存储，响应脱敏 |
| model | VARCHAR(128) | 模型名 |

**`platform_embedding_config`** — 同 LLM，多一列 `dimensions INT NULL`（向量维度）。

**`platform_mysql_datasource`**

| 列 | 类型 | 说明 |
|---|---|---|
| host | VARCHAR(256) | |
| port | INT | default 3306 |
| default_database | VARCHAR(128) | |
| username / password | VARCHAR(128) / VARCHAR(256) | 密码明文存储，响应脱敏 |

**`platform_milvus_config`**

| 列 | 类型 | 说明 |
|---|---|---|
| uri | VARCHAR(256) | 空 = 回退 env `MILVUS_*` |
| token | VARCHAR(256) | 响应脱敏 |
| default_db | VARCHAR(128) | default 'default' |

**`kg_user_graph_space`**（`db_model/platform_governance.py:65`，用户↔图空间绑定关系；空间本体在 NebulaGraph 侧）

| 列 | 类型 | 说明 |
|---|---|---|
| id | VARCHAR(36) PK | UUID |
| user_id | VARCHAR(128) | 索引 `idx_kg_user_graph_space_user` |
| space_name | VARCHAR(128) | |
| created_at | DATETIME | server_default=now() |

约束：`UNIQUE(user_id, space_name)`

## 四、关键机制

- **owner 隔离**：列表按 owner 过滤（管理员全量、普通用户仅自己，`resource_owner_filter`）；单条操作校验 `ensure_owner_access`，越权 403。列表因此**不走共享结果缓存**——缓存键不含用户身份，共享缓存会串数据。
- **默认配置全局唯一**：设默认/建默认时 `clear_other_defaults` 清掉同 owner 其它行；四张表同套路。删除默认配置只告警不阻止，删除后回退 env。
- **LLM 配置与全局 LLM 客户端联动**：增删改/设默认后 `reset_llm_client()` 使进程单例失效；`resolve_llm_settings()` DB 默认配置优先，**DB 配置缺 api_key 或无记录时回退 env**（`LLM_API_KEY`/`ZHIPUAI_API_KEY`，避免空配置屏蔽可用 env key）；另有 `get_llm_client_by_id()` / `get_llm_settings_by_id()` 供作业 activity 按指定配置临时构造客户端。
- **测试/验证都是真实探活**，返回 `{ok, latencyMs, error}`：
  - LLM：真发一次 `chat.completions`（max_tokens=1、`thinking: disabled`）；
  - embedding：真发一次向量请求；
  - MySQL：建临时 `MySQLClient` 做 `health_check`；
  - Milvus：建临时 pymilvus 客户端 `list_databases`。
  - `test`（已保存配置）与 `verify`（保存前用表单原始参数）是两个入口。
- **图空间创建**：走默认 env 空间的 trs-graph 客户端执行 DDL（CREATE SPACE 需已存在空间做执行上下文），创建后轮询确认再绑定；单存储节点集群可把 `GRAPH_SPACE_REPLICA_FACTOR` 调小避免 "Host not enough!"。名称校验 `^[A-Za-z_][A-Za-z0-9_]{0,63}$`。

## 五、工作时序图

### 5.1 新建模型配置（验证通过才能保存，LLM / embedding）

```mermaid
sequenceDiagram
    autonumber
    actor U as 管理员
    participant FE as 配置管理页(新建弹窗)
    participant API as FastAPI handler
    participant SVC as LlmConfigService
    participant DB as MySQL(platform_llm_config)
    participant LLM as LLM 服务(OpenAI 兼容)

    U->>FE: 填写 name/baseUrl/model/apiKey
    note over FE: 任何字段改动 → watch(form) 置 verified=false，必须重新验证
    U->>FE: 点击"验证连接"
    FE->>API: POST /llm-config/llm-configs/verify {baseUrl, model, apiKey}
    API->>SVC: verify_connection()（未落库的原始参数）
    SVC->>LLM: chat.completions(max_tokens=1, thinking disabled)
    alt 探活成功
        LLM-->>SVC: 响应
        SVC-->>FE: {ok:true, latencyMs} → verified=true，"保存"按钮解锁
    else 探活失败
        LLM-->>SVC: 异常
        SVC-->>FE: {ok:false, error} → toast 警告，仍不可保存
    end
    U->>FE: 点击"保存"
    FE->>API: POST /llm-config/llm-configs（mysql/milvus 类无验证门槛，直接到这一步）
    API->>SVC: create_config(payload)
    SVC->>DB: INSERT（id=LLM-XXXXXXXX，api_key 明文入库）
    alt is_default=true
        SVC->>DB: clear_other_defaults(owner)（同类别默认全局唯一）
    end
    SVC->>SVC: reset_llm_client()（进程级 LLM 单例失效，下次按 DB 默认重建）
    SVC-->>API: 脱敏响应（hasApiKey + apiKeyMasked，绝不回明文）
    API-->>FE: 保存成功 → loadByCategory 刷新列表
```

### 5.2 已保存配置的运维操作（测试连接 / 设默认 / 停用 / 删除）

```mermaid
sequenceDiagram
    autonumber
    actor U as 管理员
    participant FE as 配置管理页(详情抽屉)
    participant API as FastAPI handler
    participant SVC as XxxConfigService
    participant DB as MySQL(配置表)
    participant EXT as 外部目标(LLM/MySQL/Milvus/embedding)

    U->>FE: 打开详情抽屉，点击"测试连接"
    FE->>API: POST /{kind}-configs/{id}/test
    API->>SVC: test_connection(id)（先 ensure_owner_access，越权 403）
    SVC->>DB: 读配置行
    SVC->>EXT: 真实探活（chat 一次 / health_check / list_databases / embedding 一次）
    alt 探活成功
        EXT-->>SVC: ok
        SVC-->>FE: {ok, latencyMs} → 行状态置"正常"
    else 探活失败
        EXT-->>SVC: 异常
        SVC-->>FE: {ok:false, error} → 行状态置"异常"
    end
    opt 设为默认
        U->>FE: "设为默认"
        FE->>API: POST /{kind}-configs/{id}/set-default
        API->>SVC: set_default(id)
        SVC->>DB: clear_other_defaults(owner) + UPDATE is_default=true
        SVC->>SVC: reset_llm_client()（仅 LLM 类）
        SVC-->>FE: 引用情况变为"默认语言模型"
    end
    opt 编辑保存（凭据留空保留原值）
        U->>FE: 修改字段 → "保存修改"
        FE->>API: PUT /{kind}-configs/{id}
        API->>SVC: update_config(id, payload)
        note over SVC: api_key/password/token 为空字符串时保留原值
        SVC->>DB: UPDATE + updated_at
    end
    opt 停用/删除
        U->>FE: "停用" / "删除"(confirm)
        FE->>API: PUT（status=停用）或 DELETE /{kind}-configs/{id}
        SVC->>DB: UPDATE status / DELETE 行（删默认仅告警，回退 env）
    end
```

### 5.3 图数据空间：创建 → 绑定 → 解绑

```mermaid
sequenceDiagram
    autonumber
    actor U as 管理员
    participant FE as 配置管理页(图数据空间)
    participant API as graph_space handler
    participant SVC as GraphSpaceService
    participant DB as MySQL(kg_user_graph_space)
    participant TG as trs-graph(默认空间客户端)
    participant NG as NebulaGraph

    U->>FE: "新建图数据空间"（名称须匹配 ^[A-Za-z_][A-Za-z0-9_]{0,63}$）
    FE->>API: POST /graph-spaces {name}
    API->>SVC: create_space(actor, name)
    SVC->>TG: list_spaces()（校验图服务可用 + 名称不存在）
    TG->>NG: SHOW SPACES
    SVC->>TG: execute_write(CREATE SPACE IF NOT EXISTS `name`<br/>vid_type=FIXED_STRING(64), partition_num, replica_factor)
    loop 等待 schema 传播（最多 20 次 × 0.5s = 10s）
        SVC->>TG: list_spaces() 轮询确认
    end
    SVC->>DB: INSERT kg_user_graph_space(user_id, space_name)
    SVC-->>FE: 已创建并绑定（提示：秒级传播延迟后可在任务触发时选择）
    opt 管理员绑定已有空间
        U->>FE: 从 bindableSpaces 下拉选择 → "绑定"
        FE->>API: POST /graph-spaces/{name}/bind
        API->>SVC: bind(actor, name)
        SVC->>TG: list_spaces()（校验存在，不存在 400）
        SVC->>DB: INSERT 绑定行（幂等：已绑定则跳过）
        SVC-->>FE: 已绑定
    end
    opt 解除绑定
        U->>FE: "解除绑定"（confirm：仅解除关联）
        FE->>API: DELETE /graph-spaces/{name}
        API->>SVC: unbind(actor, name)
        SVC->>DB: DELETE 绑定行
        note over SVC,NG: 只删绑定行，绝不 DROP 空间，图数据保留
        SVC-->>FE: 已解除绑定
    end
```
