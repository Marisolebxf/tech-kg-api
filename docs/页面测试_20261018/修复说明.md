**修复**（`service/temporal_workflows.py`，`write_records` 实体路径）：

- 写前合并 `_merge_entity_rows`（守卫锁临界区内）：
  - 批内同 VID 多条按出现序累积（同列后者覆盖，先出现的列保留）；
  - `FETCH PROP ON` 批量读图上旧值，记录**未携带的列保留图上值**；
  - `create_time`/`update_time` 不从图上保留（仍由平台每次写入兜底刷新）；

# 二轮（Codex 评审后）：P1 并发丢列 + P2 静默覆盖

Codex 对 4a64ce40 的技术评审（见《GLM-Codex协作对话》17:46 条）确认两个残余缺口，处置见《修复合并部署评估》。实现落在 **fix/entity-write-merge-props-1018 @ a9fe42a8**（4a64ce40 之上），按双方在对话文件议定的规格。

## P1：per-VID fail-closed 写锁（并发同 VID 丢列）

**缺口**：#2 的合并只解决**顺序**多来源写；并发入口真实存在——`SchemaExtractWorkflow` 来源间 `asyncio.gather` 并行 + 来源内 N worker。同名微锁按显示名（name/name_cn/name_en/name_zh）加键，**无名记录不进锁、异名同 VID 不互斥**，且获取失败 fail-open 降级无锁。整标签覆盖语义下并发子集写互相清列。

**修复**（`service/entity_write_guard.py::vid_write_locks` + `temporal_workflows.py` 接线）：

- 键 `kg:entity:vid:{space}:{tag}:{md5(vid)}`：按 vid 而非显示名，无名/异名同 VID 落同一把锁；批内排序获取防交叉死锁；`SET NX PX` + Lua token 比删释放（复用同名锁机制）。
- **锁覆盖完整 FETCH → 合并 → INSERT**：FETCH 在 `_write_all` 内执行，锁包整个 `_write_all`。锁在终判**之后**按最终 records 惰性取 vids——终判会原地改写合并目标 vid（p_new→p_exist），按实际写入目标加锁才不漏。同名锁仍在外层包「终判 + INSERT」（后到者终判必须看到先到者已提交的 INSERT，汪小红双写根治不退化）。
- **fail-closed**：获取失败/等待超时 → 抛可重试错误，活动层/Temporal 整批重试（幂等），绝不降级无锁。与同名锁 fail-open 的分野：同名锁保消歧**活性**（Redis 故障不应打断抽取），VID 锁保数据**正确性**（无锁并发写 = 确定性丢列，不拿正确性换可用性）。
- **租期与所有权**：TTL/3 心跳续期（pipeline PEXPIRE，Lua 校验 token）；续期失败置丢失标记 → 写图 chunk 间熔断中止 + 临界区退出抛错，最大限度收敛不安全窗口；释放校验持有者令牌。
- **运维含义：Redis 成为实体写路径的硬依赖**（Redis 不可用时实体写图批将失败重试直至恢复）。开关：`ENTITY_WRITE_VID_LOCK_ENABLED`（默认开，`"0"` 关——仅排障用）、`ENTITY_WRITE_VID_LOCK_WAIT_SECONDS`（默认 30）、`ENTITY_WRITE_VID_LOCK_HEARTBEAT_SECONDS`（默认 TTL/3）。

## P2：损坏旧属性熔断（静默覆盖）

**缺口**：`_fetch_existing_props` 对字符串 props JSON 解析失败置 None 后跳过、非 dict 形状直接跳过——等价于「无旧值」，静默退回覆盖清列，与合并的存在意义矛盾。

**修复**：两种情形都抛 `GraphRequestError`（502，带 vid 上下文）→ `_with_watermark_retry` 非瞬态直接上抛 → 活动层重试。合并先于一切 INSERT chunk，**抛错时本批零写入**。

# 三轮（Codex 二轮复核后）：锁生命周期两个 P1

Codex 复核 a9fe42a8（《二轮修复复核_a9fe42a8.md》，29 passed / 2 failed）确认 P2 与普通同 VID 并发已修，但指出两个锁生命周期缺口。实现落在 **fix/entity-write-merge-props-1018 @ 50ca7da7**（a9fe42a8 之上，2 文件 +146/-7，只动 `temporal_workflows.py` 与锁测试文件）。

## P1-1：活动取消提前解锁 → shield + 排空（drain）

**缺口**：`asyncio.to_thread` 的协程被取消并不会停止后台同步写线程；a9fe42a8 的 shield 缺失使取消直接穿透——上下文管理器退出、停心跳、释放锁，而写线程仍在跑。竞态序列：A 暂停在 FETCH → 取消 A → B 获锁写 h_index=5 → A 线程恢复，用取消前的旧快照 INSERT，B 的列被清。

**修复**（`temporal_workflows.py::_run_write_all`）：`asyncio.shield(write_task)` 之上，捕到 `CancelledError` 后：

1. 置 `vid_lost["cancel"]` 停止派发标志（写线程内每次派发前检查，恢复后零 INSERT）；
2. **循环排空** `write_task`——排空期间再次被取消则继续等；线程以异常（含失锁熔断）或正常收尾均跳出。排空全程锁与心跳续期持有（上下文未退出），B 的写入窗口与 A 线程收尾严格互斥；
3. 重抛 `CancelledError`（取消语义对上游保持透明）。

Codex 明确要求不止 shield（shield 只保证「不把取消注入 await 点」，不保证线程收尾后再解锁），本实现即按其「取消时安全等待在途线程收尾再解锁」建议。

## P1-2：失锁后当前 chunk 内重试仍写入 → 每次派发前检查 should_abort

**缺口**：a9fe42a8 的丢失标志只在 **chunk 间**检查。批 INSERT 抛瞬态错（high watermark）进入 `_with_watermark_retry` 退避，退避期间心跳续期失败置丢失，但内部重试 attempt 仍会再次派发 INSERT——已发生的写入无法靠「临界区退出抛错」撤销。

**修复**：`_with_watermark_retry` 新增 `should_abort` 钩子，**每次 attempt 派发前**调用（含退避 sleep 之后、含最后一次派发前），命中抛 `RuntimeError` 不派发。接线覆盖全部派发面：

- 批语句重试（`_write_chunk` 主路径）；
- 未知列自愈循环（`write_with_self_heal` 内部 while）；
- 逐条回退（per-row fallback 的 `write_with_self_heal`）；
- `_write_all` chunk 间检查（原有，保留）。

`_abort_write() = vid_lost.get("lost") or vid_lost.get("cancel")`——租期丢失与活动取消共用一个熔断条件。Codex 的「重新获锁必须重新 FETCH 合并」天然满足：锁与 FETCH 都在 `_write_all` 内，整批重试即重新走加锁 + FETCH，不存在旧快照跨锁复用。

# 四轮（Codex 三轮复核后）：排空期重复取消忙等

Codex 复核 50ca7da7（《三轮修复复核_50ca7da7.md》，31 passed + 新增重复取消探针 1 failed）确认上轮两个问题已修，但指出排空循环的新缺口。实现落在 **fix/entity-write-merge-props-1018 @ a12a1c34**（50ca7da7 之上，3 文件 +205/-2）。

## P1：排空期间再次取消 → 无让出点忙等

**缺口**：50ca7da7 的排空循环裸 `await write_task`（temporal_workflows.py `_run_write_all` 取消分支）。二次外层取消经未 shield 的 await 传染给 write_task：任务被取消而底层同步线程停不下来；此后循环反复 await 已取消任务，立即抛 `CancelledError` 且**不让出事件循环**——忙等冻结，同循环的心跳续期与一切协程饿死，Redis 锁最终可能过期而僵尸线程仍在跑。Codex 以子进程 watchdog 探针取证（2 秒无恢复 → 退出码 42）。

**修复**：

- 排空循环内每次等待改为 `await asyncio.shield(write_task)`：外层重复取消只落在 shield 外壳上被吸收，write_task 不受传染、继续真实挂起（每次迭代有让出点）；
- `except CancelledError` 内区分 `write_task.cancelled()`：任务自身被取消则跳出上抛（持续 shield 下不可达的防御分支），堵死 await 已取消任务的同款忙等路径；
- 线程异常/正常收尾两条出口语义不变（取消优先上抛）。
