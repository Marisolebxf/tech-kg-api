## #1 volume 恒空（物料）

- 位置：`docs/gkx_local_1_materials/scripts/page_test/paper_entity_step.py` 的 `paper_record`（物料正本；本目录 `scripts/` 下是测试当时的快照副本，未含此修复，复测请用正本）
- 原因：Schema 声明了 `volume` 列、`dwd_zh_paper.volume` 有值，但脚本输出没有 volume 键，平台按缺失列写图。
- 修复：补 `"volume": paper_text(row.get("volume"))`。
- 生效条件：**重新上传脚本**后新建任务才带 volume；既有空间需「更换脚本 → 重跑」才回填（幂等空读不会补）。

## #2 多来源同 VID 覆盖清空（平台缺陷，重点）

**根因（图库探针实证）**：Nebula 的 `INSERT VERTEX` 对已存在顶点是**整标签覆盖**——语句未列出的列被重置成默认值。`write_records` 的注释此前假设「列级 upsert 互不覆盖」，据此让不同来源各写各的列子集，后到者把先写者的列清掉（Person：作者批只带姓名，清空了学者批的 scholar_org/paper_nums/h_index）。

**修复**（`service/temporal_workflows.py`，`write_records` 实体路径）：

- 写前合并 `_merge_entity_rows`（守卫锁临界区内）：
  - 批内同 VID 多条按出现序累积（同列后者覆盖，先出现的列保留）；
  - `FETCH PROP ON` 批量读图上旧值，记录**未携带的列保留图上值**；
  - `create_time`/`update_time` 不从图上保留（仍由平台每次写入兜底刷新）；
  - DESCRIBE 已知全列且本批覆盖齐全时跳过 FETCH（省一次往返）；
  - 图上 NULL 不进合并；关系路径语义不动。
- 多行 INSERT 批量写图、自愈、回退路径全部保持。

**验证**：新增 `tests/unit/test_write_records_merge.py` 7 例（跨批保留 / 批内并集 / 全列免 FETCH / 缺列必 FETCH / 审计列不保留 / NULL+JSON 字符串形状 / 关系路径不合并），`test_write_records_batching` 同 VID 跨列集用例改写为断言合并后单语句。一次性容器全量 pytest：**2631 passed / 22 failed**，与 origin/kgetl 纯净基线同环境对照（2624/22，失败集均为环境依赖用例）——净增 7 通过、零回归；ruff 通过。

**部署与回填**：

- 需重建 api 与 temporal-worker 镜像（共用后端镜像）后重启；
- 修复只保证**今后不再清列**：已被清空的列不会自愈——水位已高的幂等空读不触发写图，需对受影响来源新建同配置全量任务（或降低水位）重跑，让各来源按新语义把列写齐；新建空间无此债。
