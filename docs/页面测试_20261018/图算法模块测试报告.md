# 图谱查询算法模块页面测试

2026-10-18，dev2 主栈，使用可见浏览器在「综合查询 → 图算法」执行。空间：`gkx_ui_20261018_01`。本次仅运行算法、查询与记录结果，没有修改业务代码、抽取脚本或共享配置。

结论：**PageRank、Degree 的本例默认参数结果通过独立核对；Louvain 两次显示成功，但分别丢失13个顶点和返回空结果，结果完整性不通过。**

## 数据及方法

测试空间包含39个实体、37条边。三类边分别为 AUTHORED_BY 19、PUBLISHED_IN 10、BELONGS_TO_NODE 8。使用页面 nGQL 控制台读取全部边：

```ngql
MATCH (s)-[e]->(d) RETURN id(s) AS src, id(d) AS dst, type(e) AS relation LIMIT 100
```

37条边的不同端点共34个，另外5个实体不参与所选关系：两个 IndustryChain、两个无关联 IndustryNode 和 `org_O2026L006`。因此基于这些边的完整顶点结果应对照34，而非39。

独立基线与响应：[原始边](algorithm-reference-edges.json)、[校验摘要](algorithm-independent-validation.json)、[PageRank响应](algorithm-pagerank-result.json)、[Degree响应](algorithm-degree-result.json)、[Louvain混合边响应](algorithm-louvain-result.json)、[Louvain单边类型响应](algorithm-louvain-single-result.json)。响应均从页面实际触发的网络请求中读取，未通过单独接口调用代替UI提交。

## 算法结果

| 算法 | 关系选择 | 实际结果 | 验收 |
|---|---|---|---|
| PageRank | 三类关系 | succeeded，34行，38秒 | 34个VID完全覆盖；按当前结果的归一化口径独立计算，最大绝对误差约4.44e-16 |
| Degree | 三类关系 | succeeded，34行，首次28秒 | 每个VID的入度、出度、总度与原始边计数完全一致；入度和37、出度和37、总度和74 |
| Louvain | 三类关系 | succeeded，21行，53秒，truncated=false | **未通过**：13个机构/产业链节点端点未返回 |
| Louvain复现 | 仅BELONGS_TO_NODE | succeeded，0行，44秒，truncated=false | **未通过**：8条边涉及13个端点，页面却提示“算法执行成功，无返回记录” |

三类关系统一设置：无权重、encodeId=true、partitionNum=8。PageRank默认 maxIter=10、resetProb=0.15；Louvain默认 maxIter=8、internalIter=5、tol=0.5。页面主表单仅展示关系选择，未对隐藏的数值参数做修改或越界测试。

PageRank独立计算采用有向边：从每顶点初值1出发，迭代 `r_next(v)=0.15+0.85*sum(r(u)/out_degree(u))` 共10次，最终统一缩放至分数和为34。此处说明本例核对口径，不把输出值大于1误判为错误；结果分数和约34。该验证覆盖本例默认参数，不代表对所有图和参数的全面数学证明。

Louvain对社区最优性和随机编号没有固定唯一答案；但不能在没有过滤说明、truncated=false的情况下省略所选关系中的整批端点。本次未把“作业成功”当作“社区结果正确”。

## Louvain问题复现

1. 进入该测试空间的「综合查询 → 图算法 → Louvain算法」。
2. 三类关系全部选择，提交作业。
3. 成功后只返回21个论文/期刊/专家顶点，共5个社区；机构—产业链节点的13个顶点全部缺失。
4. 只保留「企业归属产业链节点（BELONGS_TO_NODE）」，再次提交。
5. 作业仍成功，但接口 `rows=[]`、`count=0`、`truncated=false`；页面显示“算法执行成功，无返回记录”。

缺失的13个顶点：`org_O2026L001`–`org_O2026L005`，`node_IC0101001`–`node_IC0101005`，`node_IC0202001`、`node_IC0202003`、`node_IC0202005`。

相同边与端点已经由 nGQL 和 Degree核实存在，不能归因于本次抽取没有产生这些数据。响应本身缺行，因此也不是前端仅展示第一页导致。需要继续只读定位算法引擎处理小连通分量、社区聚合/回溯及结果落盘/读取的环节；当前证据尚不能把责任唯一定位到某一行代码。

证据：[三类关系结果21行](algo-07-louvain-success.png)、[仅BELONGS_TO_NODE成功但0行](algo-08-louvain-single-relation.png)。
