## 发现的问题

### 1. 论文 volume 未写入

- 文档 Step 6 要求核对 `paper_P2026L001` 的 DOI/volume。
- 实际 DOI 为 `10.3724/lite.2026.001`，但查询未返回 `volume` 值。
- 仓库轻量数据 SQL 中该论文的 `volume` 是 `56`（此处比对的是仓库种子数据，未直接查询线上 MySQL 行）。
- 页面专用 `paper_entity_step.py` 的 `paper_record` 没有输出 `volume`，可解释该字段缺失。应补齐映射或调整文档验收范围；本次仅测试，未修改脚本。
- 证据：[属性查询](query-paper.png)、[定向查询](06-paper-missing-volume.png)。

### 2. 专家多来源抽取后未保留学者属性

- 文档要求 `Person.scholar_org/paper_nums/h_index` 来自 `dwd_scholar`。
- `person_A2026L001` 最终属性中有 `name_zh=张守拙`、`name_en=ZHANG Shouzhuo`，`source_table=dwd_zh_author`，但未返回上述三个学者属性。
- 仓库种子数据对应值为“中科天玑科技有限公司”、46、18。页面专用脚本的学者 mapper 输出这三个属性，作者 mapper 仅输出姓名和溯源。
- 推断：同一 VID 随后由作者来源写入时，未保留前一个学者来源的属性。写入合并行为仍需进一步定位，不能仅凭任务成功判为属性验收通过。
- 证据：[完整属性查询](query-person.png)、[定向查询](05-person-missing-properties.png)。

### 3. source_table 与文档要求的库表全名不一致

- 文档要求 `source_table` 指向 `gkx_lite.dwd_*`。
- 实际论文为 `dwd_zh_paper`，专家为 `dwd_zh_author`，均无 `gkx_lite.` 前缀。
- 脚本以拆分后的裸表名生成溯源信息；需统一脚本输出与文档口径。
- 证据同上述论文、专家属性截图。

### 4. 首次打开任务详情短暂显示无步骤，刷新后恢复

- 首跑执行历史已显示“已完成”，详情仍显示 `0/0`、“暂无流程步骤数据”、“暂无可验收结果”。
- 刷新页面后显示正确的 `9/9` 成功及处理/写入结果。属于本次观测到的状态刷新问题，未影响实际抽取。

## 给修复者的只读定位线索

以下为代码阅读结果及建议方向，未实施修复、未更改线上配置或数据。

1. 论文缺失字段：查看本目录 `scripts/paper_entity_step.py` 的 `paper_record`。它只输出 DOI、标题、年份、publication_name、source、extra_json 和溯源，没有输出 volume；因此仅在 Schema 建出该列并不能产生值。建议先补上源字段映射，并检查同一文档列出的其他论文属性是否也存在同类遗漏。
2. 专家属性：本目录 `scripts/person_entity_step.py` 的 `scholar_person` 输出 scholar_org/paper_nums/h_index，`paper_author_person` 未输出这三个字段。两个来源对同一 author/scholar ID 生成相同 VID。最终 source_table 指向作者表，学者属性缺失，建议检查跨来源同 VID 的写入、列缺省和覆盖语义。
3. 目标分支 `backend/service/temporal_workflows.py` 的 `write_records` 是平台写入入口，包含 `filtered`、`_prepared`、`_write_chunk`，实体使用 nGQL `INSERT VERTEX`。代码注释称列级更新可保留未列出的属性，但本次页面观察不能支持直接依赖该假设；应核对线上部署版本及实际图后端行为，再决定采用显式更新已有节点、读后合并或其他保留属性的方案。当前没有足够证据把问题唯一归因到某一行。
4. 溯源：本目录脚本 `_split_source` 使用 `rsplit('.', 1)[-1]` 取得裸表名，后续 `provenance` 将裸表名写入 `source_table`；目标分支 `write_records.filtered` 对 source_table 使用 `setdefault`，不会覆盖脚本已经给出的裸表名。应先统一“裸表名还是库表全名”的约定，避免修改后影响 mapper 路由。
5. 建议回归：同 VID 先写学者属性、再写作者姓名后，仍应保留机构/论文数/h 指数；新建同配置任务增量空读不会修复既有缺失字段，修复后需安排受控回填并再次核对 39 点/37 边及幂等性。
