# 自定义图谱构建流水线设计说明

## 1. 文档目的

本文档沉淀自定义图谱构建流水线（Pipeline）的产品定位、页面设计、使用方式、运行模型及后续演进方向，为产品评审、交互设计、前后端研发和测试提供统一依据。

本文档描述的页面路由为：

- 自定义图谱构建流水线：`/#/pipelines`
- 配置管理：`/#/configurations`

当前实现属于交互原型，用于验证产品结构和操作逻辑，暂不代表已经具备真实的数据处理、模型调用和任务调度能力。

## 2. 产品定位

### 2.1 核心目标

图谱构建流水线面向知识工程师、数据工程师和图谱管理员，允许用户通过组合标准算子的方式，定义原始数据如何被处理、抽取、校验并写入知识图谱。

核心数据链路如下：

```text
数据进入
  ↓
内容解析与转换
  ↓
实体、关系和事件抽取
  ↓
实体对齐与质量治理
  ↓
Schema 变更或图谱写入
  ↓
定时或手动运行
```

用户保存的不只是页面上的节点顺序，而是一份完整的图谱生产定义：

```text
Pipeline =
数据源
+ 节点及连接关系
+ 节点参数
+ Schema 约束
+ 质量规则
+ 异常处理策略
+ 调度与运行策略
```

### 2.2 Pipeline 与工作流的区别

Pipeline 和工作流都由多个节点组成，但核心对象和使用目标不同。

| 对比项 | Pipeline（数据流水线） | Workflow（业务工作流） |
| --- | --- | --- |
| 核心对象 | 数据 | 任务、人员和审批状态 |
| 主要目的 | 加工、转换、抽取和写入数据 | 协调业务处理过程 |
| 常见节点 | 清洗、转换、实体抽取、质量校验、图谱写入 | 审批、人工审核、通知、条件分支 |
| 自动化程度 | 通常高度自动化 | 经常包含人工参与 |
| 本项目示例 | 将论文或资讯转化为实体和关系 | 将低置信结果交由管理员审核 |

本功能的核心是“数据如何变成知识图谱”，因此定义为图谱构建 Pipeline。人工处理是 Pipeline 的异常治理环节之一，并不改变其数据流水线属性。

## 3. 设计原则

### 3.1 能力积木化

将复杂的图谱构建过程拆成可复用算子。用户不需要编写完整程序，只需要选择算子、确定执行顺序并配置参数。

### 3.2 编排与配置分离

中间画布负责表达“以什么顺序执行”，右侧面板负责表达“每个节点如何执行”，避免在节点卡片中堆放大量参数。

### 3.3 公共配置与流程定义分离

数据源连接、模型地址、API Key、Schema 和质量规则等公共能力由配置管理统一维护，Pipeline 仅保存对配置项的引用。

这样可以：

- 避免在多条 Pipeline 中重复维护连接信息；
- 集中管理密码和 API Key；
- 更换模型或连接地址时统一生效；
- 追踪公共配置被哪些 Pipeline 使用；
- 在删除配置前完成影响分析。

### 3.4 先验证再发布

Pipeline 在正式发布前应使用少量样例数据试运行，检查数据源连接、节点参数、Schema 匹配、抽取结果和异常数量。

### 3.5 质量治理前置

抽取结果不能无条件进入生产图谱。图谱写入前必须经过规则校验，低置信或不符合规则的数据进入隔离区或人工处理队列。

### 3.6 高风险变更可控

Schema 新增、删除和生产图谱写入属于高风险操作，需要权限控制、影响分析、审批、版本记录和回滚机制。

## 4. 页面信息架构

页面采用“顶部操作区 + 三栏工作台”的结构。

```text
┌──────────────────────────────────────────────────────────────┐
│ Pipeline 名称、状态、试运行、保存草稿、发布、运行记录          │
├──────────────┬───────────────────────────────┬───────────────┤
│              │                               │               │
│   算子库     │          流程画布             │   节点配置    │
│              │                               │   运行调度    │
│              │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

### 4.1 顶部操作区

顶部展示和操作 Pipeline 的全局信息：

- Pipeline 名称和说明；
- 当前状态：草稿或已发布；
- 查看运行记录；
- 使用样例数据试运行；
- 保存草稿；
- 发布 Pipeline。

草稿允许持续编辑，不应创建生产调度任务。发布前需要完成完整校验，发布后才根据调度策略自动运行。

### 4.2 左侧算子库

算子库是可复用能力集合，支持分类筛选、关键词搜索、点击添加和拖拽添加。

当前算子分为五类。

#### 输入类

| 算子 | 作用 |
| --- | --- |
| 数据源 | 从数据库、API、文件、对象存储或消息流读取数据 |

#### 处理类

| 算子 | 作用 |
| --- | --- |
| 文档解析 | 解析 PDF、Word、网页正文和文档元数据 |
| 摘要生成 | 从长文本中提炼与图谱构建相关的核心内容 |
| 字段转换 | 清洗、映射、合并、拆分和格式转换 |
| 条件过滤 | 按条件保留或丢弃记录 |

#### 抽取类

| 算子 | 作用 |
| --- | --- |
| 实体抽取 | 识别实体类型、名称和属性 |
| 关系抽取 | 识别实体之间的语义关系及证据 |
| 事件抽取 | 识别事件类型、参与方、时间和地点 |
| 实体对齐 | 与存量图谱召回、消歧、合并或创建实体 |

#### 图谱类

| 算子 | 作用 |
| --- | --- |
| Schema 新增 | 创建新的实体、关系或属性定义 |
| Schema 删除 | 下线现有实体、关系或属性定义 |
| 写入图谱 | 将校验通过的数据增量写入目标图谱 |

#### 控制类

| 算子 | 作用 |
| --- | --- |
| 质量校验 | 执行完整性、唯一性、证据和置信度规则 |
| 人工处理 | 将低置信或异常数据送入人工处理队列 |

### 4.3 中间流程画布

画布用于展示数据的处理顺序和节点状态。当前原型采用线性结构，例如：

```text
科技资讯实时流
  → 文档解析
  → 实体抽取
  → 关系抽取
  → 质量校验
  → 写入图谱
```

每个节点卡片展示：

- 节点名称和算子类别；
- 算子说明；
- 两项关键配置摘要；
- 节点顺序；
- 是否已经配置；
- 试运行时的等待、运行和成功状态。

当前支持以下画布操作：

- 点击或拖拽算子到画布；
- 在指定位置插入算子；
- 调整节点前后顺序；
- 删除节点；
- 点击节点打开右侧配置面板。

### 4.4 右侧节点配置面板

节点配置面板根据所选算子动态展示参数。

示例：实体抽取节点可配置：

- 抽取模型；
- 允许抽取的实体类型；
- 置信度阈值；
- Prompt；
- 输出内容和证据要求。

示例：实体对齐节点可配置：

- 目标实体索引；
- 候选召回数量；
- 自动合并阈值；
- 名称、机构和标识符的组合策略。

节点配置只影响当前 Pipeline 中的当前节点。模型服务地址、凭据等公共信息仍由配置管理维护。

### 4.5 右侧运行与调度面板

运行与调度面板用于定义 Pipeline 如何被触发和执行，包括：

- 是否启用定时任务；
- 执行频率和时间；
- 时区；
- 失败重试次数；
- 运行超时时间；
- 运行资源组；
- 失败通知方式。

示例策略：

```text
执行频率：每天
执行时间：02:30
时区：Asia/Shanghai
失败重试：2 次
运行超时：60 分钟
资源组：标准运行资源组
失败通知：平台通知 + 企业微信
```

## 5. 使用方式

### 5.1 创建 Pipeline

1. 进入“图谱构建流水线”页面。
2. 输入 Pipeline 名称和用途说明。
3. 从左侧添加数据源节点。
4. 依次添加处理、抽取、治理和图谱写入算子。
5. 调整节点顺序，形成完整数据链路。
6. 逐个点击节点并完成参数配置。
7. 设置运行和调度策略。
8. 保存草稿。
9. 使用样例数据试运行。
10. 确认结果后发布 Pipeline。

### 5.2 配置数据源节点

数据源节点是 Pipeline 的起点，至少需要定义：

- 引用的数据源配置；
- 数据表、Topic、Bucket 或 API 资源；
- 全量或增量读取方式；
- 增量水位字段；
- 每批读取数量；
- 数据源断开时的处理策略。

示例：

```text
数据源：科技资讯实时流
Topic：tech_news
读取方式：增量读取
水位字段：publish_time
```

### 5.3 配置抽取节点

抽取过程建议拆分为多个可独立配置和重跑的节点：

```text
实体抽取
  → 实体对齐
  → 关系抽取
  → 质量校验
```

拆分后的优点：

- 可以为不同阶段使用不同模型；
- 可以独立设置实体和关系置信度；
- 可以限制允许产生的 Schema 类型；
- 可以单独调整实体消歧策略；
- 节点失败后只重跑受影响阶段；
- 更容易观察每个阶段的输入和输出。

### 5.4 配置质量治理

质量校验至少覆盖：

- 必填属性是否缺失；
- 实体唯一标识是否重复；
- 关系两端实体是否合法；
- 实体和关系是否符合当前 Schema；
- 置信度是否达到自动入图阈值；
- 关系是否具有足够的来源证据；
- 删除和合并操作是否超过影响阈值。

建议处理策略：

```text
校验通过 → 写入图谱
校验失败 → 隔离结果 → 人工处理 → 修正后从失败节点重跑
```

### 5.5 试运行

发布前使用固定规模的样例数据执行整条 Pipeline。

试运行至少输出：

- 读取记录数；
- 每个节点的输入和输出数量；
- 每个节点耗时；
- 实体、关系和事件数量；
- 质量规则命中数量；
- 进入人工处理的数据数量；
- 错误日志和失败节点；
- 少量中间结果样例。

原型中模拟读取 100 条样例数据，并依次展示每个节点的运行状态。

### 5.6 发布与定时执行

发布动作需要验证：

- Pipeline 名称不为空；
- 至少包含一个数据源；
- 至少包含一个输出或图谱写入节点；
- 所有必填节点参数已经完成；
- 引用的公共配置处于可用状态；
- Schema 变更已经审批；
- 试运行已经成功；
- 用户具有目标图谱的写入权限。

发布成功后，调度系统按照保存的策略创建定时任务。修改已发布 Pipeline 时应产生新版本，不直接覆盖正在运行的版本。

### 5.7 查看运行记录

运行记录用于查看 Pipeline 的历史执行情况，至少包含：

- 运行实例编号；
- 手动或定时触发方式；
- 开始和结束时间；
- 总体状态；
- 读取、产出和异常数量；
- 各节点状态和耗时；
- 失败原因；
- 使用的 Pipeline 版本和配置快照。

## 6. 典型使用场景

### 6.1 科技资讯实体关系抽取

```text
Kafka 科技资讯流
  → 文档解析
  → 内容过滤
  → 实体抽取
  → 实体对齐
  → 关系抽取
  → 事件抽取
  → 质量校验
  → 写入图谱
```

适用于从实时资讯中识别企业、产品、技术领域、融资和合作事件。

### 6.2 论文全文知识抽取

```text
论文对象存储
  → PDF 文档解析
  → 摘要生成
  → 实体抽取
  → 论文引用关系抽取
  → 专家与机构对齐
  → 质量校验
  → 写入图谱
```

适用于构建论文、作者、机构、研究方向和引用关系。

### 6.3 新实体类型上线

```text
新业务数据源
  → 字段转换
  → Schema 新增
  → 实体抽取
  → 质量校验
  → 写入图谱
```

Schema 新增需要先完成影响分析和管理员审批，批准后才允许后续抽取及写入。

## 7. 配置管理设计

### 7.1 配置分类

配置管理页面统一维护四类公共资源：

| 分类 | 示例 |
| --- | --- |
| 数据源连接 | MySQL、PostgreSQL、REST API、Kafka、S3/OSS |
| 模型与抽取服务 | LLM、Embedding、NER、文档解析服务 |
| Schema 与字典 | 图谱 Schema、标准字典、质量规则集 |
| 调度与运行策略 | 调度策略、运行资源组、告警策略 |

### 7.2 配置生命周期

配置项应具有以下状态：

- 正常：健康检查通过，可以被 Pipeline 使用；
- 异常：连接或服务检查失败，已引用 Pipeline 需要告警；
- 停用：不允许被新 Pipeline 引用，已有引用需要提示影响。

配置管理需要支持：

- 新建和编辑配置；
- 搜索与状态筛选；
- 连接测试；
- 启用和停用；
- 引用关系查看；
- 凭据加密和脱敏；
- 配置变更审计。

### 7.3 Pipeline 与配置项的引用关系

```text
配置管理
├── 科技资讯 Kafka
├── 科技文本抽取大模型
├── 生产图谱 Schema v1.8
├── 图谱入库质量规则 v1.3
└── 标准运行资源组
        ↓ 引用
科技资讯实体关系抽取 Pipeline
```

Pipeline 的每次正式运行都应保存配置快照，避免公共配置更新后无法追溯历史结果。

## 8. 建议的 Pipeline 数据模型

后端可将 Pipeline 定义保存为带版本的 JSON 文档。示例结构如下：

```json
{
  "id": "PIPELINE-TECH-NEWS-01",
  "name": "科技资讯实体关系抽取",
  "version": 3,
  "status": "published",
  "description": "从科技资讯中抽取企业、技术、事件及其关系",
  "nodes": [
    {
      "id": "source-1",
      "type": "data-source",
      "configRef": "DS-KAFKA-01",
      "config": {
        "topic": "tech_news",
        "mode": "incremental",
        "watermark": "publish_time"
      }
    },
    {
      "id": "entity-extract-1",
      "type": "entity-extract",
      "configRef": "MODEL-LLM-01",
      "config": {
        "schema": ["Organization", "Product", "ResearchField", "Event"],
        "threshold": 0.82
      }
    },
    {
      "id": "graph-write-1",
      "type": "graph-write",
      "config": {
        "graph": "tech-kg-production",
        "mode": "merge",
        "batchSize": 1000
      }
    }
  ],
  "edges": [
    { "source": "source-1", "target": "entity-extract-1", "condition": "success" },
    { "source": "entity-extract-1", "target": "graph-write-1", "condition": "success" }
  ],
  "schedule": {
    "enabled": true,
    "cron": "30 2 * * *",
    "timezone": "Asia/Shanghai",
    "retryCount": 2,
    "timeoutMinutes": 60
  }
}
```

设计时应区分：

- Pipeline 定义：用户当前编辑的逻辑；
- Pipeline 版本：每次发布产生的不可变快照；
- Run：某个版本的一次实际运行；
- Node Run：某次运行中单个节点的执行记录；
- Config Snapshot：本次运行引用的公共配置快照。

## 9. 运行状态模型

### 9.1 Pipeline 状态

```text
草稿 → 校验中 → 已发布 → 已停用
                 ↓
               新版本草稿
```

### 9.2 运行实例状态

```text
等待执行
  → 运行中
  → 成功
  → 部分成功
  → 失败
  → 已取消
  → 超时
```

### 9.3 节点运行状态

```text
等待 → 运行中 → 成功
             ├→ 失败
             ├→ 重试中
             ├→ 已跳过
             └→ 等待人工处理
```

## 10. 权限与安全

建议按资源和操作设置权限：

- 查看 Pipeline；
- 创建和编辑草稿；
- 试运行；
- 发布、停用和回滚；
- 读取指定数据源；
- 使用指定模型；
- 修改 Schema；
- 写入测试图谱；
- 写入生产图谱；
- 查看原始数据和运行日志；
- 查看或更新凭据。

敏感信息不得直接保存在 Pipeline JSON 中。数据库密码、Token 和 API Key 应保存在密钥中心，Pipeline 只保存凭据引用标识。

## 12. 当前原型尚未实现的能力

当前页面未接入真实后端，因此尚未实现：

- Pipeline 定义持久化；
- 真实拖拽连线和图结构编辑；
- 分支、合流、循环和并行执行；
- 节点之间的数据传输；
- 数据库、API、Kafka 和对象存储连接；
- LLM、NER 和 Embedding 模型调用；
- Schema 变更审批；
- 真实调度器和执行引擎；
- 运行日志、中间结果及血缘存储；
- 用户权限和凭据中心；
- Pipeline 版本对比、回滚和发布审批。

- 支持条件分支和失败分支；
- 支持画布缩放、框选和自动布局；
- 支持节点复制和批量删除；
- 支持节点输入输出字段预览；
- 提供常用 Pipeline 模板。

质量校验建议优先演进为明确的双分支：

```text
                    ┌→ 校验通过 → 写入图谱
抽取 → 质量校验 ───┤
                    └→ 校验失败 → 人工处理 → 修正后重跑
```

### 13.2 第二阶段：接入定义和配置服务

- 保存 Pipeline 草稿；
- 保存和校验节点配置；
- 接入配置管理服务；
- 实现发布版本快照；
- 实现数据源连接测试；
- 实现 Schema 兼容性检查。

### 13.3 第三阶段：接入执行引擎

- 将 Pipeline 图转换为可执行 DAG；
- 接入调度器和任务队列；
- 支持节点重试、超时和取消；
- 保存节点输入、输出、日志和指标；
- 接入人工处理平台；
- 支持从失败节点继续运行。

### 13.4 第四阶段：生产治理

- Pipeline 版本对比与回滚；
- 发布审批和权限隔离；
- 数据血缘和影响分析；
- 运行成本、吞吐量和质量指标；
- 模型、Prompt 和 Schema 版本追踪；
- 数据脱敏和审计；
- 多环境发布：开发、测试、生产。

## 14. 验收关注点

产品和研发验收时建议重点检查：

1. 用户是否能快速理解数据从哪里来、经过什么处理、最终写入哪里；
2. 算子分类是否符合知识图谱建设人员的认知；
3. 节点参数是否足以表达真实抽取和治理需求；
4. 公共配置与 Pipeline 私有参数的边界是否清晰；
5. 试运行结果是否能帮助用户判断是否可以发布；
6. Schema 变更和生产写入是否具备足够的风险控制；
7. 异常数据是否可以进入人工处理并从失败节点重跑；
8. 运行记录是否能够追溯 Pipeline、模型、Schema 和配置版本。
